# Ключевые слова

Раздел `#/keywords` («Ключевые слова») показывает, с каким ключом приходят клики и сколько на каждом ключе заработано. Две вкладки: «Статистика» (`#/keywords`) и «Собранные списки» (`#/keywords/lists`).

## Откуда берётся ключ

Ключ — одно значение на клик. Движок выбирает его из адреса запроса в таком порядке:

| Приоритет | Откуда | Примечание |
| --- | --- | --- |
| 1 | Параметр, сопоставленный как `keyword` в источнике трафика кампании (например `kw`) | Кампания без источника, или источник без привязки `keyword`, этот шаг пропускает |
| 2 | `keyword=` | Пропускается, если имя занято другим полем (см. ниже) |
| 3 | `q=` | Читается всегда, имя не проверяется на занятость |
| 4 | `utm_term=` | Пропускается, если имя занято другим полем (см. ниже) |

Правила выбора:

- Пустое значение уступает следующему параметру. `?kw=&keyword=shoes` даёт `shoes`.
- Имена `keyword` и `utm_term` пропускаются, если они заняты другим полем кампании: источник кампании назначил это имя любому своему параметру, кроме `keyword` (`sub_id_N`, `site`, `ad_campaign_id`, `creative_id`, `external_id`), или оно совпадает с `cost_param` либо `currency_param` кампании. Тогда берётся следующее по приоритету. Значение, которое уходит в Sub ID, дополнительное поле или цену, ключом через эти два имени не становится. Проверка идёт для каждой кампании отдельно, в том числе для кампании, в которую поток передал посетителя.
- Имя `q` не пропускается никогда: оно читается как ключ, даже если источник назначил его Sub ID или дополнительному полю, или это имя цены. Так читаются существующие ссылки с `q=`, у них остаются ключ, условия потоков и разделение.
- Пример 1: у источника `sub_id_1` равен `utm_term`. В ссылке `?utm_term=abc&q=shoes` значение `abc` попадает в Sub ID 1, а ключом будет `shoes`. Если `q=` нет, ключ пустой.
- Пример 2: у источника `sub_id_1` равен `q`. В ссылке `?q=shoes` значение `shoes` попадает и в Sub ID 1, и в ключ.
- У повторяющегося параметра читается первое значение.
- Ключ режется до 255 байт по границе символа: многобайтная буква не разрывается.
- Нет ни одного непустого значения — ключ пустой. В статистике это строка «(без ключа)».
- В режиме `?api=` базовый ключ приходит в поле `key` тела запроса ([режим `?api=`](admin-api.md)), он тоже режется до 255 байт. `keyword=`, `q=` и `utm_term=` из строки запроса в этом режиме не читаются. Параметр источника читается и здесь, из строки запроса самого api-вызова: если он там есть и не пуст, он перекрывает `key`.
- Если поток передаёт посетителя в другую кампанию, ключ перечитывается по источнику той кампании, которая выдала ответ.
- Старый пиксель `/?pb=` ключ не читает и алиасы не разбирает: он отвечает `200` и выходит до разбора ключа.

Привязка `keyword` задаётся на странице источника (`#/sources`, поле параметров). Значение — имя параметра у партнёра ([макросы и источники](macros-sources.md)).

**Важно.** Выбранный ключ — один и тот же во всех местах, где движок использует ключ:

- условие потока «Ключевое слово» (`key_text`);
- разделение по ключу (separation);
- макросы `[KEY]` и `{keyword}`;
- запрос `remote` потока;
- запись в журнал кликов (поле `keyword`);
- сбор списков `keys/`.

Ссылка, в которой есть `utm_term=` или `keyword=` без `q=`, получает непустой ключ, если эти имена не заняты другим полем или ценой кампании. Проверьте потоки с условием по ключу, в том числе те, что рассчитаны на пустой ключ: у такой ссылки ключ непустой.

В позиционных параметрах `[PAR-1]`…`[PAR-5]` исключается только `q`. `keyword` и `utm_term` остаются в них на своих местах. Макрос `{utm_term}` разворачивается как обычный параметр запроса, а не как ключ. `{keyword}` даёт выбранный ключ.

## Как использовать

Ключ из параметра `keyword`:

```text
https://<домен>/<id кампании>?keyword={keyword}
```

Ключ из `utm_term`, например в ссылке рекламной сети:

```text
https://<домен>/<id кампании>?utm_term={keyword}&utm_source=net
```

Ключ из своего параметра. В источнике кампании у поля `keyword` стоит `kw`, ссылка:

```text
https://<домен>/<id кампании>?kw={keyword}
```

В примерах `{keyword}` — условное имя подстановки: значение подставляет рекламная сеть по своему шаблону.

Статистика по ключам — вкладка «Статистика». Включать сбор ничего не нужно: движок пишет ключ в журнал кликов с каждым кликом.

## Вкладка «Статистика»

Адрес `#/keywords`. Данные за общий период шапки (не больше 92 дней).

Переключатель «Последний клик / Первоисточник» виден, если роль видит `origin_campaign_id`. Обычный режим не меняется: ключ и кампания последнего клика. Режим первоисточника (`by=origin` у `GET /api/keywords/stats` и `GET /api/keywords/trend`) считает клики с пустым `root_cid` и `step = 0`, ключ конверсии берёт из `origin_keyword`, когда `root_cid` заполнен, иначе из `keyword`, а фильтр кампании идёт по `origin_campaign_id`. Таблица, топ и тренд используют одни и те же выражения. Неизвестное `by` отвечает `400`. У роли без первоисточника переключателя нет, `by=origin` отвечает `403`. Выбор хранится в виде страницы `keyword_stats`, поле `by`. Прямой клик пишет пустой `root_cid`, клик цепочки — cid первого клика. Конверсия цепочки пишет в `origin_keyword` ключ корня.

### Колонки

| Колонка | Что считает |
| --- | --- |
| Ключ | Выбранный ключ. Пустой — «(без ключа)» |
| Клики (люди) | Клики без ботов |
| Уникальные | Уникальные клики без ботов |
| Конверсии | Все статусы, как в «Отчёте» |
| Лиды, Продажи, Отклонено | Те же конверсии по статусам |
| CR | Конверсии / клики. Итоговый CR — из итоговых сумм, проценты не складываются. При нуле кликов — «—» |
| Доход | Сумма выплат (`profit`) |
| DepSum | Сумма депозитов. Это не выплата |
| Тренд | Спарклайн кликов по дням |

Конверсия получает ключ своего клика и считается по дате конверсии, а не клика. Лид или продажа клика, который позже отклонён, в конверсии не входят; строка отказа входит в «Отклонено». Это те же правила, что у журнала конверсий ([конверсии](conversions.md)).

Порядок строк с сервера: по доходу, затем по кликам, затем по ключу. Клик по заголовку сортирует уже загруженные строки в браузере.

Тренд — линия кликов по дням, в часовом поясе интерфейса. Он есть только у первых 25 ключей в порядке сервера. У остальных строк ячейка пустая. В подсказке ячейки — суммы кликов, конверсий и дохода за период. Если тренд не пришёл, таблица остаётся как есть и ошибки нет.

### Окно тренда

Спарклайн — кнопка «Тренд: <ключ>». Клик или `Enter` с клавиатуры открывает окно с подробным графиком этого ключа. Новых запросов окно не делает: оно берёт последний ответ `GET /api/keywords/trend`. Поэтому период, фильтры, кампания и поиск в нём те же, что у таблицы, а шаг — один календарный день в часовом поясе интерфейса.

| Часть окна | Что показывает |
| --- | --- |
| Переключатель метрики | «Клики (люди)», «Конверсии», «Доход». Конверсии и доход есть только при `conv_ready` у таблицы и у тренда и если роль видит эти колонки. Других метрик нет: у тренда нет своих дневных рядов для них |
| Итоги | Сумма метрики за период, пиковый день и число дней со значением. Средние и проценты не считаются |
| График | Одна точка на день, день без данных — ноль. Подсказка у точки — дата и значение. Ось значений начинается с нуля; отрицательный доход уходит ниже нуля |
| «С чего строится тренд» | Метрика и её правило, шаг и часовой пояс, первый и последний день периода, первые 25 ключей в порядке сервера, фильтры таблицы. При `conv_ready: false` — строка о том, почему доступны только клики |
| Таблица по дням | Все дни периода и все доступные метрики, строка «Всего» — суммы |

Правила метрик в окне — те же, что у сервера:

- клики — только люди: клик с отметкой бота (поле `bot` не пустое и не `-`) не входит;
- конверсии — все статусы по дате конверсии, а не клика; лид или продажа клика, который позже отклонён, не входят;
- доход — сумма выплат (`profit`) тех же конверсий по дате конверсии.

Окно закрывается кнопкой «Закрыть», клавишей `Esc`, кликом мимо окна, сменой раздела и перезагрузкой таблицы (новый период, фильтр, поиск, «Обновить»). Фокус возвращается на спарклайн. Окно работает в обеих темах и на узком экране: график берёт ширину окна, таблица по дням прокручивается.

### Управление

- Выбор кампании. «Все кампании» или одна; строка идёт в запрос как `f=campaign_id:eq:<id>`. Если у роли скрыто поле `campaign_id`, выбора нет, а запрос идёт по всем видимым кампаниям.
- Поиск по ключу. Подстрока, регистр не важен, ищет сервер (`f=keyword:contains:<текст>`) после паузы 400 мс.
- Фильтры. Тот же конструктор, что у журнала кликов ([фильтры и столбцы](log-filters.md)).
- Пагинация. 50 строк на странице; сортировка и страницы работают над всеми загруженными строками.
- Итоговая строка «Всего». Сумма всех загруженных строк, не страницы. При обрезке до 2000 строк она скрыта: была бы неполной.
- Экспорт. «Экспорт CSV» и «Экспорт HTML»: все загруженные строки в текущем порядке, плюс итоговая строка, если она показана. Колонки «Тренд» в файле нет. В CSV деньги идут числом, валюта (`$`) — в заголовке колонки, пустая ячейка вместо «—». Ячейка текста, начинающаяся с `=`, `+`, `-`, `@`, табуляции или `CR`, получает ведущий апостроф, чтобы таблица не выполнила её как формулу. Числа апостроф не получают.

Сохранённый вид страницы лежит в аккаунте под ключом `keyword_stats`: сортировка, выбранная кампания, условия фильтра ([виды страниц](log-filters.md)). Текст поиска и период в него не входят: период общий.

### Лимиты и ошибки

| Случай | Ответ |
| --- | --- |
| Период длиннее 92 дней или `from` не раньше `to` | `400 bad range`, «Период слишком длинный» |
| Больше 2000 ключей | Ответ с `truncated: true`, предупреждение «Показаны первые 2000 ключей, сначала с большим доходом» |
| Два запроса по ключам уже идут | `429 busy`, «Сервер занят другими отчётами по ключам» |
| ClickHouse остановил запрос | `504 query too heavy`: выберите кампанию или сократите период |

Подробности — в [лимитах аналитики](analytics-limits.md#ключевые-слова).

### Когда деньги не считаются

Ответ несёт `conv_ready`. При `false` колонки «Конверсии», «Лиды», «Продажи», «Отклонено», CR, «Доход» и «DepSum» показывают «—» (в CSV — пустые ячейки): клики есть, денег по ним нет, нули не выводятся. Так бывает в двух случаях:

- в таблице `conversions` ещё нет колонки `keyword` (волна `ext`, миграция не применена), поэтому конверсию нельзя отнести к ключу;
- в фильтре стоит поле, которого у конверсий нет, например `bot` или `uniq`: такое условие отбирает клики, а не конверсии.

Тренд при `conv_ready: false` показывает «—» для конверсий и дохода в подсказке.

## Вкладка «Собранные списки»

Адрес `#/keywords/lists`. Выберите кампанию, день и источник списка: «из ссылки» или «из поисковиков».

Это сырые файлы `keys/<кампания>/<дата>.dat` (ключ из ссылки) и `keys/<кампания>/<дата>-se.dat` (запрос из реферера поисковика). В каждой строке один клик человека. Боты в файлы не попадают.

Файл пишется только при включённой галке в настройках кампании:

- «Собирать ключевые слова» — пишет выбранный ключ, по правилам выше;
- «Собирать ключевые слова из реферера поисковика» — пишет запрос из `Referer`: `text` у Яндекса, `query` у Rambler и tut.by, `p` у Yahoo, `q` у Google, Mail.ru и Bing.

Файлы хранятся 30 дней. Срок задаёт `keys_days` в «Автоматизация» → «Очистка ключевых слов»; `0` — не удалять. Чистка идёт по расписанию задачи (по умолчанию раз в сутки) и смотрит на время изменения файла.

### Что попадает в строку

Один клик — одна строка. Перед записью значение чистится:

- перевод строки (`\n`, `\r`), табуляция, другие управляющие символы и разделители строк Unicode (`U+2028`, `U+2029`) заменяются пробелом; несколько подряд дают один пробел. `?q=first%0Asecond` пишется как `first second`;
- байты, которые не складываются в UTF-8, удаляются;
- пробелы по краям обрезаются;
- строка режется до 255 байт по границе символа;
- пустой результат не пишется.

### Лимит файла

Один файл за день растёт до 8 МиБ (`8388608` байт). Это 150–280 тысяч ключей по 30–60 байт: больше, чем нужно за день одной кампании, а 30 дней обоих списков — меньше 0,5 ГиБ на кампанию. Лимит у каждого файла свой: `.dat` и `-se.dat` считаются отдельно.

Значение задаёт переменная движка `EMTDS_KEYS_MAX_BYTES` в байтах; `0` снимает лимит. Не число или отрицательное число — в журнал движка уходит предупреждение и действует 8 МиБ.

Полный файл не останавливает клик: строка просто не пишется. В журнал движка раз в 10 минут уходит `keys: daily file limit reached, keywords dropped` с путём файла и числом отброшенных строк. Размер движок читает с диска один раз на файл за день и дальше считает в памяти, поэтому клик не делает лишний `stat`. Удалённый каталог кампании создаётся заново, счёт начинается с нуля.

### Просмотр и скачивание

Вкладка показывает начало файла: до 5000 строк и до 1 МиБ. Если файл длиннее, над текстом появляется предупреждение «Показаны первые N строк» с числом строк на экране. Весь файл даёт кнопка «Скачать файл»: `keywords-<кампания>-<дата>[-se].txt`. Сервер отдаёт файл потоком и не держит его в памяти.

| Маршрут | Ответ |
| --- | --- |
| `GET /api/keys?group=&date=&se=` | `{content, truncated, lines, size, max_lines}`: начало файла, признак обрезки, число строк в `content`, размер файла в байтах, лимит строк. Файла нет или он не читается — пустой `content` и `200` |
| `GET /api/keys/download?group=&date=&se=` | Весь файл, `text/plain`, `Content-Disposition: attachment`. Плохие `group` или `date` — `400`, файла нет — `404` |

`date` — день в формате `YYYY-MM-DD` по часам движка, `se=1` выбирает список из поисковиков.

Отличие от статистики:

| | Статистика | Собранные списки |
| --- | --- | --- |
| Источник | ClickHouse, таблицы `events` и `conversions` | Файлы `keys/` |
| Нужна галка | Нет, ключ пишется с каждым кликом | Да |
| Запросы из реферера поисковика | Нет | Да, файл `-se.dat` |
| Деньги | Есть | Нет |
| Боты | Не считаются | Не пишутся |
| Срок | Период до 92 дней, строки `events` живут 365 дней | 30 дней по умолчанию |

## Роли

Раздел `keywords` открывает `GET /api/keywords/stats`, `GET /api/keywords/trend`, `GET /api/keys` и `GET /api/keys/download`. Что скрывают поля роли:

- `keyword` скрыт — все четыре маршрута отвечают `403 forbidden`, страница показывает отказ;
- чужая кампания в `GET /api/keys` и `GET /api/keys/download` — `404 not found`;
- `status` скрыт — из ответа уходят `leads`, `sales`, `rejected`; `conv` и `profit` остаются и считают все статусы;
- `profit` скрыт — уходят `profit` и `depsum`, в тренде — массивы `profit`; в интерфейсе пропадают «Доход» и «DepSum». Скрытый `cost` колонку «Доход» не убирает;
- `uniq` скрыт — уходит `unique`;
- `campaign_id` скрыт — выбора кампании нет, запрос идёт по всем видимым кампаниям; условия фильтра на скрытых полях в запрос не уходят;
- кампании роли ограничивают таблицу и тренд: считаются только видимые кампании ([роли](roles.md#скрытие-в-ключевых-словах)).
