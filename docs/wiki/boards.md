# Разделы

Раздел — отдельный набор кампаний и каталогов внутри одной TDS. Вид по умолчанию есть всегда: id `main`, имя «По умолчанию». Пустой `board_id` и написание `main` — это он же. Пока других разделов нет, в нём лежит всё. Когда разделы есть, в нём по-прежнему лежат строки с пустым `board_id`, а строки других разделов видны, пока у `main` включён широкий вид.

Список лежит в `boards.json` рядом с остальными файлами состояния. Пока файла нет, виден только вид по умолчанию и файл не создаётся. Первое создание записывает его и новый раздел. Имена «По умолчанию», «Основной» и `main` создать нельзя. Id нового раздела собирается из латинских букв и цифр имени; имя без латиницы получает id `board` и короткий суффикс, если такой id уже занят.

Запрос панели несёт раздел в заголовке `X-Emtds-Board`. Пустое значение — раздел по умолчанию. Чужой раздел отвечает `403`.

## Кто видит

- Администратор окружения и пользователь `ADMIN` без списка `board_ids` видят все разделы.
- `all_boards: true` тоже открывает все разделы, без перечисления id.
- Обычный пользователь без `board_ids` видит только вид по умолчанию.
- Непустой `board_ids` открывает только эти разделы. `default_board` — раздел после входа; пустое значение значит вид по умолчанию.
- Создать раздел (`POST /api/boards`) может администратор; у записи необязательный `icon` из списка ключей панели, пустое значение — иконка `board` в интерфейсе. `PATCH /api/boards/{id}` меняет имя и/или `icon`. У вида по умолчанию тот же вызов принимает `include_all`; у другого раздела это поле отвечает `400`, в файл не пишется. `PUT /api/boards/order` сохраняет порядок остальных разделов (вид по умолчанию остаётся первым), `DELETE /api/boards/{id}` снимает пустой раздел (не вид по умолчанию и без строк каталога — иначе `409 board in use`).
- Переключатель (`#board`, подпись текущего раздела) стоит в шапке рядом с кнопкой периода. Кнопка только открывает меню смены раздела (и «Импорт из вида по умолчанию» у другого раздела); настроек разделов в шапке нет. Переключатель появляется, когда видны хотя бы два раздела.
- В меню профиля первая подпись — переведённый тип учётки (`Администратор` или `Пользователь`), под ней постбеки и интеграции, затем пункты вкладок настроек в порядке самих вкладок: «Настройки», «API ключи», «Пользователи», у администратора ещё «Настройки разделов» (иконка шестерёнки, `#/settings/boards`) и «О системе». Затем, если разделов больше одного, разделитель и подпись «Разделы», строки разделов с иконкой (из поля `icon`, иначе `board`; у вида по умолчанию она зелёная) и галочкой у текущего. Открытое меню пересчитывает позицию при ресайзе окна.
- Вкладка помнит выбор в `sessionStorage` (`emtds_board`): вид по умолчанию хранится как `main` (старый пустой ключ тоже читается как он); пока ключа нет, берётся раздел по умолчанию профиля из ответа API. Смена раздела сбрасывает кэш сумм сводки, каталогов и расхода и заново открывает текущую страницу. Числовой номер кампании ссылкой не становится: адрес остаётся `#/flows/{slug}`.

## Настройки разделов

Страница `#/settings/boards` (вкладка «Настройки разделов» в «Настройки»): создать раздел (`POST /api/boards`), в таблице сменить имя или иконку (`PATCH`), удалить пустой (`DELETE`, не `main`). Иконка выбирается кнопкой со значком: окно с поиском, недавними парами (до десяти, общий список браузера) и подписью «Все иконки» над сеткой. Цвет — второе окно в два ряда, десять заливок того же значка, оно открывается только по клику на значок. Цвет раздела — поле `icon_color`. В наборе значки панели, Lucide и ещё Android, iOS и SEO, всего больше двухсот. У не-основного раздела слева ручка переноса: призрак ряда шириной таблицы следует за курсором, место вставки — пунктир высотой ряда, остальные сдвигаются. Столбец иконки занимает ширину заголовка и отступов. Кнопка «Добавить участника» вставляет строку выбранного пользователя в таблицу. Справа иконка состава и иконка удаления. Если при сохранении значка сессия ответила `csrf`, панель один раз берёт новый токен и повторяет запрос. Окна значков и цветов открываются у своей кнопки. Если окно не влезает справа, его правый край совпадает с правым краем кнопки, и оно остаётся в видимой части окна, без полосы прокрутки. Отдельного столбца с превью нет, а у вида по умолчанию без своей иконки на кнопке зелёный значок доски.

`GET /api/boards` отдаёт поле `members` только сессии с правом управления разделами (как у `POST /api/boards`). У вида по умолчанию в ответе всегда есть `include_all`. У остальных разделов этого поля нет.

Пока раздел один, кнопки вида у строки по умолчанию нет. Когда разделов больше одного, справа от её иконки появляется раскрытие «Вид раздела». Внутри одна галочка «Отображать содержимое всех разделов». Она включена, пока в `boards.json` у `main` нет `include_all` или значение `true`. Снятие пишет `include_all: false`. Обратное включение поле из файла убирает: отсутствие снова значит «включено».

Включённая галочка, когда открыт вид по умолчанию, показывает кампании, офферы, лендинги, сети, источники, шаблоны s2s, клики, конверсии, сводку, отчёт и расход тех разделов, которые эта сессия и так может открыть. Раздел, на который прямой заход отвечает `403`, в этом виде не появляется. Выключенная галочка оставляет в виде по умолчанию только строки с пустым или `main` `board_id`. Чужой раздел по-прежнему показывает только свои строки. Одна кампания остаётся одной строкой статистики, сумма двух копий не считается.

Правка не переносит строку: `board_id` берётся из хранения. Новая строка, созданная в виде по умолчанию, получает этот вид. Строка другого раздела, которой нет в теле `PUT /api/groups`, не удаляется. Её снимает только `DELETE`. Ссылка кампании на оффер, лендинг, источник или кампанию другого раздела по-прежнему не принимается. Состав и «Импорт из вида по умолчанию» берут только строки с пустым или `main` `board_id`. Роль участника считается по разделу строки: `read` не пишет, `created` видит только свои строки.

## Состав раздела

`POST /api/boards/{id}/assign` задаёт полный состав каталога раздела (не для `main`, иначе `400`). В карточке галочка берёт всю папку или группу, а поиск над полем добавляет отдельную строку по id и имени; id уже покрытой метки в `ids` не дублируется. Тело: `folders` — папки кампаний (`folder`); `groups` — метки групп офферов, лендингов, сетей и источников (`group`); `ids` — ручные id по типам, включая `s2s`. Обрабатываются только строки из вида по умолчанию или этого раздела; снятые с состава возвращаются в вид по умолчанию (пустой `board_id`); строки других разделов не меняются. Вид по умолчанию этим вызовом не набирается.

## Участники и роли

`PUT /api/boards/{id}/members` заменяет список участников целиком. Роли: `read`, `edit`, `created`. После сохранения у затронутых пользователей `board_ids` пересобирается из разделов, где они есть в `members`; `all_boards` сбрасывается в `false`.

Роль действует внутри открытого раздела поверх глобальных прав страницы (кампании, офферы, лендинги, сети, источники, шаблоны s2s): глобальные права не расширяются. Администратор окружения и `ADMIN` ролями участника не сужаются.

- `read` — каталог раздела читает, записать каталог раздела не может.
- `edit` — в пределах глобальных прав на запись в этом разделе.
- `created` — видит и меняет только строки со своим `created_by` в этом разделе. У шаблонов s2s поля `created_by` нет, роль `created` их в разделе не видит.

## Импорт и перенос

`POST /api/boards/import` копирует выбранные кампании, офферы, лендинги, сети, источники и общие шаблоны постбеков из раздела `from` в текущий. У копий новые id, исходные записи остаются. Шаблоны чекера не копируются. Ссылка на кампанию, которой в копии нет, отбрасывается. В интерфейсе это «Импорт из вида по умолчанию» у раздела, который не он.

`POST /api/boards/move` не копирует: у выбранных строк меняется `board_id` на раздел `to`. Ссылка на кампанию, которая осталась в прежнем разделе, снимается.

У кампании, оффера, лендинга, сети, источника и шаблона постбека поле `board_id`. Пустое — вид по умолчанию. Выключение потока cron это поле не стирает.

## Keitaro

Один объект в `keitaro.json` — общее подключение, без `board_id`: импорт идёт в раздел запроса. Массив — отдельное подключение на раздел, у элемента поле `board_id`. Подключение этого раздела важнее общего. Новая кампания из переноса получает `board_id` этого подключения. Повторный импорт уже лежащей кампании её `board_id` не меняет. Одинаковый номер кампании в разных разделах не смешивает строки журнала: клик ищется в разделе подключения.
