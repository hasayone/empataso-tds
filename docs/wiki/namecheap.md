# Регистрация доменов через Namecheap

Серверная часть: проверка доступности и цены, покупка домена, смена NS, подключение через Cloudflare и проверка направления. Домен после покупки попадает в `domains.json` тем же путём, что `POST /api/domains`, с ролью «Ссылки кампаний». Список доменов не закрывает приём кликов.

## Аккаунт

Настройки лежат в `namecheap.json` (режим `0600`, запись атомарная). Путь задаёт `EMTDS_NAMECHEAP_FILE`. Файла нет — аккаунта нет. Повреждённый файл (не JSON, неверные поля, пустой ключ) админку не останавливает: регистратор остаётся выключенным, причина пишется в лог и отдаётся в поле `error` ответа `GET`, ключа в ней нет. Сохранение (`PUT`) перезаписывает файл и снимает ошибку. Поля проверяются при чтении так же, как при `PUT`. Ключ API и контакты в ответах не возвращаются: есть только `has_key` и `has_contacts`.

Поля: `name` (1–64 знака, имя аккаунта; домены запоминают его в `registrar_account`), `api_user`, `username` (пусто — равно `api_user`), `client_ip`, `api_key`, `sandbox`, `contacts`. Контакт один и идёт во все роли (владелец, технический, административный, биллинг): `first_name`, `last_name`, `address1`, `city`, `state`, `postal_code`, `country` (две буквы), `phone` в виде `+1.5551234567`, `email`; `organization` и `address2` необязательны.

`client_ip` должен быть внесён в белый список API у Namecheap. Исходящий адрес админки определяет проверка соединения: запрос с `0.0.0.0` получает от Namecheap ошибку «Invalid request IP», адрес берётся из неё.

Базовый адрес Namecheap и адрес песочницы задают `EMTDS_NAMECHEAP_URL` и `EMTDS_NAMECHEAP_SANDBOX_URL`; без них используются публичные (хост и путь собираются из констант пакета). Тесты ходят только на `httptest`-сервер.

## API

Настройки, проверка соединения, покупка (`register`) и смена NS работают только по сессии (cookie), ключ API их не принимает. `POST /api/registrars/namecheap/check` и `register` — только полный администратор, не пользователь `USER` с разделом «Домены». Проверка доступности (`check`) допускает и ключ `ADMIN`; покупка — только сессию администратора. Сохранение аккаунта и проверка соединения — раздел «Интеграции» (тоже только администратор).

## Интерфейс

- `#/integrations`, карточка Namecheap: имя пользователя и API-ключ. Одно введённое имя уходит и в `api_user`, и в `username`. Имени аккаунта на форме нет: в сохранение уходит уже записанное имя, а если его ещё нет — `Namecheap`. IP сервера — отдельное поле только для копирования: это адрес, с которого сервер ходит в API, его добавляют в белый список кабинета Namecheap и руками не вводят. Песочница и контакты владельца остаются. Ключ — поле `type=password`, в ответе его нет, при сохранённом ключе в поле подсказка «сохранён»; пустое поле оставляет прежний ключ. Сохранённые контакты не показываются (`has_contacts`): кнопка «Изменить контакты» открывает пустую форму, а без неё уходит `contacts: null`. Повреждённый `namecheap.json` показывается строкой `error`. «Проверить соединение» шлёт введённые значения, «Найти исходящий IP» шлёт `detect` и подставляет адрес, который увидел Namecheap: его копируют в белый список кабинета Namecheap и сохраняют. Песочница — переключатель (`.sw`), поля идут двумя колонками по ширине карточки (`.intsec .g2`, одна колонка на узкой карточке). Если админка запущена на локальной машине, GET отдаёт `local: true`, и карточка пишет, что найденный IP — это подключение разработчика, а не сервер.
- `#/domains`, кнопка «Зарегистрировать домен» (только администратор): «Проверить цену» вызывает `check`, цена за год умножается на число лет, покупка недоступна, пока не отмечено подтверждение суммы; в `max_price` уходит эта сумма за весь срок. Ответ 409 `price changed` показывает новую цену и снимает отметку: нужно подтвердить заново. Премиум-имя не покупается. `pending` (409, 502 и 500 `registered but not saved`) закрывает окно, строка остаётся в списке, `too early` показывает ожидание в минутах из `retry_after`.
- Строка со статусом `pending` помечена в столбце статуса. В её меню «Сверить с Namecheap» повторяет `register` (сервер сверяет и не покупает второй раз) и «Удалить принудительно» (`DELETE ?force=1`; ответ `registered at namecheap` означает, что покупка подтверждена, строка не удалена).
- «Сменить NS» есть в меню только у доменов с `registrar: namecheap`: список из 2–12 имён и отметка подтверждения, в запрос уходит `confirm: true`.
- Регистрация и список доменов учитывают Cloudflare: см. раздел ниже.

| Маршрут | Назначение |
| --- | --- |
| `GET /api/registrars/namecheap` | `{configured, name, api_user, username, client_ip, sandbox, has_key, has_contacts, error}`; `error` есть, только если `namecheap.json` не удалось прочитать |
| `PUT /api/registrars/namecheap` | Сохранить аккаунт. Пустой `api_key` или маска оставляют ключ, `contacts: null` оставляет контакты. Ответ как у GET |
| `POST /api/registrars/namecheap/test` | Тело `{api_user, username, client_ip, api_key, sandbox, detect}`, пустое берётся из сохранённого. Ответ `{ok, detected_ip, error}`, отказ Namecheap — тоже 200 с `ok:false` |
| `POST /api/registrars/namecheap/check` | `{domains: [..]}`, 1–50 имён. Ответ `{results: [{domain, available, premium, price, currency, error}]}`, `price` — год в USD, `null` без цены |
| `POST /api/registrars/namecheap/register` | `{domain, years 1–10, max_price, group, nameservers}` или `cloudflare: true` (вместе с `nameservers` нельзя). `max_price` — сумма за все годы, которую видел оператор. Поле `reconcile: true` включает режим только сверки: годы и цена не проверяются, покупка недостижима. Без строки `pending` для этого домена ответ 404 `not found`, при другом состоянии строки — 409 `not pending`; вызов Namecheap `create` в этом режиме не происходит никогда. Ответ 201: `{domain, charged, expected, namecheap_status, over_max_price, ns_error, hosts_error, cloudflare, cloudflare_error}` |
| `POST /api/domains/{id}/ns` | `{nameservers: [2–12], confirm: true}` → `{status:"ok", nameservers}` |

Коды `PUT`: 400 поле, 409 идёт покупка, 503 нет файла, 500 не записалось. Коды `check`: 400 список, 503 не настроено, 502 ответ Namecheap с ошибкой. Коды `register`: 201 `{domain, charged, ns_error}`; 400 вход; 404 `not found` и 409 `not pending` (только при `reconcile: true`); 409 `already exists`, `registration in progress`, `not available`, `price unknown`, `price changed` (с `price`), `pending`, `too early` (с `retry_after` в секундах), `not registered` (строка `pending` снята, домена в аккаунте нет); 422 премиум; 503 не настроено; 502 ошибка Namecheap (с `pending:true`, если исход неизвестен). Коды `ns`: 400, 403 не наш домен, 404, 409 `pending`, 503, 502.

Ошибки Namecheap приходят без адреса запроса, ключ в тексте заменён маской.

## Покупка без дубля

1. Защита от двойной покупки стоит первой: блокировка на домен берётся до чтения аккаунта. Сохранение настроек в это время отвечает 409, а проверка занятости и запись файла идут под одной блокировкой, поэтому покупка не стартует между ними.
2. Повторная проверка доступности; премиум-имена не покупаются (422).
3. Цена берётся свежим вызовом `users.getPricing`, мимо кеша. Нужна строка с `Duration`, равным числу лет, и `DurationType` `YEAR`. Цена — большая из `YourPrice` и `Price`; `CouponPrice` не используется. Namecheap указывает цену единицы срока (года), поэтому цена и `AdditionalCost` умножаются на число лет, если у строки нет `PricingType` `ABSOLUTE`. Строка в другой валюте не годится. Нет подходящей строки — 409 `price unknown`, и покупки нет. Итог выше `max_price` — 409 `price changed` с ценой. Кеш цен нужен только экрану проверки доступности.
4. Блокировка на домен: второй запрос на то же имя получает 409.
5. Строка пишется в `domains.json` со статусом `registrar_status: "pending"` и `disabled: true` до вызова `domains.create`, ожидаемая сумма — в `registrar_expected`. Пока домен `pending`, он не предлагается для ссылок.
6. `domains.create` вызывается один раз, без автоповтора. Контекст не зависит от обрыва запроса браузера.
7. После `create` всё остальное идёт под отдельным коротким контекстом (45 с), не зависящим от того, сколько времени съел `create`. После любой ошибки `domains.getInfo` сверяет владение: домен свой, если ответ называет этот домен и `IsOwner` равен `true`; статус (`Ok`, `Locked`) на это не влияет и возвращается как `namecheap_status`. Владеем — строка завершается: статус очищается, `disabled` снимается. Namecheap отказал и не владеем — строка удаляется. Исход неизвестен — строка остаётся `pending`, ответ 502 с `pending:true`.
8. `registrar_charged` пишется только из `ChargedAmount` ответа `create`. Если домен подтверждён через `getInfo`, сумма неизвестна: `charged` в ответе 0, а `expected` — цена, посчитанная до покупки. Если списано больше `max_price`, в лог идёт предупреждение, а в ответе `over_max_price: true`.
9. Повторный запрос на `pending`-домен только сверяет, не покупает. Пункт меню «Сверить» в списке доменов шлёт `{domain, reconcile:true}`: так даже снятая гонкой строка не превращается в новую покупку (404 или 409 вместо `buy`), а пункт на время запроса выключен. Строка `pending` хранит время записи `registrar_pending_since` (RFC 3339, UTC); поле выставляет только сервер и переносит вместе с `registrar_expected`; строка без времени считается старой. Домен свой по `getInfo` — строка подтверждается сразу. Строка снимается, только если одновременно: `getInfo` явно говорит, что домена нет в аккаунте (ошибка 2019166 / 2016166 либо ответ с тем же именем, без учёта регистра, и `IsOwner=false`), `domains.check` говорит, что имя свободно, и с метки прошло 15 минут. Раньше срока — 409 `too early` с `retry_after`, строка остаётся. Пустое или чужое имя в ответе, сетевая ошибка, другая ошибка API или занятое имя тоже оставляют строку `pending`. Снятие — 409 `not registered` с `pending:false`.
10. Если `nameservers` заданы, они уходят в `domains.dns.setCustom` после покупки и A-запись на IP сервера их не подменяет; сбой NS не отменяет покупку, текст идёт в `ns_error`. Пустой список и не Cloudflare: для только что купленного домена `domains.dns.setHosts` ставит A `@` (AAAA для IPv6) на публичный IP сервера (`EMTDS_PUBLIC_IP`, TTL 1800). Сбой этой записи идёт в `hosts_error` и покупку не отменяет. Без публичного IP запись не ставится.

Поля `registrar`, `registrar_account`, `registrar_status`, `registrar_charged`, `registrar_expected` принадлежат серверу: обычное `POST` и `PUT /api/domains` их не принимает, импорт из Keitaro и правка домена их сохраняют.

Домен в статусе `pending` или с идущей покупкой защищён: `DELETE` и смена хоста через `PUT` отвечают 409 `pending`, остальные поля `PUT` сохраняются, но `disabled` остаётся `true`. Переименование другого домена на хост, который сейчас покупается, отвечает 409 `registration in progress`.

Выход из зависшей строки для администратора с cookie-сессией (ключ API не подходит): `DELETE /api/domains/{id}?force=1`. Сначала `getInfo` под замком хоста, дальше те же условия, что у повторного запроса на покупку (общий код). Домен свой — удаления нет, строка подтверждается сразу, ответ 409 `registered at namecheap` с `confirmed:true`. Явно не свой, имя свободно и прошло 15 минут — строка удаляется, ответ 200; раньше срока — 409 `too early` с `retry_after`. Ответа нет (сеть, другая ошибка API) — 502, строка остаётся; неоднозначный ответ или занятое имя — 409 `pending`, строка остаётся. Идёт покупка этого хоста — 409 `registration in progress`. Не настроен Namecheap — 503.

Новый домен на хост, который покупается или уже есть строкой `pending` (регистр не важен), отвечает 409 `registration in progress`. Перед записью `pending` покупка ещё раз проверяет хост под тем же замком записи `domains.json`: если хост уже есть, ответ 409 `already exists` до `domains.create`.
## Смена NS

Только для доменов с `registrar: namecheap` и `registrar_account`, равным имени сохранённого аккаунта. Дополнительно `getInfo` должен подтвердить владение. Без `confirm: true` — 400. Переименование аккаунта отрезает уже купленные домены от смены NS.

## Cloudflare

### Интеграция

`#/integrations`, карточка Cloudflare: API-токен (права на аккаунт: Zone:Edit, DNS:Edit, Zone Settings:Edit), Account ID. «Проверить» показывает число зон. Токен и Account ID хранятся в `cloudflare.json` на томе (режим `0600`), в ответах API не отдаются (`has_token`). Публичный IP сервера берётся из `EMTDS_PUBLIC_IP` в `/etc/emtds/server.env`; без него подключение доменов недоступно (в GET видно `public_ip`). Признак `local: true` в GET (`public_ip` пуст и заголовок `Host` — loopback, частный адрес, `localhost`, имя без точки или `.local`/`.localhost`/`.internal`/`.lan`) заменяет красную строку нейтральной: интеграция не запускается на локальной машине, нужен сервер с публичным IP. На сервере без публичного IP при обращении по публичному имени остаётся красная строка с `EMTDS_PUBLIC_IP`. Пустой ключ выкладка заполняет тем же запросом, что и установка, и уже заданный адрес не заменяет.

| Маршрут | Назначение |
| --- | --- |
| `GET /api/cloudflare` | `{configured, account_id, has_token, public_ip, local, error}` |
| `PUT /api/cloudflare` | Сохранить токен и Account ID; пустой токен или маска оставляет прежний |
| `POST /api/cloudflare/test` | Проверка токена; ответ `{ok, zones, error}` |

### Покупка и подключение

Если Cloudflare настроен и известен публичный IP, в окне регистрации поле NS скрыто, стоит галочка «Подключить через Cloudflare» (`cloudflare: true` в `register`). Перед оплатой — окно подтверждения с доменом, сроком, ценой и режимом DNS (Cloudflare или свои NS). После покупки с Cloudflare: зона в аккаунте, A `@` на публичный IP с проксированием, SSL Full, Always Use HTTPS, NS у Namecheap меняются на NS Cloudflare. Без Cloudflare и без своих NS после покупки ставится A `@` на публичный IP через Namecheap (только для только что купленного домена). Если подключение после оплаты не удалось, строка остаётся «Подключение к Cloudflare…» (`cf_status: connect_pending`); фоновая проверка повторит попытку, повторной покупки нет.

Для уже существующего домена: меню строки → «Подключить через Cloudflare» (`POST /api/domains/{id}/cloudflare`, `confirm: true`); операцию можно безопасно повторять. Для доменов не из нашего аккаунта Namecheap в ответе могут быть NS для ручной смены (`ns_manual`).

### Статус и проверка

В списке доменов отдельно состояние (Включён / Выключен / Ожидает оплаты) и вердикт проверки. Причины не-OK: DNS-запись не найдена; приватный адрес; сервер не отвечает по HTTPS; чужой ответ движка; сертификат сервера отклонён; не направлен (A указывает на другие IP, нужен публичный IP); ждём Cloudflare (NS ещё не сменились, показаны NS). Если имя резолвится на публичный IP этого сервера или движок ответил с тем же Host, и единственная проблема — недоверенный сертификат сервера (самоподписанный или цепочка не принимается), причина `untrusted`: в ячейке статуса жёлтый текст «Сертификат сервера не доверенный». Это не «не направлен» и не красный провал, бейдж «Включён» рядом не ставится. Полная проверка остаётся во всплывающей подсказке. Чужой адрес, отсутствие DNS, молчание сервера и ответ другого сервиса этот статус не получают. ОК ставится только своим ответом движка с тем же Host на `https://домен/healthz`.

Фоновая проверка в admin (`WatchDomains`, интервал `EMTDS_DOMAIN_WATCH`, по умолчанию 5 минут): только домены с Cloudflare и новые покупки Namecheap. Покупку проверяют каждые 5 минут в течение часа от времени покупки (`WatchSince`, функция `namecheapAutoCheck`) тем же `recheckDomain`, что и ручная кнопка; когда домен стал OK, выключен или час вышел, автопроверка этого домена прекращается и остаётся ручная проверка. Домены с Cloudflare идут до 50 за проход, после 48 часов без успеха — не чаще раза в час. Отдельного планировщика нет. Импортированные из Keitaro домены (без `WatchSince` и без Cloudflare) не опрашиваются.

Кнопка ручной проверки в строке — глазик с пульсацией, левее «⋯». Она нарисована, пока у домена нет законченной проверки (поле `checked` пусто) или идёт автопроверка новой покупки; после проверки и по окончании часа кнопки в строке нет, ручная проверка остаётся в меню «⋯» → «Проверить». У покупки в ожидании оплаты кнопки нет.

Когда домен впервые стал OK, на любой странице один раз появляется окно «Домен подключён» с кнопками «Понятно» и «Перейти к доменам»; отметка `connect_seen` общая для всех пользователей (`POST /api/domains/connected/ack`).

### Адрес админки (admin.<домен>)

Если домен **основной** (`primary`) или роль **«Админка»** / **«Админка и ссылки»** (`admin` / `both`) и строка **не выключена**, панель открывается по `https://admin.<домен>/`. Сам `<домен>` целиком остаётся у движка: клики, лендинги, постбеки и `GET https://<домен>/healthz` с заголовком `X-Emtds-Service: engine` не меняются. Хост в каталоге не может начинаться с `admin.` — поддомен вычисляется сервером (`admin_host` в API).

После подключения Cloudflare, сохранения домена с ролью админки или активации зоны админка в фоне создаёт **проксируемую A-запись** `admin.<домен>` на `EMTDS_PUBLIC_IP` (тот же механизм, что A `@`). Запись с **чужим IP** не перезаписывается (`admin record points to another server`); **CNAME** на этом имени тоже не трогают. Повтор — кнопка «Создать запись admin» или `POST /api/domains/{id}/admin-dns` (доступ как у подключения Cloudflare). В строке домена: `admin_dns` (`ok` или текст ошибки), после проверки — `admin_ok` и `admin_reason` (`dns`, `tls`, `connect`, `foreign`). Сертификаты на сервере не выпускают: у посетителя Universal SSL Cloudflare, до origin — режим **Full** с самоподписанным сертификатом.

`GET https://admin.<домен>/healthz` без входа отвечает `ok`, `X-Emtds-Host` и **`X-Emtds-Service: admin`**. Запрос на `admin.*`, не привязанный к включённому основному/админ-домену, — **404**. **Вход по паролю** на `admin.*` без Redis (лимит входа не в общем хранилище) — **503** `login unavailable`; с Redis лимит считает IP посетителя по **X-Forwarded-For** (крайний справа недоверенный адрес), **`CF-Connecting-IP` не читается**.

Запасной вход по **IP сервера** (как раньше) сохраняется. На edge nginx vhost `admin.*` (`deploy/nginx/emtds-admin-host.conf`) пропускает только трафик с адресов Cloudflare; иначе **444**. Ключ **`EMTDS_ADMIN_TRUSTED_PROXIES`** (CIDR через запятую) задаёт доверенные прокси для admin; **неверный CIDR — процесс admin не стартует**. `apply-edge.sh` дописывает ключ в `/etc/emtds/server.env` рядом с `EMTDS_TRUSTED_PROXIES`; в compose он пробрасывается в контейнер admin.

Подробнее про поля API — [admin-api](admin-api.md). Регистрация и Cloudflare — разделы выше.

### Сервер и nginx

Nginx отдаёт любые **не-admin** домены на 443 движку (`deploy/nginx/emtds-engine.conf`, `default_server`); **`admin.*`** — на admin (`127.0.0.1:8090`). IP посетителя для запросов от Cloudflare берётся из `CF-Connecting-IP` (диапазоны в `deploy/nginx/cloudflare-ips.txt`). Применение: `bash deploy/apply-edge.sh` (бэкап конфигов, `nginx -t`, откат при ошибке); nginx на сервере вручную не править.
