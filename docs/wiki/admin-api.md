# API-ключи и Admin API

Меню пользователя «Профиль» открывает `#/settings`. Вкладка «API ключи» — `#/settings/keys`. Кнопка «Документация» на этой вкладке открывает встроенную страницу `#/settings/docs`.

На вкладке профиля карточка «Компания» задаёт название (до 64 символов) и логотип — data-URL картинки до 200 КБ в интерфейсе. По умолчанию название и логотип пустые: блок бренда в шапке и на экране входа скрыт, меню начинается от левого края, заголовок вкладки — `TDS`. Значения видны в шапке админки и на экране входа у всех. Сохранение идёт в `PUT /api/ui` вместе с остальными настройками интерфейса. Тема, язык и период хранятся только в браузере.

«Создать новый ключ» спрашивает название и доступы. Название обязательно и не длиннее 64 символов. Доступ — `admin`, `engine` или оба. В окне «Admin API» включён сразу, «Движок» выключен. Пустой набор доступов не сохраняется.

Сырой ключ — `em_` и 40 шестнадцатеричных знаков, всего 43 символа. Ключи, выданные до появления префикса `em_`, начинаются с `kz_` и продолжают работать: проверка принимает оба префикса и отклоняет любой другой. В ответе `POST /api/api-keys` поле `key` приходит один раз, вместе с записью `item`. После закрытия окна сырой ключ нигде не хранится. В списке у названия стоит точка состояния: зелёная — активен, красная — отозван, с датой отзыва под именем. Столбец «API ключ» показывает префикс ключа (`em_`, у старых `kz_`; запись хранит его в поле `lead`) и первые 8 знаков секрета с многоточием и кнопку копирования этого префикса; полный ключ из таблицы не достать. Дальше доступы («Admin API», «Движок») и время создания. Кнопка «⋯» сразу после названия открывает меню: у активного — «Перевыпустить», «Изменить», «Отозвать»; у отозванного — «Удалить». В файле лежит sha256 сырого ключа, не сам ключ. Ответ списка хеш не отдаёт.

Отзыв ставит время в `revoked_at` и оставляет запись. Повторный отзыв того же id отвечает `404`. Админка перестаёт принимать отозванный ключ сразу после записи файла. Движок перечитывает тот же файл по тикеру `EMTDS_RELOAD_INTERVAL`. Пустое или неположительное значение интервала для наблюдателя ключей становится одной минутой. Файл читается заново, когда изменились время модификации или размер. До этого тика режим `?api=` ещё принимает отозванный ключ. Ошибка чтения оставляет прежний набор.

Перевыпуск — `POST /api/api-keys/{id}/rotate`: тот же id, имя, доступы и время создания, новые префикс и хеш; ответ `200` с `{key, item}`, сырой ключ приходит один раз. Старый секрет админка отклоняет сразу, движок — после перечитывания файла, не позже чем через минуту. Отозванный ключ не перевыпускается — `409`. Правка — `PUT /api/api-keys/{id}` с телом `{"name","scopes"}` и теми же правилами, что при создании; секрет не меняется; отозванный — `409`. Удаление записи — `DELETE /api/api-keys/{id}?hard=1`: только для уже отозванного ключа, ответ `204`, запись исчезает из файла; активный ключ — `409`, неизвестный id — `404`. `DELETE` без `hard` остаётся отзывом. Ошибки валидации отвечают `400` с текстом, сбой генерации или записи файла — `500`.

### Срок жизни и последнее использование

У записи ключа есть `created_at`, `expires_at`, `last_used_at` и `last_used_ip`. Срок задаёт поле `ttl_days` в `POST /api/api-keys`: `0` или поле не передано — бессрочно, иначе 7, 30, 90 или 365 дней от текущего момента; другое число — `400`. Окно создания показывает тот же выбор. Истёкший ключ админка отклоняет `401` с кодом `key_expired` (текст `api key expired`); режим `?api=` движка тоже его не принимает. «Продлить» в меню «⋯» — `PUT /api/api-keys/{id}` с `{"ttl_days": N}`: новый срок считается от текущего момента, `0` снимает срок; секрет не меняется. В списке столбец «Срок» показывает бейдж: «Истёк» (красный), «Истекает через N дн.», если осталось 7 дней или меньше (жёлтый), дату окончания или «Бессрочно» (нейтральный).

`last_used_at` и `last_used_ip` ставит админка при каждом принятом запросе с ключом, но не чаще раза в минуту на ключ. IP маскируется: у IPv4 последний октет заменяется на `x` (сеть /24), у IPv6 остаётся /48. Отметки копятся в памяти и раз в минуту, а также при остановке admin атомарно пишутся в файл ключей. Запросы движка с `?api=` отметку не ставят: файл ключей пишет только admin. У ключей, созданных до появления этих полей, срока нет, а столбец «Использован» показывает «ещё не использовался». Кнопки «показать ключ» нет: в файле лежит только хеш.

Файл задаёт `EMTDS_API_KEYS_FILE`. Путь пустой — ключи выключены, заголовок `Api-Key` админка не принимает, создание отвечает `503`. Отсутствующий файл — пустой набор, это не ошибка. `EMTDS_API_KEY` в файл не пишется и админку не открывает. Для `?api=` движка он подходит рядом с файловыми ключами доступа `engine`.

## Заголовок и что ключу закрыто

Запрос к админке передаёт `Api-Key: em_...`. Кука сессии и `X-CSRF-Token` для этого запроса не нужны. Непустой заголовок — единственный способ входа: при неверном ключе кука не проверяется. Нужен доступ `admin`. Нет доступа, ключ отозван или неизвестен — `401`. С MCP-клиентом тот же ключ используется через [MCP-сервер](mcp.md).

### Тип ключа и доступы

У ключа есть тип: `ADMIN` или `USER`. В окне ключа он задаётся при создании и правке, в API — полем `type` в `POST /api/api-keys` и `PUT /api/api-keys/{id}`. Любое другое значение — `400`.

`ADMIN` действует как администратор панели: все разделы и все записи, кроме маршрутов из списка ниже и опасных действий, которые ключу нужно выдать отдельно. `USER` ограничен, как учётная запись `USER` в [пользователях](users.md): доступ задаёт либо роль (`role_id`), либо свой набор (`access` — разделы, гранты, скрытые поля). Правила те же, что у пользователей: роль вместе с непустым `access` — `400`, неизвестная роль — `400`, раздел только для администратора в `access` — `400`. Для ключа с ролью доступ берётся из роли при каждом запросе; если роль удалили, ключ отвечает `401`. Запись, созданная `USER`-ключом, получает владельца `apikey:<id ключа>`. У ключей `ADMIN` роль и доступ не хранятся: при смене типа на `ADMIN` они очищаются.

Ключ без поля `type` в файле — старый ключ. Он читается как `ADMIN` без опасных действий.

### Права ключа

Ключ только для чтения — тип `USER` с ролью или собственным набором, где у разделов отмечено только чтение. Запись по разделам работает так же, как у пользователей: ключ пишет только в разделы, где отмечена запись, и только записи, которые ему видны. Опасные действия поверх этого выдаются отдельными галочками. На странице документации это объясняет блок «Права ключа», а маршруты, которые удаляют или массово перезаписывают данные (`DELETE`, `keitaro_purge`, `logs_delete`, `groups_replace`), помечены бейджем «Удаляет данные».

### Опасные действия

Опасное действие — отдельное разрешение ключа, поле `actions` (массив имён). Маршрут с действием отвечает ключу без него `403 action required: <имя>`, даже если раздел ему открыт. Сессия браузера действиями не ограничена.

| Действие | Маршруты |
| --- | --- |
| `keitaro_import` | `POST /api/keitaro/import` |
| `keitaro_purge` | `POST /api/keitaro/purge` |
| `logs_delete` | `DELETE /api/logs` |
| `groups_replace` | `PUT /api/groups` — замена всего массива кампаний |
| `cron` | `PUT /api/cron`, `POST /api/cron/run` |
| `boards` | `POST /api/boards`, `PUT /api/boards/order`, `PATCH /api/boards/{id}`, `PUT /api/boards/{id}/members`, `POST /api/boards/{id}/assign`, `DELETE /api/boards/{id}`, `POST /api/boards/move`, `POST /api/boards/import` |
| `landing_files` | `DELETE /api/landings/{id}`, `POST /api/landings/{id}/archive`, `PUT` и `DELETE /api/landings/{id}/files/{path}` |
| `lists_read` | `GET /api/lists`, `GET /api/lists/{name}` |

Неизвестное имя действия — `400`. Ключу `USER` нельзя выдать `cron` и `boards` (`400`). `lists_read` ключу `USER` выдать можно: без этой галочки `GET /api/lists` и `GET /api/lists/{name}` отвечают `403 action required: lists_read`, даже если раздел списков открыт. Сессия браузера списки читает по-прежнему, без галочки. Остальные действия для `USER` имеют смысл только там, где маршрут не закрыт для не-администратора: `groups_replace` (раздел `flows`) и `landing_files` (раздел `landings`, включая удаление лендинга). Маршруты `keitaro_*` и `logs_delete` требуют администратора, поэтому `USER` через них не пройдёт и с выданным действием.

### Что ключу закрыто всегда

Эти маршруты отвечают любому ключу `403 cookie session required` (код `cookie_required`), и в схеме `GET /api/openapi.json` для ключа их нет:

- `/api/api-keys`: список, создание, перевыпуск, правка, отзыв, удаление
- `/api/users` со всеми вложенными адресами, `/api/roles` со всеми, включая `reload`
- `POST /api/password`
- `GET /api/me`, `GET` и `PUT /api/me/views`
- `POST /api/logout`
- `GET`, `PUT /api/keitaro/settings`, `POST /api/keitaro/check`
- `GET`, `PUT /api/cloudflare` и `POST /api/cloudflare/test`
- `GET`, `PUT /api/registrars/namecheap`, `POST …/test`, `POST …/check`, `POST …/register`
- `POST /api/domains/{id}/ns`, `POST /api/domains/{id}/cloudflare`, `POST /api/domains/{id}/admin-dns`, `POST /api/domains/connected/ack`

`POST /api/login` заголовок ключа не читает. `GET /api/ui` открыт любой сессии, в том числе ключу; `PUT /api/ui` требует раздел `settings`, то есть ключа `ADMIN` или сессии администратора.

### Ошибки и коды

Тело ошибки — `{"error": "текст", "code": "…"}`. Текст может меняться, код стабилен.

| `code` | Когда |
| --- | --- |
| `bad_request` | любой `4xx` без собственного кода: плохое тело, валидация |
| `unauthorized` | `401`: нет или неверный ключ, сессия |
| `forbidden` | `403`: нет раздела, гранта или права |
| `action_required` | `403 action required: <имя>`: у ключа нет опасного действия |
| `cookie_required` | `403 cookie session required`: маршрут только для сессии браузера |
| `not_found` | `404`, в том числе неизвестный путь под `/api/` |
| `method_not_allowed` | `405`: метод не поддерживается маршрутом; заголовок `Allow` перечисляет допустимые |
| `conflict` | `409` |
| `too_large` | `413` |
| `too_many_requests` | `429`: лимит ключа |
| `bad_gateway` | `502` |
| `unavailable` | `503` |
| `query_too_heavy` | `504 query too heavy`: запрос статистики остановлен лимитом ClickHouse ([лимиты](analytics-limits.md)) |
| `internal` | остальные `5xx` |

### Формат TOON для AI

Для AI можно выводить информацию в формате `text/toon`, передав `?format=toon`. TOON (Token-Oriented Object Notation, [спецификация](https://github.com/toon-format/spec)) несёт ту же модель данных, что JSON, но массив однородных записей пишет таблицей: имена полей один раз в заголовке `имя[N]{поле1,поле2}:`, дальше по строке на запись. Так ответ занимает меньше токенов в контексте модели.

- Включение: `?format=toon` в строке запроса (для `POST`, `PUT`, `PATCH`, `DELETE` тоже — тело запроса остаётся JSON) или заголовок `Accept: text/toon`. `?format=json` всегда даёт JSON, даже при `Accept: text/toon`. Другое значение `format` игнорируется — как будто параметра нет. По умолчанию — JSON.
- Ответ: `Content-Type: text/toon; charset=utf-8`, тот же статус. Ошибка тоже в TOON с теми же полями: `code: not_found` и `error: not found`.
- Права, фильтры ролей и скрытие секретов не меняются: TOON строится из того же JSON-документа, который ушёл бы клиенту.
- Не конвертируются: выгрузки CSV (`/api/logs/export`, `/api/postbacks/export`), скачивание файлов и ключей, поток событий ассистента, страница и статика. gzip работает как с JSON.
- Целые за пределами ±(2^53−1) пишутся строкой в кавычках, чтобы не потерять цифры. Кодировщик — официальная библиотека [toon-go](https://github.com/toon-format/toon-go) (MIT, спецификация 4.4); одна точка — `writeJSON` в `internal/admin/admin.go`, флаг ставит прослойка `toonFormat` (`internal/admin/toon.go`).
- В OpenAPI: в `info.description` — описание формата, в `components.parameters.format` — общий параметр (`json` | `toon`), у ответа с JSON-примером рядом лежит `text/toon` с тем же примером в TOON. В параметры каждой операции `format` не добавлен: MCP и ассистент строят инструменты из параметров, и лишний аргумент только тратил бы токены.

Пример: `curl -H "Api-Key: em_..." "https://admin.example/api/offers?format=toon"`.

JSON (245 символов):

```json
{"items":[{"id":"o1","name":"Casino RU","country":"RU","payout":12.5,"enabled":true},{"id":"o2","name":"Betting UA","country":"UA","payout":8,"enabled":false},{"id":"o3","name":"Slots KZ","country":"KZ","payout":10.25,"enabled":true}],"total":3}
```

TOON (133 символа, на 46% короче):

```
items[3]{id,name,country,payout,enabled}:
  o1,Casino RU,RU,12.5,true
  o2,Betting UA,UA,8,false
  o3,Slots KZ,KZ,10.25,true
total: 3
```

По спецификации табличная форма требует у всех записей один набор полей и только простые значения (или вложенные объекты одного вида). Наши ответы пропускают пустые поля (`omitempty`), поэтому перед кодированием TOON массив записей выравнивается (`toonTable` в `internal/admin/toon.go`, только в TOON, JSON не меняется):

- каждая запись получает объединение ключей всех записей в порядке первого появления, недостающее поле — `null`. `null` в ячейке значит «поля нет в JSON»;
- поле-массив простых значений (`countries`, `subs`) библиотека в таблице держать не умеет, поэтому в ячейку пишется его компактный JSON строкой: `["ru","kz"]` → `"[\"ru\",\"kz\"]"`, пустой массив → `"[]"`. Ячейка-строка, начинающаяся с `[`, — это список. Строковое значение, которое само выглядит как JSON-массив, в TOON от такого списка не отличить;
- массив, где хоть у одной записи есть вложенный объект или массив объектов, не трогается: он остаётся таблицей с группами полей `{a,b{c}}`, если записи одного вида, иначе — списком. Так остаются `report` и `stats/performance` (поле-объект `cost` есть не у всех строк) и `groups` (потоки и правила).

Тесты `TestToonTableRoundTrip` и `TestToonAnswersRoundTrip`: декодер TOON, затем удаление `null` и разбор JSON-ячеек дают исходный JSON.

### Лимиты ключа

Лимит действует на каждый проверенный ключ отдельно и не касается сессии браузера. Устойчивая скорость — 10 запросов в секунду, всплеск — 30. Тяжёлые маршруты (чтения ClickHouse: `GET /api/logs`, `GET /api/logs/export`, `GET /api/log-values`, `GET /api/postbacks`, `GET /api/postbacks/export`, `GET /api/postback-log`, `GET /api/report`, `GET /api/keywords/stats`, `GET /api/keywords/trend` и `GET /api/stats/{summary,timeseries,breakdown,performance,facts}`) вдобавок держат не больше двух одновременно выполняемых запросов на ключ. Превышение — `429` с заголовком `Retry-After` в секундах (не меньше 1) и текстом `too many requests` или `too many heavy requests`. Состояние лимита живёт в памяти процесса admin; отзыв или удаление ключа сбрасывает его запись.

### Журнал действий ключей

Каждая запись, не `GET`, `HEAD` и `OPTIONS`, от ключа дописывается строкой JSON в файл `<EMTDS_DATA_DIR>/audit/admin-ГГГГ-ММ.jsonl` (месяц по UTC) и дублируется строкой `api key write` в лог admin. Поля: `ts`, `key_id`, `method`, `route`, `status`, `ms`, `ip`. `route` — шаблон маршрута (`PUT /api/groups/{id}`), не путь с id. Тела, заголовки, строка запроса и сам ключ не пишутся. Чтения не журналируются. Если `EMTDS_DATA_DIR` пуст, файла нет, остаётся только лог. Каталог создаётся с правами `0700`, файл — `0600`. Файлы старше шести месяцев admin удаляет при старте и затем раз в сутки; чужие файлы в каталоге не трогаются.

### Схема `GET /api/openapi.json`

Открыт любой сессии. Отдаёт OpenAPI 3.1 для маршрутов, которые доступны именно этой сессии: ключу не показываются адреса только для браузера, адреса без нужного действия и адреса вне его разделов; сессии браузера — все, которые ей разрешены. Публичные маршруты (`GET /api/health`, `GET /healthz`, `GET /api/brand`) тоже в схеме: у них `security: []` и `x-emtds-public: true`. Маршруты входа (`/api/setup`, `/api/login`, `/api/recover`) видит только сессия браузера, как маршруты с `x-emtds-cookie-only`.

Расширения операции: `x-mcp` (`read` или `write` — операция годится для MCP-инструмента и меняет ли она данные), `x-emtds-section`, `x-emtds-admin` (только администратор или ключ `ADMIN`), `x-emtds-action`, `x-emtds-heavy`, `x-emtds-cookie-only`, `x-emtds-public`, `x-emtds-i18n` (`{ru:{summary, description}, uk:{…}}`). У параметра есть свой `x-emtds-i18n` (`{ru, uk}`); у параметра пути, который съедает несколько сегментов, в схеме стоит `x-emtds-path`. `tags` операции — раздел документации; верхний `tags` перечисляет разделы по порядку с названиями на трёх языках. В `responses` есть код успеха с примером ответа (`example`) и коды ошибок самого маршрута; общие `401`, `403` и `429` в каждом маршруте не повторяются. Пример тела запроса лежит в `requestBody.content.<тип>.example`. Схема питает [MCP-сервер](mcp.md) и страницу `#/settings/docs`.

Единственный источник текста — таблица `routeDocs` (`internal/admin/routedoc*.go`, AI — `assistant_routes.go`), разделы — `docTags` (`routedoc_tags.go`). Тест `TestRouteDocCoversEveryRoute` требует запись для каждого смонтированного маршрута и ничего лишнего: краткое описание на en, ru и uk; у маршрута, доступного ключу, ещё полное описание на трёх языках, переводы параметров, пример тела, пример ответа (кроме `204`) и только известные коды ошибок.

### Страница `#/settings/docs`

Страница строится из `GET /api/openapi.json` сессии браузера. Сайдбара со списком маршрутов нет. Сверху поиск по пути, методу, заголовку, описанию и параметрам: регистр, «ё» и другая раскладка не важны, нужны все слова. Список обновляется с паузой после ввода, совпадения подсвечены, счётчик показывает, сколько маршрутов нашлось. Стрелки двигают выбор, Enter и клик прокручивают к карточке. Без запроса фокус в поле показывает все маршруты. Под поиском оглавление разделов страницы, сами карточки остаются на странице. Фильтр метода сужает только поиск. У каждого эндпоинта якорь `#/settings/docs/op-<operationId>`, у раздела — `#/settings/docs/sec-<тег>`. Карточка: бейдж метода, путь, описание, бейджи «Нужна галочка …», «Только ключ ADMIN», «Тяжёлый», «Без ключа», таблица параметров (имя, где, тип, обязателен, описание), пример `curl` с кнопкой копирования, пример тела, пример ответа и коды ошибок. Заголовки разделов (`div.bt`, например «Аутентификация») жирные. В тексте аутентификации ключ — `em_...`; ключи до этого префикса начинаются с `kz_` и принимаются. Базовый адрес в примерах — `location.origin`. Кнопки «OpenAPI JSON» и «Postman» скачивают схему и коллекцию (`GET /api/postman.json`, тот же набор маршрутов), «Markdown» открывает `/api/docs.md` на языке интерфейса. Последний блок «Ключу недоступно» собран из `x-emtds-cookie-only`. По умолчанию фильтр — «Все методы»; поиск и фильтр сбрасываются при каждом открытии.

Методы окрашены одинаково в оглавлении, карточках и фильтре: `GET` — зелёный, `POST` — синий, `PUT` — жёлтый, `PATCH` — акцентный, `DELETE` — красный; цвета берутся из переменных темы, поэтому работают в светлой и тёмной. Примеры JSON и `curl` подсвечены своим маленьким подсветчиком из чистого блока SPA (`apiDocsHighlight`): ключи, строки, числа и литералы JSON, команда, флаги и строки `curl`. Сторонняя библиотека не нужна: примеры строит сама страница через `JSON.stringify` и `apiDocsCurl`, поэтому формат заранее известен, а загрузчик, лицензия и CSP не меняются. Текст экранируется до разметки.

### Публичная документация

Без входа доступны:

- `/docs` — та же страница справочника, но со всеми маршрутами; якоря — `/docs#op-<operationId>`;
- `GET /api/docs/openapi.json` — OpenAPI всех маршрутов без фильтра по сессии; маршруты только для браузера отмечены `x-emtds-cookie-only`, с галочкой — `x-emtds-action`;
- `GET /api/docs/postman.json` — коллекция Postman тех же маршрутов, без секретов, с вымышленными примерами и заглушкой ключа `em_example`;
- `GET /api/docs.md?lang=en|ru|uk` — весь справочник одним текстом Markdown для людей и AI-агентов; `/llms.txt` — тот же текст на английском.

Только чтение. Примеры вымышлены, ключей, данных и внутренних адресов в ответах нет; адрес сервера в схеме — `/`. Ответы кэшируются на пять минут (`Cache-Control: public, max-age=300`, `ETag`, `304` на совпавший `If-None-Match`). Лимит — 10 запросов в секунду и всплеск 30 на адрес клиента, сверх — `429` с `Retry-After`. Тот же `/api/openapi.json` для ключа и сессии не меняется: он по-прежнему показывает только доступное вызывающему.

Переключатель «Публичная документация» в карточке «Публичная ссылка» на странице `#/settings/docs` (нужна запись в разделе интеграций, только сессия браузера) хранится в `docs.json` (`EMTDS_DOCS_FILE`, по умолчанию в каталоге данных admin): `GET` и `PUT /api/docs/settings` с `{"public": bool}`. По умолчанию включено. Выключенная — `/docs`, `/api/docs/openapi.json`, `/api/docs/postman.json`, `/api/docs.md` и `/llms.txt` отвечают `404`. `GET /api/postman.json` при этом остаётся у сессии и ключа. Файл, который не читается, закрывает публичную документацию. Рядом ссылка `<origin>/docs` с кнопкой копирования. Коллекция, OpenAPI и `/llms.txt` собираются из `routeDocs`, отдельного файла коллекции нет.

nginx менять не нужно: в `deploy/nginx/emtds.conf` (по IP) и `emtds-admin-host.conf` (`admin.<домен>`) `location /` уже ведёт в admin, поэтому `/docs`, `/llms.txt` и `/api/docs*` доходят без правок.

### Как правит агент

Для записи кампании агент использует `PUT /api/groups/{id}`, а не `PUT /api/groups` (его закрывает действие `groups_replace`). У записи нет ETag и версии: побеждает последняя запись, правка поверх чужой правки молча перетирает её. Агент читает `GET /api/groups`, меняет свою кампанию и сразу пишет её. `PUT /api/groups` с телом `[]` или `null`, после слияния которого из сохранённого списка пропадает хотя бы одна кампания, отвечает `409` `empty list would delete campaigns; use DELETE /api/groups/{id}`. Снятие одной кампании — `DELETE /api/groups/{id}`.

`GET /api/logs/filters` — тяжёлый маршрут (слот `keyHeavyMax` у ключа). Неготовая волна измерения отдаёт пустой список и `200`. Любая другая ошибка запроса — `500` `stats error`. `POST /api/cron/run` с `job=telegram_test` от ключа отвечает `403` `cookie session required`.

Правило отсутствующего поля у `PUT`: у каталогов и кампаний `PUT` заменяет запись целиком, поэтому поле, которого нет в теле, пропадает или принимает значение по умолчанию. У `PUT /api/api-keys/{id}` наоборот: не присланное поле сохраняет прежнее значение, и клиент, приславший только `name` и `scopes`, не сбросит тип, роль, доступ и действия. Роль без `access` убирает сохранённый `access`, непустой `access` без роли убирает сохранённую роль.

### Перед откатом

Перед откатом admin на версию без типов ключей отзовите все ключи `USER` и ключи с непустым `actions`. Старый admin переписывает `api_keys.json` без новых полей: ключ `USER` теряет тип, роль и доступ и становится обычным `ADMIN`, ключ с действиями теряет список действий. Откат без отзыва превращает ограниченный доступ в полный. Откат на версию, которая не знает действие `lists_read`, считает ключ с этим действием недействительным, пока действие не уберут.

## Карта маршрутов

Каждый защищённый маршрут описан в таблице `routeAccess` (`internal/admin/access.go`); маршрут без записи в ней не даёт админке стартовать. «Админ» значит только администратор: сессия администратора или ключ `ADMIN`; разделы `users`, `api_keys`, `integrations`, `automation`, `pages`, `bot_protection` и `settings` тоже только для них. «Кука» — маршрут закрыт любому ключу (`403`, код `cookie_required`). «Действие» — ключу нужно выданное действие. «Тяжёлый» — маршрут под дополнительным лимитом ключа.

Без `routeAccess` и без сессии работают маршруты из `publicRoutes`: `GET /api/health`, `GET /healthz`, `GET /api/brand` и вход (`GET` и `POST /api/setup`, `POST /api/login`, `POST /api/recover`); плюс `GET /assets/…` и сама страница `GET /`. Заголовок `Api-Key` они не читают.

## Текущая сессия (`GET /api/me`)

Только кука, без `Api-Key`. Ответ `200`:

```json
{
  "user": "логин",
  "uid": "id из users.json",
  "type": "ADMIN или USER",
  "csrf": "…",
  "engine": "база ссылок движка",
  "prefs": { "lang": "", "tz": "" },
  "pages": ["dashboard", "flows", "…"],
  "access": { "sections": [], "grants": {}, "hidden": [] },
  "role": { "id": "…", "name": "…" },
  "hidden": ["cost", "cost_cents", "cost_cur"]
}
```

У администратора окружения (кука без `uid`) поле `uid` пустое, `type` — `ADMIN`, `pages` — все разделы, `access` нет. У записи `ADMIN` в `users.json` — полный список `pages`, `access` не отдаётся. У `USER` в `access` — действующие разделы, гранты и скрытые поля (для пользователя с ролью — из роли); `pages` совпадает с видимыми пунктами меню. `role` есть только у пользователя с существующей ролью. `hidden` — все скрытые id с учётом групп, всегда массив.

## Роли (`/api/roles`)

Только кука и раздел `users`. `GET`, `POST` `/api/roles`, `GET`, `PUT`, `DELETE` `/api/roles/{id}` и `POST /api/roles/reload` (перечитать `roles.json` после ручной правки; `200` или `503 roles unavailable: <причина>`). Назначение через `role_id` в `/api/users` и все правила — в [Роли](roles.md).

## Пользователи (`/api/users`)

Только кука. Раздел `users` в access (тип `ADMIN` в файле или администратор окружения). API-ключ — `403 cookie session required`.

| Метод | Путь | Тело | Успех | Ошибки |
| --- | --- | --- | --- | --- |
| GET | `/api/users` | — | `200`, массив без `hash`; первая строка — администратор окружения (`id` пустой, `source: env`), далее записи файла с `source: file` | при выключенном файле — `200` и только строка администратора окружения |
| POST | `/api/users` | `login`, `password`, `type`, `enabled`, `prefs`, `access`, `role_id` | `201`, запись | `400` валидация, неизвестная роль, роль вместе с непустым `access`; `409` логин занят или зарезервирован; `503` users disabled |
| GET | `/api/users/{id}` | — | `200` | `404` |
| PUT | `/api/users/{id}` | `login`, `type`, `enabled`, `prefs`, `role_id` (частично) | `200` | `400`; `404`; `409` last administrator, себя выключить, логин |
| DELETE | `/api/users/{id}` | — | `204` | `404`; `409` last administrator, себя |
| PUT | `/api/users/{id}/password` | `{"password"}` | `204` | `400` короткий пароль; `404` |
| PUT | `/api/users/{id}/access` | объект `access` целиком | `200`, `access_source: manual` | `400` секция/ресурс/mode; `404`; `409 user has a role` — у пользователя с ролью доступ задаёт роль |

Пустой `type` при создании — `USER`. Пароль можно не передавать; пустой пароль в `PUT …/password` снимает вход. Администратор окружения не имеет `id`, маршруты `/api/users/{id}` к нему не применимы (`404`); пароль — `POST /api/password` под своей сессией.

## Ограничения для USER

Без раздела или вне гранта: `403 forbidden` на защищённый маршрут. Невидимая запись каталога или кампания — `404 not found` на GET/PUT/DELETE по id. Статистика и журналы с `f=` по скрытой money-метрике — `400`. Все `/api/spend` при `hidden: cost` — `403`. Сохранение кампании, оффера, лендинга и исходящих постбэков кампании со скрытым макросом (`[IP]`, `{status}` и т. п.) — `400 macro <макрос> uses hidden field <поле>`, если такой же строки нет дословно на том же месте сохранённой записи; новый `{имя}` при скрытом `keyword`, `sub_id_N` или `cost` — `400 macro {имя} may read a hidden field`; смена параметра скрытого поля в источнике или `cost_param`, `currency_param` кампании — `400`; `offer_query` сети проверяется как ссылка, оффер на сети с запрещённым макросом в `offer_query` — `400 network offer_query: …`; смена `out` потока с запрещённым макросом в `curl`, `b_curl` или `remote.url` — `400 stream … sends a hidden field`; любой файл лендинга (`PUT /api/landings/{id}/files/…`, каждый файл `POST …/archive`) — по тому же правилу дословности; архив, который не читается целиком, — `400 bad archive` для всех, каталог лендинга не меняется; любая операция с лендингом (запись записи, файла, удаление файла, загрузка архива), после которой точкой входа становится другой файл с запрещённым макросом, — `400 landing entry <путь>: …`; `entry`, который движок не принимает (абсолютный путь, `..`, `\`, скрытый файл), — `400 entry must be a relative path inside the landing` для всех (правила — в [Роли](roles.md)); `GET /api/log-fields` помечает у каждого поля `hideable`. Подробности — [Пользователи панели](users.md).

## Настройки интерфейса (`/api/ui`, `/api/brand`)

Файл задаёт переменная `EMTDS_UI_FILE`. По умолчанию `ui.json` лежит рядом с `groups.json` в каталоге состояния админки.

`GET /api/ui` — любая сессия: браузера или ключа, раздел не нужен. Тело: `{ "cols": { "ключ": [{ "id", "on" }] }, "dash": { "panels", "dim" }, "company": { "name", "logo" } }`. Если путь к файлу не задан, ответ — значения по умолчанию с `200`. Ошибка чтения файла — `500`.

`PUT /api/ui` — раздел `settings` (администратор или ключ `ADMIN`); сессии браузера нужен заголовок `X-CSRF-Token`, ключу — нет. Тело того же вида. Валидация (`ui.go`): ключи `cols` — `[a-z][a-z0-9_]{0,31}`, не больше 32 групп; в группе не больше 200 столбцов, id обязателен, не длиннее 64 символов, без дубликатов; `dash.panels` — не больше 64 строк по 64 символа; `dash.dim` — не длиннее 64 символов; `company.name` — после trim не длиннее 64, пустое остаётся пустым; `company.logo` — пустой или data-URL `image/png|jpeg|gif|webp|svg+xml` в base64, не длиннее 280 000 байт. Нарушение — `400` с текстом ошибки, `bad json` при невалидном JSON. Без настроенного пути к файлу — `503` «ui file not configured». Без сессии — `401`.

`GET /api/brand` — без сессии. Ответ `{ "name", "logo" }`, заголовок `Cache-Control: no-store`. Столбцы и панели не отдаются. Нужен экрану входа и шапке до авторизации.

## Кампании (`/api/groups`)

`GET /api/groups` отдаёт массив кампаний. `PUT /api/groups` принимает массив целиком и отвечает `200` `{"status":"saved"}`.

`PUT /api/groups/{id}` записывает одну кампанию: строка с этим id заменяется, если её не было — добавляется. Тело — один объект, не больше 8 МБ. Пустой `id` в теле берётся из пути. Непустой `id`, отличный от пути, отвечает `400` `id mismatch`. Успех — `200` `{"status":"saved"}`.

`DELETE /api/groups/{id}` снимает кампанию. Нет такого id — `404` `not found`. Успех — `200` `{"status":"deleted"}`.

Запись и удаление требуют раздел `flows`. Нет хранилища кампаний — `503`.

Ответы админки сжимаются gzip, если в `Accept-Encoding` есть `gzip` и это не переход протокола (`Upgrade` или `Connection: upgrade`). В ответе тогда `Content-Encoding: gzip`, добавляется `Vary: Accept-Encoding`, `Content-Length` снимается. Ответ без тела уходит без `Content-Encoding`.

`GET /api/lookup?ip=` (раздел `tools`) отдаёт объект `visitor`, список `lists` (в какие `.dat` попал адрес) и список `databases` (загруженные гео-базы: `path`, `type`, `built`, `loaded`). В `visitor` поле `proxy`: адрес есть в `ip_proxy` либо организация совпала с `proxy_org`, и адреса из `ip_private_relay` при этом прокси не считаются. Поля `asn` и `org` берутся у DB-IP, а при его промахе у MaxMind. Когда базы расходятся, добавляются `asn_alt` и `org_alt` — номер и название у второй базы (MaxMind); если расхождения нет, этих полей в ответе нет. Подробно — [гео-базы](geo-databases.md). Негодный адрес — `400`.

`POST /api/simulate` (тот же раздел) в ответе тоже кладёт `proxy` в `visitor`. Правила потока, включая `proxy` и `ip_version`, проверяются. Детекция ботов не запускается.

`groups.json` пишется одним компактным JSON, без отступов. Пустые необязательные поля не пишутся. Поле `status` у кампании и у потока пишется всегда.

В правилах потока `proxy` и `ip_version` устроены как `unique` и `bot`: `0` — выключено. У `proxy` значение `1` — только прокси, `2` — только не прокси. У `ip_version` значение `1` — только IPv4, `2` — только IPv6 ([правила потока](router-rules.md)). У потока поле `filter_or`: истина значит «любое из этих условий». В блоке `bots` потока поля `ch_proxy` и `ch_non_mobile`; оба по умолчанию выключены и в файл не пишутся, пока ложь. Смысл проверок — [защита от ботов](bot-protection.md).

`GET /api/bot-protection` (раздел `bot_protection`) отдаёт профиль установки: включённые переключатели `ch_*` и `save_ip` (выключенные не пишутся), поле `ch_proxy` всегда (`true` или `false`), а также `proxy_default` и `private_relay`. `proxy_default: true` — в `bot_protection.json` нет значения `ch_proxy`, действует умолчание «включено», причём движок включает его, только когда загружен непустой `ip_private_relay`. `private_relay: true` — этот список в каталоге данных есть и не пуст. Нет файла или он не разбирается — профиль по умолчанию. `PUT /api/bot-protection` сливает тело с сохранённым профилем по ключам: названные ключи заменяются, остальные остаются, `null` убирает ключ. `{"ch_proxy":null}` возвращает проверку прокси к умолчанию, `{"ch_proxy":false}` выключает явно. Неизвестные ключи и `redirect`, `out`, `header` отбрасываются. Ответ — как у `GET`. Тело не объект, значение не булево или тело больше 1 МиБ — `400`; путь файла не задан — `503`; запись не удалась — `500`. Сохранённый профиль действует на клики не позже чем через 5 секунд.

## Режим `?api=`

Движок принимает параметр `api`: JSON в обычном или URL-safe base64. Внутри поле `key_api`. Его принимает ключ с доступом `engine` или значение `EMTDS_API_KEY`. Неверный ключ — `403`. Остальные поля: `id` (кампания), `ip`, `referer`, `useragent`, `se`, `lang`, `uniq` (`yes` — уникальный визит), `key`, `domain`, `page`, `cf_country`, `pars` (массив строк). Запрос идёт на домен ссылок движка, не на адрес админки. Заголовок `X-Requested-With` в этом режиме в клик не пишется.

```bash
curl -H "Api-Key: em_..." "http://127.0.0.1:8090/api/report?from=2026-10-01T00:00:00Z&to=2026-10-16T00:00:00Z&f=country:eq:PL"
curl -H "Api-Key: em_..." "http://127.0.0.1:8090/api/stats/breakdown?dim=country&limit=6&from=2026-10-01T00:00:00Z&to=2026-10-16T00:00:00Z&f=device:eq:mobile"
curl -H "Api-Key: em_..." "http://127.0.0.1:8090/api/stats/summary?from=2026-10-01T00:00:00Z&to=2026-10-16T00:00:00Z&f=country:eq:PL"
curl -H "Api-Key: em_..." "http://127.0.0.1:8090/api/stats/performance?from=2026-10-01T00:00:00Z&to=2026-10-16T00:00:00Z&f=device:eq:phone"
curl -H "Api-Key: em_..." "http://127.0.0.1:8090/api/stats/facts?from=2026-10-01T00:00:00Z&to=2026-10-16T00:00:00Z&f=country:eq:PL"
curl -H "Api-Key: em_..." "http://127.0.0.1:8090/api/logs/export?from=2026-10-01T00:00:00Z&to=2026-10-16T00:00:00Z&f=country:eq:PL"
curl -H "Api-Key: em_..." "http://127.0.0.1:8090/api/postbacks/export?from=2026-10-01T00:00:00Z&to=2026-10-16T00:00:00Z&f=status:eq:sale&sort=profit&dir=desc"
```

Журналы кликов и конверсий (`GET /api/logs`, `GET /api/logs/export`, `GET /api/postbacks`, `GET /api/postbacks/export`) принимают необязательные `sort` и `dir`. `sort` — имя поля из `GET /api/log-fields` для нужной таблицы (`events` или `conversions`), включая алиас `group` для кампании. Сортировать нельзя по внутренним полям, по `useragent`, `referer`, `out`, `page` и по столбцам, чья волна на сервере ещё не готова. Пустой `sort` — порядок по времени строки (`ts`) по убыванию. `dir` — только `asc` или `desc`; пустой `dir` трактуется как `desc`. Неверное поле, скрытое для роли поле или неверный `dir` — ответ `400` с текстом `bad sort`. У экспорта те же фильтры, что у таблицы; `limit` и `offset` игнорируются. CSV обрезается на 50 000 строк; при обрезке заголовок ответа `X-Export-Truncated: 1`. В админке CSV кликов и конверсий скачивается через `fetch`; при этом заголовке показывается предупреждение, имя файла берётся из `Content-Disposition`, если есть.

Кратко по адресам. Кампании — в разделе выше: `GET /api/groups` массивом, `PUT /api/groups` массивом, одна запись — `PUT` и `DELETE /api/groups/{id}`. Каталоги: список `GET` и `POST`, запись `GET`, `PUT`, `DELETE` на `/{id}`. Офферы `/api/offers`, сети `/api/affiliate-networks`, лендинги `/api/landings`, источники `/api/traffic-sources`. Общие исходящие S2S-шаблоны: `GET /api/s2s` массивом, `PUT /api/s2s` всем массивом и только администратору; у кампании они указываются в `postback_ids` (подробно — в [postbacks](postbacks.md)). Домены: `GET` и `POST /api/domains`, запись на `/api/domains/{id}`, проверка `POST /api/domains/{id}/check` (подробно — в [офферах и лендингах](offers-landings.md)). Покупка и сверка доменов у Namecheap — `POST /api/registrars/namecheap/register` только администратору с сессией браузера; тело `{domain, reconcile: true}` только сверяет строку `pending` и никогда не покупает: без такой строки ответ `404 not found`, при другом состоянии — `409 not pending` (подробно — в [namecheap](namecheap.md)). `GET /api/stats/facts` в строке клика несёт `uniq` и `uniq_first` — уники самой строки и уники первого шага кампании. Журналы и срез — в примерах выше. Фильтры `f=` описаны в [фильтрах и столбцах журналов](log-filters.md). `GET /api/stats/summary`, `GET /api/stats/timeseries`, `GET /api/stats/performance` и `GET /api/stats/facts` принимают `from`, `to` и повторяемый `f=` по кликам. У ряда timeseries параметр `step` в секундах и не меньше 3600. В точке timeseries поле `cost` — центы клика по коду валюты. `GET /api/stats/performance` в строке несёт `cost` так же; конверсия с `group_id` стыкуется по нему, строка без `group_id` (старые postbacks) — по имени кампании. `GET /api/stats/facts` в клике отдаёт `cost_cents` и `cost_cur`: одна связка ключей может повториться для разных валют. `GET /api/postbacks` отдаёт `rows`, `total` (сумма profit) и `count` (сколько строк подошло под фильтр, не размер страницы). `GET /api/spend` фильтр `f=` не принимает. `GET /api/cron` отдаёт `telegram_configured`, `config_error` (текст проверки конфига, без секретов) и `geo_paths.city_file` / `geo_paths.asn_file`. Для DB-IP ASN Lite есть `geo_paths.dbip` (путь к файлу известен: задан `EMTDS_DBIP_ASN_DB` или выводится из `EMTDS_ASN_DB` / `EMTDS_GEO_DB`), `geo_paths.dbip_file` (файл есть и не пуст) и `dbip_url` — шаблон адреса источника с `{YYYY-MM}`. Источник `dbip_asn` в `geo_db.sources` — только `https://download.db-ip.com/…`, иначе конфиг не проходит проверку ([гео-базы](geo-databases.md)). В конфиге есть поле `seeded` — какие источники по умолчанию уже были предложены; клиент, который его не присылает, не возвращает удалённый источник.

Создание ключа доступно только сессии браузера:

```bash
curl -H "Content-Type: application/json" -H "X-CSRF-Token: ..." -b "сессия" \
  -d "{\"name\":\"кабинет\",\"scopes\":[\"admin\",\"engine\"]}" \
  http://127.0.0.1:8090/api/api-keys
```

Управление ключами с заголовком `Api-Key` недоступно. Полный текст с примерами режима `?api=` лежит на `#/settings/docs`.

## Ключевые слова (`/api/keywords/*`)

Раздел `keywords`. Оба маршрута только читают, тяжёлые (лимиты ключа — в «Лимиты ключа»), в схеме `GET /api/openapi.json` это операции `keyword_stats` и `keyword_trend` с `x-mcp: read`. Смысл колонок и откуда берётся ключ — в [ключевых словах](keywords.md).

| Метод | Путь | Что отдаёт |
| --- | --- | --- |
| GET | `/api/keywords/stats` | Таблица ключей за период |
| GET | `/api/keywords/trend` | Ряд по дням для первых ключей той же таблицы |

Параметры:

| Параметр | Маршрут | Смысл |
| --- | --- | --- |
| `from`, `to` | оба | Период, RFC3339. Без них — последние 24 часа. Неразобранное значение отбрасывается, берётся умолчание. `from` не раньше `to` или период длиннее 92 дней — `400 bad range` |
| `f` | оба | Повторяемое условие по кликам, как в журналах ([фильтры](log-filters.md)). Кампания — `f=campaign_id:eq:<id>`, поиск по ключу — `f=keyword:contains:<текст>`. Условие применяется и к конверсиям, если у них есть такое поле |
| `tz` | `trend` | Имя пояса IANA (`Europe/Kyiv`), по которому режутся дни. Пусто — `UTC`. `Local` и неизвестное имя — `400 bad tz` |
| `top` | `trend` | Сколько ключей вести, от 1 до 25. Пусто — 25. Другое число и не число — `400 bad top` |

Ключи для тренда в URL не передаются: сервер сам берёт первые `top` ключей в порядке таблицы (доход, затем клики, затем ключ). Поэтому ряд и таблица с теми же `from`, `to` и `f` всегда про одни и те же ключи.

Ответ `GET /api/keywords/stats`:

```json
{
  "rows": [
    { "keyword": "shoes", "hits": 120, "unique": 98, "conv": 7, "leads": 3, "sales": 4,
      "rejected": 0, "profit": 42.5, "depsum": 300 }
  ],
  "truncated": false,
  "conv_ready": true
}
```

`hits` и `unique` — только люди. `conv` и `profit` считают все статусы по дате конверсии; `leads`, `sales`, `rejected` делят `conv` по статусам; `depsum` — сумма депозитов, не выплата. Пустой `keyword` — клики без ключа. Строк не больше 2000; `truncated: true` значит, что ключей больше и оставлены первые по доходу. `conv_ready: false` — колонок конверсий для запроса нет: денежные поля тогда нули без смысла. Источник без статистики ключей отвечает `200` и пустой таблицей.

Ответ `GET /api/keywords/trend`:

```json
{
  "days": ["2026-10-01", "2026-10-02"],
  "series": [
    { "keyword": "shoes", "hits": [60, 60], "conv": [3, 4], "profit": [20, 22.5] }
  ],
  "conv_ready": true
}
```

`days` — каждый календарный день периода в поясе `tz`, пропуски включены. В каждой серии по одному числу на день, тихий день — ноль. Серии идут в порядке таблицы. При `conv_ready: false` массивов `conv` и `profit` нет.

Скрытые поля роли убирают ключи из ответа: `status` — `leads`, `sales`, `rejected`; `profit` — `profit` и `depsum` (в тренде — массивы `profit`); `uniq` — `unique` ([роли](roles.md#скрытие-в-ключевых-словах)).

| Код | Когда |
| --- | --- |
| `400` | `bad range`, `bad top`, `bad tz`, `bad filter: …` (в том числе скрытое поле) |
| `403` | у сессии или ключа скрыто поле `keyword` |
| `429` | `busy`: на этом процессе admin уже идут два запроса по ключам, третий в очередь не встаёт. Код `too_many_requests`, заголовка `Retry-After` нет. Лимит ключа на тяжёлые маршруты отвечает тоже `429`, но с `Retry-After` |
| `504` | `query too heavy`: ClickHouse остановил запрос, сократите период или выберите кампанию ([лимиты](analytics-limits.md#ключевые-слова)) |

Примеры:

```bash
curl -H "Api-Key: em_..." "http://127.0.0.1:8090/api/keywords/stats?from=2026-10-01T00:00:00Z&to=2026-10-16T00:00:00Z&f=campaign_id:eq:abc123&f=keyword:contains:shoes"
curl -H "Api-Key: em_..." "http://127.0.0.1:8090/api/keywords/trend?from=2026-10-01T00:00:00Z&to=2026-10-16T00:00:00Z&f=campaign_id:eq:abc123&top=10&tz=Europe/Kyiv"
curl -b "сессия" "http://127.0.0.1:8090/api/keywords/stats?from=2026-10-01T00:00:00Z&to=2026-10-16T00:00:00Z"
```

`GET` с кукой сессии `X-CSRF-Token` не требует.

## Домены (`/api/domains`)

Список и запись — в [офферах и лендингах](offers-landings.md) и [namecheap](namecheap.md). Дополнительно к полям `domains.json` в ответах API:

| Поле | Смысл |
| --- | --- |
| `admin_host` | Вычисляемый адрес `admin.<host>` или пусто, если домен не для админки |
| `admin_dns` | `ok`, если запись `admin.<host>` создана в Cloudflare, иначе текст ошибки без секретов |
| `admin_ok` | После проверки HTTPS: ответ admin на `admin.<host>` совпал с ожиданием |
| `admin_reason` | При сбое проверки админки: `dns`, `tls`, `connect`, `foreign` |

Домен для админки: не `disabled`, хост без префикса `admin.`, и **основной** или роль `admin` / `both`.

| Метод | Путь | Успех | Ошибки |
| --- | --- | --- | --- |
| `POST` | `/api/domains/{id}/admin-dns` | `200`, обновлённая строка с `admin_host`, `admin_dns`, `admin_ok`, `admin_reason` | `404` нет id; `403` нет записи; `409` не admin-домен, нет Cloudflare/IP/зоны, хост не корень зоны, параллельное обновление; `502` отказ Cloudflare (в т.ч. чужая A-запись); `503` нет хранилища |

Создание или смена основного/роли admin/both при активной зоне Cloudflare ставит обновление DNS admin в очередь; ответ сохранения DNS не ждёт.

`GET /healthz` на admin (в том числе `https://admin.<домен>/healthz`) — без сессии и без `Api-Key`: тело `ok`, заголовки `X-Emtds-Host`, `X-Emtds-Service: admin`, при `probe` — `X-Emtds-Probe`. На движке тот же путь отдаёт `X-Emtds-Service: engine`.

## AI-ассистент (`/api/ai/*`)

Бета, подробности — в [AI-ассистенте](ai-assistant.md). Все маршруты только по куке: `Api-Key` получает `403` (`cookie_required`), в MCP их нет. В `GET /api/openapi.json` они описаны, но без расширения `x-mcp`. Запись (`POST`, `PUT`, `DELETE`) требует `X-CSRF-Token`. Кроме настроек (раздел `integrations`) и статуса, маршруты доступны только администратору (`403 forbidden` остальным). При выключенном ассистенте всё, кроме настроек, проверки ключа, каталога моделей и статуса, — `503 ai_disabled`.

| Метод | Путь | Доступ | Тело | Ответ |
| --- | --- | --- | --- | --- |
| GET | `/api/ai/settings` | админ, `integrations` | — | `200`: `enabled`, `provider`, `model`, `allowed_models`, `keys` (`has_key`, `mask`; ключ не отдаётся), `max_output_tokens`, `max_steps`, `turn_input_tokens`, четыре лимита, `prices`, `default_prices`, `price_unknown`, `limit_ceilings`, `limit_max`, `usage_today` (общий, по пользователям, `me`), `beta` |
| PUT | `/api/ai/settings` | админ, `integrations` | любые поля настроек; `keys` `{провайдер: ключ}` (пусто или маска — оставить прежний), `clear_keys`, `prices` — полная карта правок | `200`, как GET |
| POST | `/api/ai/test` | админ, `integrations` | `provider`, `key` (пусто или маска — сохранённый) | `200 {"models":[…]}`, кэш каталога обновлён, ничего не сохраняется |
| GET | `/api/ai/models?provider=&refresh=1` | админ, `integrations` | — | `200`: `provider`, `fetched_at`, `ttl_seconds`, `models` (`id`, `name`, `context`, `input_per_m`, `output_per_m`, `tools`) |
| GET | `/api/ai/status` | любая сессия | — | `200`: `enabled`, `allowed` (`false` вне беты), `beta`, `provider`, `model`, `models`, `price_unknown`, `usage` (свой расход и лимиты, общий расход и лимиты) |
| GET | `/api/ai/chats?q=` | админ | — | `200 {"chats":[{id, title, created, updated, messages, status}]}`, `status` — `idle`, `running`, `interrupted` |
| POST | `/api/ai/chats` | админ | `title` (необязательно, до 80 знаков) | чат; при 200 чатах у пользователя старейший вытесняется |
| GET | `/api/ai/chats/{id}` | админ | — | `200`: `id`, `title`, `status`, `messages`, `changes` (карточки) |
| DELETE | `/api/ai/chats/{id}` | админ | — | `204`; правки чата остаются |
| POST | `/api/ai/chats/{id}/messages` | админ | `text` (до 8000 знаков), `context` (`page`, `arg`, `board`, `range`, `filters`, `tab`, `campaign`), `model`, `lang` (`en`, `ru`, `uk`, иначе `en`) | поток SSE, нужен `Accept: text/event-stream`, иначе `406 ai_not_acceptable` |
| GET | `/api/ai/changes?chat_id=&status=` | админ | — | `200 {"changes":[карточка]}` |
| POST | `/api/ai/changes/{id}/apply` | админ | `confirm_delete`, `confirm_host` | `200`, карточка |
| POST | `/api/ai/changes/{id}/reject` | админ | — | `200`, карточка |
| POST | `/api/ai/changes/{id}/revert` | админ | — | `200`, карточка |
| POST | `/api/ai/messages/{message_id}/revert` | админ | `chat_id` | `200 {"reverted":[id…],"stopped_at","error"}`; откат в обратном порядке до первого конфликта |

События потока ответа (`event: <имя>` и `data: <json>`; строка `: ping` — сердцебиение, неизвестные события клиент пропускает):

| Событие | Данные |
| --- | --- |
| `status` | `{"text"}` |
| `tool` | `{"name","summary"}` — вызван инструмент чтения |
| `text` | `{"message_id","text"}` — ответ модели |
| `proposal` | карточка правки (`status: proposed`) |
| `usage` | `{"input","output","usd"}` |
| `done` | `{"message_id"}` — конец хода |
| `error` | `{"code","error","params"}` — конец хода с ошибкой |
| `text_delta` | `{"text"}` — зарезервировано на потоковый вывод, сейчас не отправляется |

Карточка правки: `id`, `chat_id`, `message_id`, `resource` (`offers`, `affiliate_networks`, `traffic_sources`, `landings`, `campaigns`), `op` (`create`, `update`, `delete`), `entity_id`, `title`, `status` (`proposed`, `pending`, `done`, `aborted`, `reverted`, `rejected`), `diff` (`field`, `before`, `after`, `host_changed`), `links`, `external_host_change`, `landing_files` (`count`, `bytes`), `renumbered`, `created`, `applied`, `reverted`, `error`, `error_code`, `error_params`.

Ошибка — как везде в admin: `{"error":"…","code":"…","params":{…}}`; `params` необязателен, `error` на английском служит запасным текстом, панель строит текст по `code` и `params` через `tr`.

| HTTP | `code` | Когда |
| --- | --- | --- |
| `400` | `ai_bad_key` | нет ключа провайдера или провайдер отверг ключ |
| `400` | `ai_bad_model` | модель не в `allowed_models`, не в каталоге или без инструментов (`params.model`) |
| `400` | `ai_bad_limit` | лимит или параметр хода вне допустимого (`params.field`, `min`, `max`) |
| `400` | `ai_bad_patch` | поле вне белого списка, неверное значение, правка ничего не меняет |
| `400` | `ai_redacted_value` | в патче осталась маска, которой нет у сохранённой записи |
| `400` | `ai_confirm_required` | нужны `confirm_delete` или `confirm_host` (`params.need`) |
| `400` | `ai_input_too_large` | сообщение и список инструментов не помещаются в `turn_input_tokens` |
| `403` | `forbidden` | не администратор (вне беты) |
| `404` | — | чат, правка или запись не найдены или скрыты |
| `406` | `ai_not_acceptable` | нет `Accept: text/event-stream` |
| `409` | `ai_busy` | у пользователя уже идёт ход; чат отвечает |
| `409` | `ai_stale` | запись изменилась после предложения |
| `409` | `ai_conflict` | состояние не совпадает с ожиданием (`params.reason`) |
| `409` | `ai_has_links` | на удаляемую запись ссылаются (`params.links`) |
| `409` | `ai_landing_too_large` | лендинг больше 10 МиБ или 2000 файлов, или в нём симлинк |
| `409` | `keitaro_running` | идёт перенос, синхронизация или очистка Keitaro |
| `413` | `ai_chat_full` | чат переполнен, начните новый |
| `429` | `ai_quota` | лимит токенов или USD; повреждённый `usage.json` |
| `429` | `ai_rate_limited` | лимит запросов у провайдера |
| `429` | `ai_busy` | процесс уже ведёт максимум ходов |
| `502` | `ai_provider_error` | сбой провайдера |
| `503` | `ai_disabled` | ассистент выключен или не настроен |
| `504` | `ai_timeout` | провайдер не ответил вовремя |
| `507` | `ai_disk_full` | нет места для истории или снимка файлов |

Код `result_too_large` приходит модели в результате инструмента, а не клиенту.

## Статика `/assets/`

`GET /assets/{путь}` — без сессии и без `Api-Key`. Файлы встроены в бинарник админки из `internal/admin/web/vendor` (`//go:embed`). Ответ с `Cache-Control: public, max-age=86400`. Пустой путь, путь с завершающим `/`, каталог и неизвестный файл — `404`; листинг каталогов не отдаётся.
