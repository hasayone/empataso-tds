# Партнёрские сети

`GET|POST /api/affiliate-networks` и `GET|PUT|DELETE /api/affiliate-networks/{id}`.

Поля: `id`, `name`, `status`, `postback_url`, `offer_param`, `offer_query`, `group`.

Подпись группы — поле `group` в `networks.json`. Поиск на странице сети идёт по номеру, имени, группе, `postback_url` и `offer_query`. Общие правила групп, фильтров и окна «Группы» — в [офферах и лендингах](offers-landings.md), раздел «Группы и поиск».

Номер выдаёт сервер, если в `POST` нет `id`. Id сети — числовой. Файл `network_seq.json` только растёт, удалённый номер не возвращается. Явный `id` принимается. Форма его не отправляет. Правка идёт через `PUT` и сохраняет `offer_param` и `status`.

Таблица сортируется щелчком по заголовку любого включённого столбца: №, имя, группа, клики, лиды, продажи, отклонённые, CR, EPC, CPC, доход, депозит, расход, прибыль, ROI. «Группа» включена по умолчанию. Повторный щелчок меняет направление. Первый щелчок по числовому столбцу идёт по убыванию, по имени — по возрастанию. uEPC, CR подтв. и CR режима сортируются так же, когда шестерёнка их включает. Сортировка и набор столбцов хранятся в `/api/me/views`.

Внизу `#/networks` закреплён тот же двухрядный блок, что у кампаний: верхний ряд — суммы отфильтрованного списка (клики, уники, конверсии, продажи, расход, доход, депозит, прибыль, ROI, EPC; проценты не складываются, депозит не входит в доход), нижний — страница, размер (10/25/50/100/1000 или своё до 5000, по умолчанию 50) и экспорт CSV/HTML всех строк фильтра, не страницы. Скрытый `profit` прячет деньги в футере. Поиск, группа и сортировка возвращают на первую страницу. Размер страницы хранится в `networks.page` у `/api/me/views`, не в `localStorage`. Вложенная таблица офферов открытой сети не пагинируется и второго блока не получает.

`postback_url` — заметка для кабинета сети. Движок её не вызывает и вторую очередь не поднимает.

`offer_query` — строка вроде `sub1={subid}`. Она дописывается к ссылке, которую видит посетитель, после того как оффер уже узнан по адресу без этой склейки. Уже стоящий query не затирается. Адрес длиннее 500 символов, с пробелом или со схемой `://` даёт `400`.
Строка сети на странице — сумма кликов и конверсий с этим `network_id` за период. Доход подтверждённый считает статусы `lead` и `sale`. Открытие строки показывает офферы этой сети.

Шаблон по умолчанию: `{engine}/postback?subid={subid}&status={status}&payout={payout}`. Готовые адреса копируются из меню пользователя, пункт «Постбеки» выше настроек: лид и отказ (`status=rejected`) без выплаты, продажа с `payout={payout}`, «Копировать все» кладёт три строки. Поле сети `postback_url` остаётся заметкой и движок его не вызывает.

Шестерёнка столбцов сети помнит порядок в `emtds-net-cols`. В самом низу списка столбцов сетей, офферов и кампаний шесть производных, выключенных по умолчанию, каждый от знаменателя своей строки и не суммой процентов (после них ещё «depSum»: сумма параметра `depsum` постбека по строке, депозит лидов и продаж; в доход не входит, отклонённые конверсии в неё не попадают, без параметра там 0): «CR лидов» (лиды / клики), «CR от уников» ((лиды + продажи) / уники), «Уники %» (уники / клики), «Аппрув %» (продажи / (продажи + отклонённые)), «Доход с конверсии» (доход / (лиды + продажи)), «Доход с 1000 кликов»; нет данных или знаменатель 0 — тире, не ноль. Деньги в таблице — `moneyText` с двумя знаками и группировкой разрядов; пустой код расхода — USD (`0.00 $`), с другой валютой — код (`0.00 EUR`). Столбец «Уники» (`uniq`) в сетях выключен по умолчанию и считает `uniq` строк сети. Доход без расхода даёт ROI `100%` только когда у кампании за период нет расхода. Неразложенный расход кампании этот процент сети не ставит. Несколько валют в один процент не склеиваются.

У оффера поле `network_id`. Закрытый каталог шаблонов сетей не скачивается и на сервер не пишется.

## Шаблоны сетей в диалоге

`GET /api/affiliate-network-templates` отдаёт шаблоны для диалога: `id`, `name`, `offer_query`, `postback_url`, `instruction`, `conversions`, `source`, `extracted`, `edited`, `custom`. Доступ — как к разделу «Сети». Вшитый каталог один: `internal/admin/net_templates.json`, ничего не вшито в страницу. В нём ровно 333 названия из списка шаблонов панели Keitaro, без собственных заготовок; повторов названий нет. Варианты `CPA`, `RevShare`, `Drop` — отдельные шаблоны.

`extracted`: `full` — известны и параметры оффера, и адрес постбека; `partial` — что-то одно; `none` — известно только название, «параметры не извлечены». У `none` выбор шаблона заполняет одно название и пишет об этом под выбором, чужие параметры не рисуются. Пустое значение не придумывается. В `postback_url` начало адреса — маркер `{origin}`, страница подставляет публичный адрес этого трекера; макросы сети (`{{visit_id}}` и подобные) остаются как есть, чужой хост, путь-токен и `from=` в каталог не попадают. `source`: `keitaro-json` — поля из выгрузки шаблонов Keitaro, `custom` — шаблон, добавленный в диалоге.

Поля `keitaro-json` взяты из выгрузки только как есть: `offer_query` — параметр оффера сети; `postback_url` собран из макросов сети `subid`, `status`, `payout`, `currency`, `tid` на наш приём `/postback`. Если у сети нет макроса `subid` (таких 48), адрес постбека пуст и параметры оффера остаются строкой для ссылки оффера; значение-список вариантов (`reg,dep,lead`) макросом не считается и в адрес не попадает. `instruction` хранится дословно (допустимы теги `p`, `br`, `code`, `a`), в диалоге выводится только для чтения: всё остальное экранируется, ссылки — только `http` и `https`. `conversions` — списки статусов сети (`lead_status`, `sale_status` и т. п.) только для чтения: трекер их не сопоставляет, движок читает `status=lead|sale|rejected`. Из выгрузки извлечены параметры оффера у всех 333 сетей, адрес постбека — у 285, инструкция — у 163, списки статусов — у 155.

### Узнавание шаблона при открытии сети

Когда открыта сохранённая сеть, а её название (без учёта регистра и пробелов по краям) совпадает с названием шаблона, шаблон выбирается в поле «Шаблон», под ним показываются инструкция и статусы. Название, параметры оффера и адрес постбека, уже стоящие в диалоге, не меняются. Если шаблона с таким названием нет, у того, кто может менять сети, он добавляется из этой открытой сети (`POST /api/affiliate-network-templates`, шаблон `custom` на томе данных): название и параметры оффера как у сети, без инструкции, если её нет. Адрес постбека попадает в шаблон только в виде собственного приёма `{origin}/postback` без `from=`; чужой хост и путь-токен отбрасываются, сервер такие адреса в шаблоне не принимает (`400`). Остальные сети не перебираются, вшитый `net_templates.json` при этом не меняется.

### Правка шаблонов

Тот, у кого есть право менять сети, дописывает шаблон из диалога: карандаш рядом с выбором открывает короткую форму (параметры оффера, постбек, инструкция), «+» добавляет шаблон с новым названием. Новый раздел меню не нужен. API только для сессии браузера: `POST /api/affiliate-network-templates` (тело `name`, `offer_query`, `postback_url`, `instruction`; `409`, если название уже есть среди каталога и добавленных), `PUT /api/affiliate-network-templates/{id}` и `DELETE /api/affiliate-network-templates/{id}`.

Правки лежат отдельно от вшитого каталога, в `net-templates.json` на томе данных админки (путь — `EMTDS_NET_TEMPLATES_FILE`), поэтому обновление образа их не стирает. Правка заменяет только сохранённые поля: пустое поле, как и поле, равное значению каталога, не хранится и следует каталогу; очистка поля снимает его правку. Название из каталога не меняется и не удаляется (`400` на другое название). `DELETE` у шаблона каталога снимает правку, у добавленного — удаляет шаблон. Битый файл правок не ломает список (отдаётся каталог), но запись поверх него отклоняется.

Выбор шаблона заполняет название, параметры оффера и адрес постбека. Поле заменяется, только пока оно пустое или всё ещё хранит значение предыдущего шаблона: то, что вписал пользователь, не затирается. Сохранённые сети каталог не меняет. Новая сеть открывается с пустыми шаблоном и параметрами оффера. Поле параметров стоит выше адреса постбека, рядом с подписью «?» — какие параметры добавлять ко всем офферам (`ваш_sub1={subid}` обязательно). Адрес постбека — текстовое поле на две строки; трекер этот адрес не вызывает.
