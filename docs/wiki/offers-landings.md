# Офферы и лендинги

Внешний адрес больше не вклеивается в поток строкой. Поток хранит ссылки `offers` и `landings`: id и доля `share`. Движок выбирает адрес по доле.

## Методы

| Метод | Путь | Вход | Выход | Ошибки |
| --- | --- | --- | --- | --- |
| GET | `/api/offers` | — | массив записей | 503, если файл не настроен |
| POST | `/api/offers` | name, url, status, local, group; id можно не передавать | созданная запись с номером | 400, 409 если id уже есть |
| GET | `/api/offers/{id}` | — | одна запись | 404 |
| PUT | `/api/offers/{id}` | те же поля | обновлённая запись | 404, повтор не создаёт вторую |
| DELETE | `/api/offers/{id}` | — | `{status: deleted}` | 404 |

Те же пути для `/api/landings`.

`local: true` у оффера оставляет запись в списке. Движок такой оффер не запрашивает. У лендинга `local: true` значит каталог файлов, его отдаёт движок.

Файл лежит рядом с группами: `offers.json`, `landings.json`. Пустой `id` на форме заполняет `offer_seq.json` или `landing_seq.json` (`KUZTDS_LANDING_SEQ_FILE`, по умолчанию рядом с группами). Счётчик только растёт. Нелокальный адрес начинается с `http://` или `https://`.

## Группы и поиск

Группа — свободная подпись на записи, поле `group` в JSON своего каталога (`offers.json`, `landings.json`, `networks.json`, `sources.json`, `domains.json`). Отдельной сущности группы и отдельного API нет: список групп — непустые подписи в своём файле. Движок поле не читает. В отчёт и сводку подпись не попадает.

Сервер обрезает пробелы по краям; подпись длиннее 64 символов обрезается до 64, а не отклоняется; пустая в файл не пишется. `PUT` заменяет запись целиком, поэтому тело без `group` снимает подпись.

Под заголовком каталога — общая полоса `catalogBar`: слева «Создать» (если есть право) и поиск, справа «Группы», фильтр группы и значок обновления. Поиск без учёта регистра по подстроке. Поля: оффер — номер, имя, группа, URL, имя сети; лендинг — номер, имя, группа, URL, входной файл; сеть — номер, имя, группа, postback_url, offer_query; источник — номер, имя, группа, значения параметров; домен — номер, хост, группа, роль.

Список групп скрыт, пока ни у одной записи нет подписи. Пункт «Без группы» появляется, когда есть и записи с подписью, и без. Если выбранная группа исчезла, фильтр становится «Все группы». Фильтры живут в памяти вкладки. При активном поиске или фильтре пустой отбор показывает «Ничего не найдено».

В форме записи поле «Группа» с подсказкой существующих имён; совпадение без учёта регистра подставляет уже записанное написание. У доменов группа выбирается списком с кнопкой плюс.

Кнопка «Группы» в правой части полосы каталога открывает окно: поле имени, поиск по именам групп, таблица групп с количеством записей. «Создать» открывает форму новой записи с подставленным именем; файл пишется только вместе с записью. «Удалить» снимает подпись с записей по одной последовательными `PUT` с полной записью; сами записи остаются. Первая ошибка останавливает цикл, страница перечитывается.

Столбец «Группа» у лендингов и сетей включён по умолчанию и сортируется как текст; у источников колонка в таблице, шестерёнки нет.

Keitaro: группа оффера и лендинга берётся из имени группы Keitaro и обрезается до 64 символов со строкой в отчёте потерь. У сетей, источников и доменов в Keitaro группы нет. Повторный перенос с пустой входящей группой оставляет подпись, заданную вручную; непустая заменяет.

Страница `#/offers` правит оффер. На одном потоке два оффера с одним адресом не сохраняются. Доли пишутся в кампанию, каталог оффера при этом не меняется.

У оффера вкладка «Редирект» первая: адрес и конструктор из `{subid}`, `{country}`, `{keyword}` и `{sub_id_1}`…`{sub_id_15}`. Вкладка «Локальный» показывает «HTML в разработке» и `local` не включает. Плюс у сети создаёт сеть поверх формы и выбирает её `id`, не закрывая оффер. Поля `countries`, `payout_model` (`cpa` или `cpc`), `payout`, `payout_currency` и `payout_param` пишутся в `offers.json`. Движок на клике их не читает. Галка «Добавить ещё» после создания открывает пустую форму. Шестерёнка столбцов помнит порядок в наборе столбцов аккаунта (`/api/me/views`).

Внизу `#/offers` закреплён тот же двухрядный блок, что у кампаний: верхний ряд — суммы отфильтрованного списка (клики, уники, конверсии, продажи, расход, доход, депозит, прибыль, ROI, EPC; проценты не складываются, депозит не входит в доход), нижний — страница, размер (10/25/50/100/1000 или своё до 5000, по умолчанию 50) и экспорт CSV/HTML всех строк фильтра, не страницы. Скрытый `profit` прячет деньги в футере. Поиск, группа и сортировка возвращают на первую страницу. Размер страницы хранится в `offers.page` у `/api/me/views`, не в `localStorage`. Лендинги этого блока не получают.

## Лендинги

Страница `#/landings`. Столбцы: №, имя, группа, тип, состояние, файлы. «Группа» включена по умолчанию. Тип в ячейке — `URL`, `PHP` или `HTML`. `URL` у лендинга с адресом. `PHP`, если точка входа кончается на `.php`, иначе `HTML`. Состояние — включён или выключен. Файлы — число файлов локального лендинга. Кнопка удаления спрашивает подтверждение с именем и номером: «Удалить лендинг «Имя» (ID N)?»; без имени — только номер.

Форма: имя, включён, режим «Адрес» или «Локальные файлы».

### Локальные файлы

Блок `#llocal-box` виден только в режиме «Локальные файлы». Загрузка архива: кнопка «Выбрать архив» (`.filepick`, поле `#lzip`, только `.zip`), рядом имя файла и размер в КБ; без выбора — «Файл не выбран». Выбор архива и «Загрузить архив» доступны после сохранения лендинга (есть id). «Загрузить архив» активна, когда id есть и файл выбран. После успешной загрузки поле архива сбрасывается.

Ниже — таблица файлов каталога (путь и размер). Клик по строке текстового файла открывает редактор. Текстовыми считаются ровно те расширения, что принимает API файлов: `.html`, `.htm`, `.php`, `.css`, `.js`, `.txt`, `.json`, `.xml`, `.svg` (список `LAND_TEXT` в SPA совпадает с `landingTextExt` на сервере). Остальные файлы — картинки, `.md`, `.yaml`, `.htaccess`, файлы без расширения — показаны в таблице, но не открываются. Поле «Точка входа» только для чтения, обновляется после загрузки архива. «Открыть» открывает `/l/{id}/` на движке в новой вкладке; нужен сохранённый лендинг.

Редактор (Ace): нумерация строк, подсветка и проверка синтаксиса для PHP, HTML, JavaScript, CSS и JSON — режим по расширению; прочие разрешённые текстовые файлы — без подсветки и без строки синтаксиса. Базовое и живое автодополнение включены. Под редактором — «Синтаксис в порядке» или «Ошибок синтаксиса: N»; ошибки сохранение не блокируют. Ctrl+S сохраняет, Escape закрывает окно; если открыт список автодополнения, Escape закрывает только его. Тема редактора (`cloud_editor` / `cloud_editor_dark`) следует светлой или тёмной теме админки. Ace подгружается при первом открытии редактора, не при входе в админку. Если скрипты Ace не загрузились — toast и обычное текстовое поле. Отсутствующий файл (404) можно править и сохранить.

`GET /api/landings/{id}/files` возвращает список файлов. `POST /api/landings/{id}/archive` принимает zip не больше 50 МиБ: multipart-поле `file` или сырое тело. Каталог лендинга заменяется. Ответ `{files, entry}`: `files` — сколько файлов записано, `entry` — точка входа. `__MACOSX`, каталоги и симлинки пропускаются. Архив шире 2000 записей отклоняется. Один общий верхний каталог снимается.

`GET` и `PUT /api/landings/{id}/files/{path...}` принимают только текстовые расширения `.html`, `.htm`, `.php`, `.css`, `.js`, `.txt`, `.json`, `.xml`, `.svg`, не больше 2 МиБ. Сверх предела — 413. `DELETE` того же пути снимает файл по безопасному относительному пути. `DELETE /api/landings/{id}` удаляет запись каталога и каталог файлов.

Файлы лежат в `KUZTDS_LANDINGS_DIR`. В compose это `/var/lib/kuztds/landings` у admin и engine.

Тип выхода потока `landing` — «своя страница, затем оффер». Доли лендингов — `landings` из `{id, share}`. Офферы шага `/offer` лежат в `offers`. На клике движок отдаёт точку входа. Файл `.html` читается с диска. Тело со статусом 2xx, и у HTML, и у PHP, раскрывает макросы и получает `<base href="/l/{id}/">`. Файл `.php` проксируется в контейнер `php` (`php:8.3-apache`, `KUZTDS_PHP_URL=http://php:80`). Том состояния у php только на чтение, DocumentRoot `/var/lib/kuztds/landings`, листинг выключен. В запрос уходят `X-Forwarded-For` и `X-Kuztds-Cid`. Таймаут 10 с, тело до 8 МиБ. Статус вне 2xx и заголовок `Location` передаются посетителю как есть, макросы в таком ответе не раскрываются. Пустой `KUZTDS_PHP_URL` даёт 503.

Статика лендинга — `/l/{id}/{path}`, кеш 5 минут (`Cache-Control: public, max-age=300`). `.php` и файл без расширения проксируются в php. Скрытое имя, каталог и выход за каталог лендинга — 404. `/l/{id}/` без файла — 404.

Макрос `{offer}` в лендинге становится `/{alias}/offer?cid=…`. Шаг offer повторно использует cid клика, если это 12 знаков `0-9a-z` с верной подписью или старые десять строчных hex. Иной cid заменяется новым (формат — в [макросах и источниках](macros-sources.md)).

## Домены

Страница `#/domains`. `GET|POST /api/domains` и `GET|PUT|DELETE /api/domains/{id}`. Список — массив; у каждой записи кроме полей файла есть `campaigns` — число кампаний с этим `domain_id` в `groups.json`, а для доменов админки — вычисленный `admin_host` и статус DNS/проверки (`admin_dns`, `admin_ok`, `admin_reason`). Счётчик кампаний считается на лету, в `domains.json` не пишется. Список доменов не закрывает приём кликов: движок Host по нему не фильтрует. Подключение Cloudflare, запись `admin.<домен>` и проверка направления — [namecheap](namecheap.md); поля API — [admin-api](admin-api.md). Новые домены по умолчанию получают роль «Ссылки кампаний».

Столбцы: флажок выбора, №, хост, группа, роль, кампании, статус, проверен (выключен по умолчанию). Шестерёнка слева от «Групп» прячет и переставляет столбцы, набор помнится в `kuztds-dom-cols`; № и хост не отключаются. Перед хостом стоит точка проверки: серая — не проверялся, зелёная — ОК, красная — сбой; подсказка точки — полная фраза. В колонке «Статус» та же фраза без точки. Роль показывается словами: «Админка», «Ссылки кампаний», «Админка и ссылки». Кнопка «⋯» сразу после хоста открывает «Править домен», «Проверить», «Выключить» или «Включить» и «Удалить». Правка — одно окно с хостом, группой, ролью, «Основной для ссылок» и «Выключен»; сохранение идёт `PUT /api/domains/{id}`. Внизу — пагинация как у кампаний: страницы по 10, 25, 50 (по умолчанию), 100 или 1000 строк, размер помнится в `kuztds-domains-page`, надпись «1–50 из N». Поиск и фильтр группы возвращают на первую страницу.

Флажок в шапке отмечает весь отфильтрованный список, не только видимую страницу; строки, выпавшие из поиска или фильтра группы, из выбора снимаются. Над таблицей появляется полоса: «Включить», «Выключить», «Проверить», «Группа», «Удалить». Удаление и проверка нескольких спрашивают один раз. Проверки идут по `POST /api/domains/{id}/check` не больше четырёх одновременно, в конце одно уведомление «Проверено: N, ОК: M». Включение, выключение, группа и удаление идут по одному запросу за раз через `PUT` и `DELETE`; на первой ошибке цикл останавливается и показывает её текст. Отдельного адреса для массовых действий нет.

Поле `disabled` в `domains.json` — пометка каталога. Выключенный домен не предлагается в списке доменов новой ссылки кампании и не берётся запасным адресом; у кампании, где он уже выбран, адрес остаётся этим хостом, в списке он виден с пометкой «Выключен». Выключенный домен не бывает основным: сервер снимает «Основной» при сохранении. Движок поле не читает и клики на этот хост принимает. Старые записи без поля включены.

На `PUT` сервер не берёт из тела `ok`, `reason` и `checked`: при том же хосте они остаются прежними, при другом хосте сбрасываются. `POST` эти поля тоже не принимает. Запись `domains.json` на создание, замену, удаление и проверку идёт под одним мьютексом, сетевая часть проверки — вне его. Если во время проверки хост записи сменили, результат не пишется, ответ `409 host changed`. Повторный перенос Keitaro оставляет у домена `disabled`, `ok`, `reason` и `checked`.

Проверка — `POST /api/domains/{id}/check`. Админка сначала резолвит хост (порт, если есть, отбрасывается только для DNS), затем делает `GET https://{host}/healthz?probe=<16 hex>` с заголовком `Host`, таймаутом 5 с и без редиректов. Только HTTPS, без HTTP. Соединение с непубличным адресом (loopback, локальные сети, link-local, CGNAT 100.64.0.0/10, 198.18.0.0/15) блокируется на уровне сокета, поэтому подмена DNS после резолва не помогает. Движок на `/healthz` отвечает телом `ok` и заголовками `X-Kuztds-Host` (пришедший Host) и `X-Kuztds-Probe` (эхо `probe`, только если это 1–64 строчных hex-знака). `ok` ставится только при статусе 200 и совпадении обоих заголовков — то есть когда по этому имени отвечает именно этот движок. Иначе в запись пишется первая неудачная причина `reason`: `dns` — имя не резолвится; `private` — все адреса непубличные; `connect` — нет соединения или TLS по HTTPS; `foreign` — сервер ответил (любой статус, включая редирект и 404), но заголовки не совпали — это не наш трекер. Вместе с `ok` и `reason` пишется `checked`; запись файла идёт под мьютексом, сетевая часть — вне его. Ответ — обновлённая запись. В таблице точка у хоста зелёная при «ОК», красная при «Не направлен · причина», серая при «не проверялся»; тот же текст стоит в колонке «Статус» и показывается уведомлением после одиночной проверки. Автоматической проверки по таймеру нет.
