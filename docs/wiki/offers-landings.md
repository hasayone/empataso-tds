# Офферы и лендинги

Внешний адрес больше не вклеивается в поток строкой. Поток хранит ссылки `offers` и `landings`: id и доля `share`. Движок выбирает адрес по доле.

## Методы

| Метод | Путь | Вход | Выход | Ошибки |
| --- | --- | --- | --- | --- |
| GET | `/api/offers` | — | массив записей | 503, если файл не настроен |
| POST | `/api/offers` | name, url, status, local, group; id можно не передавать | созданная запись с номером | 400, 409 если id уже есть |
| GET | `/api/offers/{id}` | — | одна запись | 404 |
| PUT | `/api/offers/{id}` | те же поля | обновлённая запись | 404, повтор не создаёт вторую |
| DELETE | `/api/offers/{id}` | — | `{status: deleted}` | 404 |

Те же пути для `/api/landings`.

`local: true` у оффера оставляет запись в списке. Движок такой оффер не запрашивает. У лендинга `local: true` значит каталог файлов, его отдаёт движок.

Файл лежит рядом с группами: `offers.json`, `landings.json`. Пустой `id` на форме заполняет `offer_seq.json` или `landing_seq.json` (`EMTDS_LANDING_SEQ_FILE`, по умолчанию рядом с группами). Счётчик только растёт. Нелокальный адрес начинается с `http://` или `https://`.

## Группы и поиск

Группа — свободная подпись на записи, поле `group` в JSON своего каталога (`offers.json`, `landings.json`, `networks.json`, `sources.json`, `domains.json`). Отдельной сущности группы и отдельного API нет: список групп — непустые подписи в своём файле. Движок поле не читает. В отчёт и сводку подпись не попадает.

Сервер обрезает пробелы по краям; подпись длиннее 64 символов обрезается до 64, а не отклоняется; пустая в файл не пишется. `PUT` заменяет запись целиком, поэтому тело без `group` снимает подпись.

Под заголовком каталога — общая полоса `catalogBar`: слева «Создать» (если есть право) и поиск, справа «Группы», фильтр группы и значок обновления. Поиск без учёта регистра по подстроке. Поля: оффер — номер, имя, группа, URL, имя сети; лендинг — номер, имя, группа, URL, входной файл; сеть — номер, имя, группа, postback_url, offer_query; источник — номер, имя, группа, значения параметров; домен — номер, хост, группа, роль.

На странице офферов в той же полосе перед фильтром группы стоит фильтр партнёрской сети («Все сети» по умолчанию, поиск по имени в списке). Он режет таблицу по полю `network_id` оффера на клиенте из того же ответа `GET /api/offers`, как и фильтр группы: оффер без сети при выбранной сети скрыт, «Все сети» возвращает всё. В списке только сети, которые используют офферы; он скрыт, пока сети нет ни у одного оффера. Выбранная сеть, которой не осталось, сбрасывается. Экспорт CSV и HTML берёт тот же отбор, что и таблица. На других страницах каталога фильтра сети нет, сохранение оффера он не затрагивает.

Список групп скрыт, пока ни у одной записи нет подписи. Пункт «Без группы» появляется, когда есть и записи с подписью, и без. Если выбранная группа исчезла, фильтр становится «Все группы». Фильтры живут в памяти вкладки. При активном поиске или фильтре пустой отбор показывает «Ничего не найдено».

В форме записи поле «Группа» с подсказкой существующих имён; совпадение без учёта регистра подставляет уже записанное написание. У доменов группа выбирается списком с кнопкой плюс.

Кнопка «Группы» в правой части полосы каталога открывает окно: поле имени, поиск по именам групп, таблица групп с количеством записей. «Создать» открывает форму новой записи с подставленным именем; файл пишется только вместе с записью. «Удалить» снимает подпись с записей по одной последовательными `PUT` с полной записью; сами записи остаются. Первая ошибка останавливает цикл, страница перечитывается.

Групповые действия есть у офферов и партнёрских сетей. В шапке таблицы и у каждой строки — флажок (в шапке «Выбрать все на этой странице»; Shift выбирает диапазон). Появившаяся над таблицей панель даёт «Группа» и «Удалить»; без выбора панели нет. «Группа» открывает окно с полем группы и пишет подпись выбранным по одной `PUT /api/offers/{id}` или `PUT /api/affiliate-networks/{id}` с полной записью, первая ошибка останавливает цикл. «Удалить» спрашивает подтверждение с числом и удаляет по одной `DELETE`. Флажки видны только у строк, которые роль вправе менять; чужие строки в выбор не попадают. Выбор сбрасывается при смене списка и после действия.

Столбец «Группа» у лендингов и сетей включён по умолчанию и сортируется как текст; у источников колонка в таблице, шестерёнки нет.

Keitaro: группа оффера и лендинга берётся из имени группы Keitaro и обрезается до 64 символов со строкой в отчёте потерь. У сетей, источников и доменов в Keitaro группы нет. Повторный перенос с пустой входящей группой оставляет подпись, заданную вручную; непустая заменяет.

Страница `#/offers` правит оффер. На одном потоке два оффера с одним адресом не сохраняются. Доли пишутся в кампанию, каталог оффера при этом не меняется.

Диалог оффера — вкладки «Основные», «Действие», «Настройки», «Значения» и «Заметки». На «Действии» пустой выбор оставляет редирект по URL; `404` отвечает 404, `text` и `html` отдают введённый текст как text/plain и text/html (пустое тело не сохраняется), `none` не редиректит и не подменяет страницу, неизвестное значение на клике остаётся редиректом. «Основные»: название, группа, статус (точка и слово рядом: зелёная — оффер включён, красная — выключен; клик переключает), сеть (плюс рядом создаёт сеть поверх формы и выбирает её `id`, не закрывая оффер) и адрес редиректа; кнопка рядом с адресом открывает выбор макросов с поиском (`{subid}`, `{root_subid}`, `{country}`, `{keyword}`, `{sub_id_1}`…`{sub_id_30}` и `{offer_value:имя}` для каждого именованного значения): клик дописывает `ключ={макрос}` в конец запроса, `[PAR-1]` и `#фрагмент` остаются на месте, ключ, который в запросе уже есть, не пишется второй раз. Макросы в адресе подсвечены цветом акцента, сохраняется обычный текст. «Настройки»: страны (`countries`, пустой список — любая страна) стоят первыми. Тип выплаты (`payout_model`): CPA пишет сумму в конверсию, CPC пишет её доходом клика и в конверсию не ставит. Выплата, валюта и «Параметр выплаты» в одной строке. Допродажи (`upsell`): включены — постбек с новым tid по тому же клику ещё одна продажа; выключены — повтор без нового tid продажу не добавляет. Капа «да» показывает суточный лимит, общий лимит, часовой пояс и один запасной оффер; капа «нет» прячет их. Выключенный лимит прячет своё число, само число сохраняется. Сутки дневного лимита кончаются в полночь `cap_tz`; пустой пояс остаётся сутками UTC, пока оффер не сохранят. Общий лимит — лиды и продажи за всё время, отказ не считается. Один запасной оффер (`fallback_id`) принимает клик и когда оффер остановлен, и когда исчерпан суточный или общий лимит; клик считается на нём. Пустое поле пропускает оффер, случайный не подставляется, цикл обрывается. Отдельного списка «только для стопа» нет. «Значения» — пары имя и значение для макроса `{offer_value:имя}`, «Заметки» — большое поле. Движок на клике читает `status`, оба лимита, страны и запасной оффер; `payout_model` (`cpa` или `cpc`) в диалоге не показывается и остаётся как сохранён. Галка «Добавить ещё» после создания открывает пустую форму. В списке офферов точка статуса стоит по вертикали по центру названия: клик по точке включает и выключает оффер, клик по названию открывает его и статус не меняет. Если у оффера в `countries` больше одной страны, рядом с именем есть кнопка «Страны» (`aria-expanded`, с клавиатуры). По нажатию под строкой появляются строки этих стран: то же число столбцов, те же правила подсчёта, что у строки оффера, но только клики и конверсии этой страны и этого оффера. Проценты считаются заново по строке страны и не складываются. Запрос уходит один раз при раскрытии (`GET /api/stats/facts` с `offer` и `countries`), не по всем офферам сразу. Одна страна или пустой список кнопки не дают. Ручной расход кампании по странам не делится: у сохранённого расхода нет страны, в строке страны остаётся цена клика. Шестерёнка столбцов помнит порядок в наборе столбцов аккаунта (`/api/me/views`).

Внизу `#/offers` закреплён тот же двухрядный блок, что у кампаний: верхний ряд — суммы отфильтрованного списка (клики, уники, конверсии, продажи, расход, доход, депозит, прибыль, ROI, EPC; проценты не складываются, депозит не входит в доход), нижний — страница, размер (10/25/50/100/1000 или своё до 5000, по умолчанию 50) и экспорт CSV/HTML всех строк фильтра, не страницы. Скрытый `profit` прячет деньги в футере. Поиск, группа и сортировка возвращают на первую страницу. Размер страницы хранится в `offers.page` у `/api/me/views`, не в `localStorage`. Лендинги этого блока не получают.

## Лендинги

Страница `#/landings`. Столбцы: №, имя, группа, тип, состояние, файлы. «Группа» включена по умолчанию. Тип в ячейке — `URL`, `PHP` или `HTML`. `URL` у лендинга с адресом. `PHP`, если точка входа кончается на `.php`, иначе `HTML`. Состояние — включён или выключен. Файлы — число файлов локального лендинга. Кнопка удаления спрашивает подтверждение с именем и номером: «Удалить лендинг «Имя» (ID N)?»; без имени — только номер.

Форма (`.modal.lmodal`) шириной до 720 px. Сверху закреплён заголовок: иконка, имя лендинга (меняется при вводе; у нового — «Новый лендинг»), под ним `ID N` и крестик закрытия. Снизу закреплён футер «Отмена / Сохранить». Дальше два блока:

- «Основное» — имя, группа с кнопкой создания группы и переключатель «Лендинг включён»;
- «Источник» — переключатель типа «Адрес» / «Локальные файлы»; у адреса — поле URL, у локальных файлов — блок `#llocal-box`.

До 560 px поля идут в одну колонку, переключатель типа и кнопки футера растягиваются на ширину, столбец «Изменён» скрыт. Цвета только из переменных темы, светлая и тёмная темы работают без отдельных правил.

### Локальные файлы

Зона загрузки `#ldrop` (`.filepick`): архив перетаскивают в зону или выбирают кнопкой «Выбрать архив» (поле `#lzip`, только `.zip`; файл другого типа отклоняется с подсказкой). В зоне видно имя архива и размер в Б/КБ/МБ, без выбора — «Файл не выбран», ниже — лимиты: до 50 МБ и 2000 файлов, архив заменяет все файлы. Выбор архива и «Загрузить архив» доступны после сохранения лендинга (есть id), до этого виден текст «Сохраните лендинг, чтобы загрузить файлы». Загрузка идёт через `XMLHttpRequest`, поэтому под зоной полоса прогресса и «Загрузка… N%»; когда тело ушло, полоса бежит без процента с надписью «Распаковка…». После ответа поле архива сбрасывается.

Ниже — «Файлы · N · общий размер», кнопка перечитать список и таблица `#lfiles`: иконка по типу файла (код, стили, картинка, архив, видео, звук, прочее), путь, размер в Б/КБ/МБ (точное число байт в подсказке) и «Изменён» — время из поля `modified` API в часовом поясе пользователя. Столбцы сортируются. Файл, который движок откроет, помечен «вход». Клик по строке текстового файла открывает редактор. Текстовыми считаются ровно те расширения, что принимает API файлов: `.html`, `.htm`, `.php`, `.css`, `.js`, `.txt`, `.json`, `.xml`, `.svg` (список `LAND_TEXT` в SPA совпадает с `landingTextExt` на сервере). Остальные файлы — картинки, `.md`, `.yaml`, `.htaccess`, файлы без расширения — показаны в таблице, но не открываются.

Список файлов всегда перечитывается с сервера: после загрузки архива, после сохранения файла в редакторе и по кнопке перечитать. Поэтому размер и время меняются сразу, в том числе у `log.json`, который пишет сам лендинг. Ответ `GET /api/landings/{id}/files` идёт с `Cache-Control: private, no-store` и без `ETag`, размер и время читаются с диска при каждом запросе.

«Точка входа» — список `#lentry`: «Автоматически: index.php, затем index.html» и страницы `.php`, `.html`, `.htm` из списка (сначала корневые, потом вложенные). Сохранённая точка входа, которой нет в файлах, остаётся в списке первой. Выбор сохраняется кнопкой «Сохранить»; загрузка архива заново выбирает точку входа на сервере. «Открыть» открывает `/l/{id}/` на движке в новой вкладке; нужен сохранённый лендинг.

Редактор (Ace): нумерация строк, подсветка и проверка синтаксиса для PHP, HTML, JavaScript, CSS и JSON — режим по расширению; прочие разрешённые текстовые файлы — без подсветки и без строки синтаксиса. Базовое и живое автодополнение включены. Под редактором — «Синтаксис в порядке» или «Ошибок синтаксиса: N»; ошибки сохранение не блокируют. Ctrl+S сохраняет, Escape закрывает окно; если открыт список автодополнения, Escape закрывает только его. Тема редактора (`cloud_editor` / `cloud_editor_dark`) следует светлой или тёмной теме админки. Ace подгружается при первом открытии редактора, не при входе в админку. Если скрипты Ace не загрузились — toast и обычное текстовое поле. Отсутствующий файл (404) можно править и сохранить.

`GET /api/landings/{id}/files` возвращает список файлов: `path`, `size` в байтах и `modified` — время последнего изменения в UTC с точностью до секунды. `POST /api/landings/{id}/archive` принимает zip не больше 50 МиБ: multipart-поле `file` или сырое тело. Каталог лендинга заменяется. Ответ `{files, entry}`: `files` — сколько файлов записано, `entry` — точка входа. `__MACOSX`, каталоги и симлинки пропускаются. Архив шире 2000 записей отклоняется. Один общий верхний каталог снимается.

`GET` и `PUT /api/landings/{id}/files/{path...}` принимают только текстовые расширения `.html`, `.htm`, `.php`, `.css`, `.js`, `.txt`, `.json`, `.xml`, `.svg`, не больше 2 МиБ. Сверх предела — 413. `DELETE` того же пути снимает файл по безопасному относительному пути. `DELETE /api/landings/{id}` удаляет запись каталога и каталог файлов.

Файлы лежат в `EMTDS_LANDINGS_DIR`. В compose это `/var/lib/emtds/landings` у admin и engine.

Тип выхода потока `landing` — «своя страница, затем оффер». Доли лендингов — `landings` из `{id, share}`. Офферы шага `/offer` лежат в `offers`. На клике движок отдаёт точку входа. Файл `.html` читается с диска. Тело со статусом 2xx, и у HTML, и у PHP, раскрывает макросы и получает `<base href="/l/{id}/">`. Файл `.php` уходит в контейнер `php` (`php:8.3-apache`, `EMTDS_PHP_URL=http://php:80`), только если он есть в каталоге лендинга; иначе 404 движка, без запроса в php. В compose php монтирует только подкаталог `landings` тома `emtds_state` (`volume.subpath`) в `/var/lib/emtds/landings` на чтение и ждёт здоровый engine. Каталоги `groups.json`, ключи и метрики php не видит. Команда контейнера выставляет `ServerTokens Prod` и `ServerSignature Off`, DocumentRoot — каталог лендингов, листинг выключен. Пока контейнер php не пересоздан, у него остаётся прежний том. В запрос уходят `X-Forwarded-For` и `X-Emtds-Cid`. Таймаут 10 с, тело до 8 МиБ. Статус вне 2xx передаётся посетителю, макросы в таком ответе не раскрываются. `Location` с хостом сайдкара (хост из `EMTDS_PHP_URL`, с портом и без) и путь `/<id>/…` без хоста переписываются в `/l/<id>/…`. Внешний `Location` не меняется. Пустой `EMTDS_PHP_URL` даёт 503.

Статика лендинга — `/l/{id}/{path}`, кеш 5 минут (`Cache-Control: public, max-age=300`). Отдаются только расширения `html`, `htm`, `css`, `js`, `mjs`, `map`, `json`, `png`, `jpg`, `jpeg`, `gif`, `webp`, `avif`, `svg`, `ico`, `bmp`, `woff`, `woff2`, `ttf`, `otf`, `eot`, `mp4`, `webm`, `ogg`, `mp3`, `wav`, `pdf`, `webmanifest`. Другое расширение, в том числе `txt`, `csv`, `xml`, `yml`, `conf`, — 404. Имя без расширения: если в каталоге есть `<путь>/index.php`, ответ `301` на `/l/<id>/<путь>/index.php` (query сохраняется); иначе 404. Сырой файл без расширения не отдаётся. Точка входа в каталоге — только `.html`, `.htm` или `.php`, иначе сохранение лендинга отвечает `400`. Скрытое имя, каталог и выход за каталог лендинга — 404. `/l/{id}/` без файла — 404.

### Безопасность файлов лендинга

PHP-лендинги держат рядом с `index.php` служебные файлы: журнал ошибок `log.json`, настройки с токенами (`groups.json`, `s2s.json`). Движок не отдаёт их по `/l/{id}/…`. Список запретов — `cmd/engine/landing_deny.go`, проверяется каждый сегмент пути без учёта регистра, до чтения с диска и до прокси в php:

- имена, начинающиеся с точки: `.env`, `.git/`, `.htaccess`, `.user.ini`;
- имена `log.json`, `logs.json`, `error_log`, `groups.json`, `s2s.json`, `composer.json`, `composer.lock`, `package.json`, `package-lock.json`, `web.config` и каталоги `vendor/`, `node_modules/`, `log/`, `logs/`;
- JSON с журналом, выгрузкой или секретом: часть имени до `.json` из слов `log`, `logs`, `error`, `errors`, `lead`, `leads`, `order`, `orders`, `config`, `settings`, `users`, `customers`, `contacts`, `backup`, `dump`, `secret`, `secrets`, `credentials`, `token`, `tokens` (`error-log.json`, `leads.json`, `config.json`); `blog.json`, `ru.json`, `data.json` отдаются;
- расширения `.log`; исходники `.phps`, `.inc`, `.phtml`, `.phar`, `.php3`…`.php8`; `.sql`, `.sqlite`, `.db`; копии `.bak`, `.old`, `.orig`, `.swp`, `.swo`, `.tmp`, `.save` и имена с `~` на конце; архивы `.zip`, `.tar`, `.gz`, `.tgz`, `.rar`, `.7z`; `.env`, `.ini`, `.pem`, `.key`, `.lock`, `.sh`.

Ответ на запрещённое имя — тот же 404, что и на отсутствующий файл, поэтому существование файла не раскрывается. `.php` только исполняется в php и никогда не отдаётся текстом. Выход за каталог лендинга (`..`, `%2e%2e`, двойное кодирование `%252e`, обратный слэш `%5c`, нулевой байт) — 404 или редирект роутера на очищенный путь, без чтения файла. nginx (`deploy/nginx`) файлы лендингов сам не отдаёт: все запросы идут в движок, контейнер `php` наружу не опубликован. Файлы лендинга целиком, включая журналы, видны только в админке через `/api/landings/{id}/files` по праву на лендинг.

Макрос `{offer}` в лендинге становится `/{alias}/offer?cid=…`. Шаг offer повторно использует cid клика, если это 12 знаков `0-9a-z` с верной подписью или старые десять строчных hex. Иной cid заменяется новым (формат — в [макросах и источниках](macros-sources.md)).

### Внешние запросы в PHP-лендинге

Код лендингов — контент пользователя, EmTDS его не переписывает. Но синхронный внешний запрос в лендинге (например `curl` во внешний сервис учёта с тайм-аутами 5 + 8 с) держит посетителя и обработчик PHP на каждом показе: замер — 230–330 мс на клик вместо ~1 мс. Engine ждёт PHP до 10 с, у `php` Apache prefork (по умолчанию 150 обработчиков) и `mem_limit 512m`, поэтому под пиком такие лендинги первыми исчерпают обработчики.

Что делать в коде лендинга:
- тайм-аут внешнего запроса не больше 1 с (`CURLOPT_TIMEOUT_MS`, `CURLOPT_CONNECTTIMEOUT_MS`);
- или отправка после ответа посетителю: `fastcgi_finish_request()` (PHP-FPM) либо отдельная очередь.

Нагрузочные замеры (`deploy/loadtest`) такие кампании исключают, чтобы тестовые клики не уходили наружу.

## Домены

Страница `#/domains`. `GET|POST /api/domains` и `GET|PUT|DELETE /api/domains/{id}`. Список — массив; у каждой записи кроме полей файла есть `campaigns` — число кампаний с этим `domain_id` в `groups.json`, а для доменов админки — вычисленный `admin_host` и статус DNS/проверки (`admin_dns`, `admin_ok`, `admin_reason`). Счётчик кампаний считается на лету, в `domains.json` не пишется. Список доменов не закрывает приём кликов: движок Host по нему не фильтрует. Подключение Cloudflare, запись `admin.<домен>` и проверка направления — [namecheap](namecheap.md); поля API — [admin-api](admin-api.md). Новые домены по умолчанию получают роль «Ссылки кампаний».

Столбцы: флажок выбора, №, хост, группа, роль, кампании, статус, проверен (выключен по умолчанию). Шестерёнка слева от «Групп» прячет и переставляет столбцы, набор помнится в `emtds-dom-cols`; № и хост не отключаются. Перед хостом стоит точка проверки: серая — не проверялся, зелёная — ОК, красная — сбой; подсказка точки — полная фраза. В колонке «Статус» та же фраза без точки. Роль показывается словами: «Админка», «Ссылки кампаний», «Админка и ссылки». Кнопка «⋯» сразу после хоста открывает «Править домен», «Проверить», «Выключить» или «Включить» и «Удалить». Правка — одно окно с хостом, группой, ролью, «Основной для ссылок» и «Выключен»; сохранение идёт `PUT /api/domains/{id}`. Внизу — пагинация как у кампаний: страницы по 10, 25, 50 (по умолчанию), 100 или 1000 строк, размер помнится в `emtds-domains-page`, надпись «1–50 из N». Поиск и фильтр группы возвращают на первую страницу.

Флажок в шапке отмечает весь отфильтрованный список, не только видимую страницу; строки, выпавшие из поиска или фильтра группы, из выбора снимаются. Над таблицей появляется полоса: «Включить», «Выключить», «Проверить», «Группа», «Удалить». Удаление и проверка нескольких спрашивают один раз. Проверки идут по `POST /api/domains/{id}/check` не больше четырёх одновременно, в конце одно уведомление «Проверено: N, ОК: M». Кнопка «Проверить живые» на панели страницы проверяет все включённые домены тем же запросом и тем же пределом в четыре. Выключенные и ожидающие оплаты не берутся. Отдельного планировщика нет. Включение, выключение, группа и удаление идут по одному запросу за раз через `PUT` и `DELETE`; на первой ошибке цикл останавливается и показывает её текст. Отдельного адреса для массовых действий нет.

Поле `disabled` в `domains.json` — пометка каталога. Выключенный домен не предлагается в списке доменов новой ссылки кампании и не берётся запасным адресом; у кампании, где он уже выбран, адрес остаётся этим хостом, в списке он виден с пометкой «Выключен». Выключенный домен не бывает основным: сервер снимает «Основной» при сохранении. Движок поле не читает и клики на этот хост принимает. Старые записи без поля включены.

На `PUT` сервер не берёт из тела `ok`, `reason` и `checked`: при том же хосте они остаются прежними, при другом хосте сбрасываются. `POST` эти поля тоже не принимает. Запись `domains.json` на создание, замену, удаление и проверку идёт под одним мьютексом, сетевая часть проверки — вне его. Если во время проверки хост записи сменили, результат не пишется, ответ `409 host changed`. Повторный перенос Keitaro оставляет у домена `disabled`, `ok`, `reason` и `checked`.

Проверка — `POST /api/domains/{id}/check`. Админка сначала резолвит хост (порт, если есть, отбрасывается только для DNS), затем делает `GET https://{host}/healthz?probe=<16 hex>` с заголовком `Host`, таймаутом 5 с и без редиректов. Только HTTPS, без HTTP. Соединение с непубличным адресом (loopback, локальные сети, link-local, CGNAT 100.64.0.0/10, 198.18.0.0/15) блокируется на уровне сокета, поэтому подмена DNS после резолва не помогает. Движок на `/healthz` отвечает телом `ok` и заголовками `X-Emtds-Host` (пришедший Host) и `X-Emtds-Probe` (эхо `probe`, только если это 1–64 строчных hex-знака). `ok` ставится только при статусе 200 и совпадении обоих заголовков — то есть когда по этому имени отвечает именно этот движок. Иначе в запись пишется первая неудачная причина `reason`: `dns` — имя не резолвится; `private` — все адреса непубличные; `connect` — нет соединения или TLS по HTTPS; `foreign` — сервер ответил (любой статус, включая редирект и 404), но заголовки не совпали — это не наш трекер. Вместе с `ok` и `reason` пишется `checked`; запись файла идёт под мьютексом, сетевая часть — вне его. Ответ — обновлённая запись. В таблице точка у хоста зелёная при «ОК», красная при «Не направлен · причина», серая при «не проверялся»; тот же текст стоит в колонке «Статус» и показывается уведомлением после одиночной проверки. Автоматической проверки по таймеру нет.
