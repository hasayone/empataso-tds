# AI-ассистент

Бета. Панель-чат в админке: ассистент читает данные трекера, отвечает на вопросы по текущей странице и предлагает правки карточками. Сам он ничего не меняет: запись происходит только после нажатия «Применить». Кнопка «AI» с меткой «БЕТА» стоит справа внизу; подпись и метка выровнены по центру кнопки. В бете ассистент доступен только администраторам; раздел `assistant` в коде заложен, но обычным пользователям и ролям доступа не даёт ([роли](roles.md#ai-ассистент)).

Маршруты `/api/ai/*` — только кука администратора, `Api-Key` получает `403`; в MCP они не видны ([MCP](mcp.md#ai-ассистент), [Admin API](admin-api.md#ai-ассистент-apiai)).

## Подключение

«Интеграции» → «+ Подключить» → «AI». Провайдеры: Anthropic (Messages API), OpenAI, OpenRouter и Gemini (через OpenAI-совместимый формат). Ключ вводит администратор; сервер хранит его в `ai.json` и никогда не отдаёт обратно: в настройках видна только маска `••••abcd`. Если в поле осталась маска или пустая строка, прежний ключ сохраняется; удалить ключ можно только явным действием (`clear_keys`).

Карточка разбита на вкладки: «Подключение», «Модели», «Цены», «Лимиты», «Права», «Расход». Открытая вкладка запоминается в `localStorage` (`emtds-ai-tab`). Кнопка «Сохранить» общая для всех вкладок, «Расход» включён: на ней сохраняются бюджеты. Если сервер отказал в сохранении, открывается вкладка с полем, о котором он говорит; ошибка ключа показывается в «Подключении».

1. Выберите провайдера, вставьте ключ, нажмите «Проверить ключ». Сервер спрашивает у провайдера список моделей и обновляет кэш каталога (час, файл `assistant/models-<провайдер>.json`). Проверка ничего не сохраняет. Без нового ключа в поле проверяется сохранённый.
   - Ключ обрезается от пробелов и переводов строк. Ключ с чужим префиксом (`sk-ant-` — Anthropic, `sk-or-` — OpenRouter, `AIza` — Gemini) отклоняется как `400 ai_bad_request` с `params.reason = wrong_provider`.
   - Заголовки: Anthropic — `x-api-key` и `anthropic-version`; OpenAI, OpenRouter (`https://openrouter.ai/api/v1`) и Gemini (`generativelanguage.googleapis.com/v1beta/openai/`) — `Authorization: Bearer`.
   - Отказ провайдера — `ai_bad_key` с текстом вида `the provider rejected the API key (HTTP 401, invalid_api_key)`. В лог admin пишется строка `ai key test failed` с провайдером, кодом и этим текстом, при успехе — `ai key test passed` с числом моделей. Сообщение провайдера в лог не попадает, потому что может цитировать часть ключа.
2. Отметьте разрешённые модели и модель по умолчанию. Модель по умолчанию должна входить в разрешённые; модель без поддержки инструментов отклоняется (`ai_bad_model`). У OpenRouter каталог берётся из его списка моделей с ценами и признаком поддержки инструментов, у остальных — id моделей и цены из встроенной таблицы.
3. Включите ассистента и сохраните. Пока он выключен, остальные маршруты `/api/ai/*` (кроме настроек, проверки ключа и статуса) отвечают `503 ai_disabled`.

Настройки лежат в разделе `integrations`, то есть доступны только администратору.

## Лимиты и расход

Лимиты считаются в токенах и в долларах США, по UTC-суткам, для всей панели и для каждого пользователя отдельно.

| Лимит | По умолчанию |
| --- | --- |
| Токенов в сутки на всех | 2 000 000 |
| Токенов в сутки на пользователя | 300 000 |
| USD в сутки на всех | 5 |
| USD в сутки на пользователя | 2 |

- `0` означает «без лимита» и действует только если администратор ввёл его сам. Поле, которого нет в `ai.json`, читается как значение по умолчанию.
- Есть жёсткие потолки лимитов хода (`max_output_tokens`, `max_steps`, `turn_input_tokens`): их отдают `limit_ceilings` и `limit_max`, превышение — `400 ai_bad_limit` с `params.field`, `min`, `max`.
- Цена задаётся за 1 млн входных и 1 млн выходных токенов. Поля заполнены встроенной таблицей известных моделей (Claude, GPT, o-серия, Gemini и др.), для OpenRouter — ценой из каталога; администратор может поправить любую цену, его значение главнее. Порядок: правка администратора, затем цена каталога, затем таблица.
- Цена неизвестна и не задана: USD-лимит для этой модели не считается, а в настройках и в панели показывается предупреждение (`price_unknown`). Токенный лимит при этом действует.
- До вызова провайдера сервер резервирует `turn_input_tokens + max_output_tokens` и их стоимость, чтобы параллельные ходы не проскочили лимит. После вызова резерв снимается, а в расход идут только токены из `usage` ответа провайдера. Превышение любого лимита — `429 ai_quota`; во время хода это событие `error` с тем же кодом.
- Отказ провайдера (неверный ключ, `401`/`403`), сетевая ошибка, таймаут, остановка хода и ответ без `usage` стоят 0. Ответ без `usage` пишет в лог `ai provider reply has no usage`: его токены в лимиты не попадают.
- При неизвестной цене в расход идут токены, а сумма в USD для этой модели не считается: в панели видно «цена неизвестна», выдуманной суммы нет.
- Расход за сегодня виден в настройках (общий и по пользователям) и в панели чата (свои числа и лимиты).
- **Бюджет в USD.** Во вкладке «Расход» справа от суммы каждого пользователя стоит поле «Бюджет, USD»: пустое поле — без бюджета, отрицательное число не принимается, `0` тоже снимает бюджет. Бюджет — только деньги за те же UTC-сутки, что «сегодня» (цена токенов, уже посчитанная по цене модели); длина чата и число токенов в нём не участвуют, токенные лимиты отдельные и не затронуты. В списке есть и пользователи без расхода, и администратор из окружения.
- **Группы.** Отдельной сущности «группа пользователей» в системе нет: ближайшее настоящее объединение — роль из `roles.json` (`User.RoleID`). Блок «Группы» под списком пользователей показывается только если в `roles.json` есть хотя бы одна роль; администратор роли не имеет (его тип `ADMIN`), поэтому бюджета для «группы администратора» нет, а без ролей блока нет вовсе. Бюджет роли — сумма трат всех пользователей с этой ролью.
- **Отказ хода.** Перед каждым вызовом провайдера `aiReserve` проверяет: траты за сутки плюс резерв этого вызова (плюс вызовы в полёте) не больше своего бюджета и бюджета группы пользователя. Побеждает более жёсткий. Отказ — `429 ai_quota` с `params.scope` = `user_budget` или `group_budget`; в чате показывается короткая причина на языке интерфейса. Бюджет не проверяется для модели без цены (как и остальные USD-лимиты).
- Бюджеты лежат в `ai.json` рядом с остальными настройками: `user_budget_usd` (id учётной записи → USD, у администратора из окружения `env-<логин>`) и `group_budget_usd` (id роли → USD), сохраняются тем же `PUT /api/ai/settings`, карта заменяется целиком. `GET` отдаёт те же карты, `budget_accounts` (кому можно задать бюджет) и `budget_groups` (роли с числом пользователей и расходом за сегодня; пусто — блока групп нет).
- Счётчик лежит в `assistant/usage.json` (`0600`, запись атомарная). Повреждённый файл не считается нулём: до конца UTC-суток ассистент отказывает всем вызовам (`ai_quota`), а копия файла сохраняется как `usage.json.bad`. Починка: исправить или удалить `usage.json` и перезапустить admin, либо дождаться следующих суток.

## Инструменты

Модель получает список инструментов из `routeDocs` (единый источник правды, он же OpenAPI). Чтение сервер выполняет сам, запись только сохраняет как предложение. Список фильтруется по доступу сессии: ассистент не видит инструмента, который ответил бы `403`.

| Режим | Что | Инструменты |
| --- | --- | --- |
| read | Каталоги: офферы, лендинги, партнёрские сети, источники трафика, домены, кампании | `list_*` и `get_*` соответствующего каталога, `list_campaigns` |
| read | Разделы панели | `list_boards` |
| read | Статистика | `stats_summary`, `stats_timeseries`, `stats_breakdown`, `stats_performance` |
| read | Журналы и отчёт | `list_logs`, `list_postbacks`, `list_log_values`, `list_log_fields`, `get_report` |
| read | Диагностика | `lookup_ip`, `simulate_visitor` (ничего не записывает) |
| propose | Создание, правка, удаление: офферы, лендинги, партнёрские сети, источники трафика, кампании | `create_*`, `update_*`, `delete_*`, для кампаний `create_campaign`, `update_campaign`, `delete_campaign` |

- Домены — только чтение: парковка и Cloudflare ассистенту закрыты.
- Список дополнительно режут права ассистента (см. ниже).

### Права ассистента

Вкладка «Права» в настройках. Модель та же, что у ролей пользователей: раздел и уровень.

| Пресет | Что разрешено |
| --- | --- |
| Только чтение | `list_*`, `get_*` и статистика |
| Правки без удаления (по умолчанию) | плюс `create_*` и `update_*` |
| Полный | плюс `delete_*`, то есть права пользователя |
| Свой | уровень по каждому разделу: ничего, чтение, правка, правка и удаление |

- Итоговое право — пересечение прав ассистента и прав пользователя, который ведёт чат. Ассистент никогда не может больше этого человека.
- Домены выше чтения не поднимаются ни в одном пресете.
- Запрещённые инструменты модели не предлагаются. Если модель всё же вызвала такой инструмент, в журнал шагов идёт событие `tool` с кодом `ai_forbidden`, и модели сообщается отказ. «Применить» для правки, которую права уже не разрешают, — `403 ai_forbidden` с `params.resource` и `params.op`.
- Откат правами ассистента не ограничен: это право человека.
- В `ai.json` права лежат в поле `perms`: `{"preset":"read|edit|full|custom","resources":{...}}`; `resources` учитываются только для `custom`.
- Списки каталогов (`offers`, `landings`, `affiliate_networks`, `traffic_sources`, `domains`, `campaigns`) поддерживают `q` (подстрока имени, id или хоста без учёта регистра), `ids` (до 200), `limit` (по умолчанию 20, не больше 50) и `offset`. Ответ — `{items, total, offset, limit}`, `total` считает все совпадения. Модель ищет по имени через `q`, а не перебирает весь список.
- `list_campaigns` отдаёт страницу сводок кампаний: `id` (слаг страницы `#/flows/{id}`), `num`, `name`, `status`, `aliases`, `folder`, `board_id`, `domain_id`, `source_id`, `streams_total`, `streams_active`. Потоки целиком приходят только для `ids` не длиннее 5. Так список в тысячи кампаний не упирается в размер ответа: `total` — все видимые пользователю кампании. Страница — 100 строк по умолчанию, до 200 (`limit`) и не больше 32 КиБ; строки, что не влезли, остаются следующей странице, ответ несёт `truncated`, а `next_offset` указывает, откуда читать дальше (на последней странице его нет). `q` ищет ещё и по номеру кампании. Доступ прежний: чужие кампании не видны.
- Ход не заканчивается обещанием. Если после работы с инструментами ассистент пишет «загружу ещё страницы» без вызова или ответ оборван лимитом вывода (`max_tokens`, `length`), сервер добавляет служебное сообщение «продолжай: вызови инструмент или дай итог» и делает ещё один вызов модели (не больше 3 подряд, каждый считается шагом, деньги — по тем же лимитам). Вызов инструмента, дважды закончившийся одной и той же ошибкой, в третий раз не выполняется; после трёх таких отказов ход завершается строкой «останавливаюсь» вместо цикла.
- Запрет записи ассистент говорит прямо. Если он вызывает изменение раздела, который права ассистента (пересечение с доступом пользователя) оставляют только на чтение, в ответ вставляется фраза на языке панели: раздел менять нельзя, читать можно; при наборе «без удаления» удаление — «удалять нельзя, читать и править можно». Модели в системную подсказку добавляется список разделов только для чтения. Права от этого не меняются: домены остаются чтением, удаление при «правках без удаления» запрещено.
- Остальные чтения ограничены `limit` ≤ 50; результат инструмента режется до 8 КиБ после редакции, слишком большой ответ — `result_too_large` с просьбой сузить фильтры.
- Один ход — не больше `max_steps` обращений к модели (по умолчанию и потолок 1000, время хода 15 с на шаг, всего 1000 шагов). Это крайняя защита от зацикливания, а не рабочий предел задачи; значения 6 и 30 из старых `ai.json` читаются как значение по умолчанию, значение выше 1000 в файле режется до 1000, PUT с ним — `400 ai_bad_limit`. Деньги ограничивают суточные лимиты и бюджеты, а не шаги. Ответ `ai_steps_limit` — упор в этот потолок.
- Сжатие контекста делает сам ассистент (`internal/admin/assistant_turn_compact.go`), команду `/compact` присылать не нужно. Когда разговор хода дорос до половины места под вход (`turn_input_tokens` минус системная подсказка и список инструментов), одним дополнительным вызовом модели без инструментов он сворачивается в сводку (что просили, найденные id и числа, уже сделанные правки и что осталось), и ход продолжается с той же задачей. Сводка идёт как данные, не как инструкция, секреты в ней вырезаются, длина до 6000 знаков. Вызов сводки проходит через ту же резервацию лимитов и бюджетов, что любой вызов, и шагом не считается; сжатий за ход может быть сколько угодно шагов (до 1000). В журнале шагов видна строка «Сжимаю контекст, чтобы продолжить». Пустая сводка или ошибка провайдера завершают ход обычной ошибкой.
- Всё, что вернул инструмент и что написано на странице, модель считает данными, а не инструкциями.
- Результат чтения уходит модели в формате [TOON](admin-api.md#формат-toon-для-ai), если он короче JSON, иначе компактным JSON (`aiToolText` в `internal/admin/toon.go`). TOON строится из уже отредактированного и сжатого до 8 КиБ результата, поэтому редакция, скрытые поля кампаний и лимит размера не меняются; учёт токенов тоже прежний. Списки каталогов, журналы и постбеки после выравнивания записей (`null` на месте пропущенного поля, массив простых значений — JSON-строкой в ячейке) короче на 31–53%; `groups`, `report`, `stats/performance` и одиночный вложенный объект остаются JSON, потому что их TOON не короче ([замеры](admin-api.md#формат-toon-для-ai)). Системная подсказка в одном предложении объясняет модели заголовок `name[N]{a,b}:`.

## Ссылки на записи в ответе

Системная подсказка (`aiSystemPrompt`, правило 8) учит модель писать упомянутую запись токеном `[[тип:id|Название]]`. `id` — поле `id` записи из результата инструмента, выдумывать его нельзя; без `id` модель пишет обычное имя.

| Тип | Страница |
| --- | --- |
| `campaign` | `#/flows/{id}` |
| `offer` | `#/offers/{id}` |
| `landing` | `#/landings/{id}` |
| `network` | `#/networks/{id}` |
| `source` | `#/sources/{id}` |

- Домены и отчёты своей страницы не имеют, ссылкой не становятся.
- Панель разбирает токен только в ответе ассистента (`aiRichParts`, `aiRichFill` в SPA). `id` — буквы, цифры и `_ . ~ -` до 128 знаков; название — до 200 знаков без `[`, `]`, `|` и переводов строки. Всё прочее (HTML, Markdown, чужие типы, адреса, `javascript:`, незакрытый токен) остаётся текстом: ответ собирается узлами DOM, без `innerHTML`. Переводы строк сохраняются.
- Если у сессии нет доступа к странице, название показывается без ссылки.
- Клик открывает ту же страницу, что пункт меню. На широком экране панель остаётся открытой, на узком (до 640 px) закрывается, чат сохраняется. Сообщения пользователя и старые ответы без токенов выводятся как раньше.

## Диктовка

Рядом с «Отправить» есть кнопка микрофона. Один клик начинает запись, и она идёт, пока вы сами не нажмёте стоп: на это время микрофон заменяется кнопкой «Остановить диктовку», повторный клик возвращает микрофон. Браузер сам закрывает сессию распознавания после паузы, диктовка перезапускает её до нажатия стопа. Пока идёт запись, над кнопками бегут волны голоса по громкости микрофона (при `prefers-reduced-motion` — статичные полоски). Распознавание идёт на языке интерфейса (ru-RU, en-US, uk-UA). Каждая подтверждённая фраза дописывается в конец поля через пробел, чтобы её можно было поправить; черновик виден отдельной строкой, сообщение само не отправляется. Доступ к микрофону запрашивает браузер. Ошибка показывается целиком и только если за всю сессию не пришло ни одной фразы: нет доступа к микрофону, нет сети у сервиса распознавания или речь не разобрана. Диктовка работает через браузер (Web Speech API): Chrome отправляет звук своему сервису распознавания, у EmTDS своего сервера и ключей для этого нет. Firefox без флага API не имеет, кнопка в нём не показывается.

## Правки

Предложение превращается в карточку в чате: что меняется (diff «было → стало» по полям), у новых и удаляемых записей — заголовок и связи. Ничего не записано, пока вы не нажали «Применить».

- Тело записи клиент не присылает: при применении сервер берёт сохранённое предложение. Патч содержит только изменённые поля из белого списка ресурса; `id`, `created_by`, `board_id` и `num` менять нельзя.
- Поля по ресурсам:
  - оффер: `name`, `url`, `status`, `local`, `network_id`, `group`, `countries`, `payout_model`, `payout`, `payout_currency`, `payout_param`;
  - лендинг: `name`, `url`, `status`, `local`, `entry`, `group`;
  - партнёрская сеть: `name`, `status`, `postback_url`, `offer_param`, `offer_query`, `group`;
  - источник трафика: `name`, `parameters`, `group`;
  - кампания: `name`, `status`, `aliases`, `redirect`, `header`, `out`, `geo`, `uniq_method`, `uniq_seconds`, `firewall`, `save_keys`, `save_keys_se`, `weight`, `sticky_stream`, `domain_id`, `source_id`, `folder`, `cost_param`, `cost_token`, `currency_param`, `currency_token`, `streams`.
- Запись ведёт через обычные обработчики панели от имени пользователя: те же проверки, доступ, разделы и журнал действий. Правки сущностей, перенесённых из Keitaro, допустимы как обычные.
- Применение и откат делят очередь с переносом из Keitaro: пока идёт перенос, синхронизация или очистка, — `409 keitaro_running`.
- Раздел записи фиксируется при предложении и повторно используется при применении; ассистент не выходит за разделы, доступные пользователю.

### Второе подтверждение

- Удаление: кнопка «Применить» открывает второй вопрос; клиент шлёт `{"confirm_delete":true}`. Без него — `400 ai_confirm_required`.
- Смена внешнего адреса: если поле URL получает хост, которого раньше не было, карточка помечает поле (`host_changed`) и просит подтверждение `{"confirm_host":true}`; без него — `400 ai_confirm_required`.

### Откат

- Откат в один клик работает для любой применённой правки: создание, изменение и удаление каждого ресурса. Для отката сервер хранит снимок исходной записи (со скрытыми полями, владельцем, разделом и номером).
- «Откатить все правки ответа» откатывает все применённые правки одного ответа в обратном порядке и останавливается на первом конфликте (`stopped_at`).
- «Откатить правки этого чата» в истории чатов (кнопка видна, пока в чате есть неоткаченные правки): сначала подтверждение со списком правок (сущность, действие, время), затем `POST /api/ai/chats/{id}/revert`. Правки откатываются в обратном порядке тем же механизмом, что одиночный откат; уже откаченные пропускаются. На первом конфликте откат останавливается: откаченное остаётся откаченным, ответ показывает, что откачено, на какой правке и почему остановка (`stopped_at`, `remaining`).
- Откат создания удаляет созданную запись; откат изменения возвращает прежние значения; откат удаления восстанавливает запись с тем же id. Занятый номер `Num` у восстановленной кампании выдаётся заново (в карточке `renumbered`).

### Конфликты

- `ai_stale` (409) — запись изменилась после того, как ассистент составил предложение: создайте новое.
- `ai_conflict` (409) — состояние не совпадает с ожиданием: запись уже есть или исчезла, откат нашёл правки поверх (хэш записи не тот), id или alias занят, раздел удалён, каталог файлов лендинга уже существует, связи кампании указывают на отсутствующие записи. Причина — в `params.reason`. Сервер ничего не перезаписывает молча.
- `ai_has_links` (409) — удаляемую сущность используют другие записи (кампании или офферы сети). Предложение не создаётся, карточка показывает зависимости (`params.links`); сначала уберите ссылки.

### Удаление лендинга

Удаление лендинга допустимо, только если откат вернёт его файлы. При применении файлы каталога упаковываются в `assistant/blobs/<id>.tar.gz` (`0600`). Предел — 10 МиБ несжатого содержимого и 2000 файлов; больше — сразу `409 ai_landing_too_large` с причиной (`size` или `files`). Симлинки в каталоге — отказ (причина `symlink`). Архив входит в общий потолок 256 МиБ каталога `assistant/` и удаляется вместе с записью об изменении. Нет места — `507 ai_disk_full`.

## Чего ассистент не может

- Менять код, запускать команды, писать файлы (кроме снимков файлов лендинга для отката). Файлы лендингов и архивы ему закрыты.
- Видеть и менять пользователей, роли, пароли, API-ключи, настройки безопасности, токены и ключи интеграций.
- Вызывать Cloudflare и Namecheap, менять и парковать домены. Keitaro — только запросы чтения.
- Менять в кампаниях исходящие постбэки, ключи S2S, заменяющие строки CURL и `[REMOTE]` (`postbacks`, `postback_ids`, `curl`, `b_curl`, `remote` и всё, что начинается с `s2s`); не ставит режим перенаправления `curl` (движок отправил бы данные посетителя на сервер по адресу).
- Применять правки сам: «Применить» нажимает человек.

## Редакция данных

Всё, что уходит провайдеру модели, в чат, в карточки и в журнал, проходит редакцию:

- секреты: ключи провайдеров, пароли, токены интеграций, значения из переменных окружения процесса, ключи подписи, `Bearer`, пароли и токены в адресах (в том числе в query и в пути); значение ключа провайдера не попадает ни в ответ, ни в лог, ни в историю;
- IP посетителей всегда маскируются: IPv4 до `/24` (`a.b.c.x`), IPv6 до `/48`; переключателя нет;
- адреса рефереров и посадочных в журналах теряют query и фрагмент, потому что там лежат click id и метки;
- скрытые поля кампании (см. выше) не показываются.

Модель видит замаскированное значение и может прислать его обратно в патче: сервер подставит сохранённое значение, но только если оно пришло неизменённым. Изменённое или обрезанное замаскированное значение — `400 ai_redacted_value`: правка не принимается, чтобы не записать маску поверх настоящего значения.

## Хранение

| Что | Где | Срок и предел |
| --- | --- | --- |
| Настройки и ключи провайдеров | `ai.json`, `0600` (`EMTDS_AI_FILE`) | пока не удалены |
| Каталог ассистента | `assistant/`, `0700` (`EMTDS_AI_DIR`) | потолок 256 МиБ |
| Чаты | `assistant/chats/<пользователь>` | 60 дней; не больше 200 чатов на пользователя, старейшие вытесняются |
| Предложения и изменения | `assistant/changes.json` | 90 дней вместе со снимками |
| Снимки файлов лендинга | `assistant/blobs/` | 90 дней, см. выше |
| Расход | `assistant/usage.json` | текущие UTC-сутки |
| Каталог моделей | `assistant/models-<провайдер>.json` | кэш 1 час |

- При удалении пользователя его каталог чатов удаляется. Предложения, изменения и записи журнала действий остаются.
- Удаление чата не удаляет его правки: их ещё можно откатить.
- Ошибка хода сохраняется в ответе ассистента (поле `error`), а событие `error` называет этот ответ в `message_id`. Поэтому одна ошибка — один пузырь и в живом чате, и после перезагрузки истории.
- Чат с идущим ответом удалить нельзя (`409 ai_busy`). Одновременно у пользователя идёт один ход; на процесс — ограниченное число.
- Файлы лежат на томе admin и переживают выкладку.

## Шлюз Keitaro

Применение и откат правки отказывают, пока работает перенос, синхронизация или очистка Keitaro (`409 keitaro_running`). Обратное тоже верно: перенос не стартует, пока ассистент пишет (`409 keitaro_running`). Повторите действие после окончания переноса.

## Модель угроз

Данные страниц, журналов и названий — недоверенный ввод, модель ими не управляет, а сервер ограничивает её белыми списками полей, редакцией и вторым подтверждением. Ключ провайдера для модели недоступен вообще, а запись в трекер всегда проходит через человека и обычные проверки доступа.

## Тестовый базовый адрес

`EMTDS_AI_TEST_BASE_URL` подменяет адрес провайдера для локальных проверок с имитацией ответов. В проде переменная не задаётся: с ней ключ и запросы ушли бы не к провайдеру.

## Точки расширения после v1

Сейчас не включено, но не мешает:

- Отдельный том для секретов: все пути секретов идут только через `Config` (`AIFile`, `AIDir`, `CIDKeyFile`, `SecretValues`) и одну функцию `processSecrets()`, жёстких путей в коде ассистента нет. Перенос секретов — смена значений переменных окружения и тома, не правка кода.
- Потоковый вывод: `aiProvider` — интерфейс, поэтому провайдер может позже реализовать необязательный стрим-интерфейс; SSE уже есть, тип события `text_delta` зарезервирован, а SPA игнорирует неизвестные события.
- Автоприменение безопасных правок: применение — отдельная функция `applyChange` без привязки к HTTP-запросу, а решение принимается в единственной точке `aiAutoApply` (вызывается в `aiTurn.afterProposal`); сейчас она всегда отвечает «нет».

## Проверка с реальным ключом

Только на локальной админке `http://127.0.0.1:8090`, с отдельным ключом провайдера с низким лимитом. Ключ не печатать в чат, логи и git.

1. Откройте «Интеграции» → «+ Подключить» → «AI», выберите провайдера, введите ключ. Поле после сохранения показывает только маску.
2. Нажмите «Проверить ключ»: список моделей появился. Отметьте одну-две модели, выберите модель по умолчанию, включите ассистента, сохраните.
3. Откройте страницу со списком или таблицей, примените фильтр (период, кампания) и спросите про неё («что здесь по кликам?»). Ответ должен опираться на данные страницы и соответствовать фильтру.
4. Попросите переименовать любой тестовый оффер. Должна появиться карточка diff. Нажмите «Применить» — имя изменилось в разделе «Офферы». Нажмите «Откатить» — имя вернулось.
5. Попросите создать тестовую запись (например, оффер с именем `ai-test`), примените, затем попросите удалить её: карточка запросит второе подтверждение; подтвердите. Откатите удаление — запись вернулась с тем же id. Откатите создание (или «Откатить все правки ответа») — записи нет.
6. Попросите показать токен интеграции, ключ API или пароль. Ассистент отказывает или показывает замаскированное значение; ключ провайдера нигде не виден.
7. Откройте настройки, вкладка «Расход»: расход за сегодня вырос на токены из ответа провайдера (USD — при известной цене, иначе «цена неизвестна»). Если ключ отклонён, расход не меняется, а в чате одна ошибка.
8. Права: поставьте «Только чтение», попросите переименовать оффер — ассистент отказывает (`ai_forbidden`); верните «Правки без удаления».
9. Откат чата: в истории чатов нажмите «Откатить правки этого чата», проверьте список в подтверждении и результат.
10. Проверьте лимит: поставьте малый дневной лимит токенов, задайте вопрос — ожидаем `ai_quota`; верните лимит.
11. После проверки по желанию выключите ассистента или удалите ключ (`clear_keys`), удалите тестовые чаты.

Автоматических тестов с реальным ключом нет и их не запускают: настоящие провайдеры в тестах заменены имитацией.
