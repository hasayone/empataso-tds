# Сертификаты доменов без Cloudflare

Домен, A-запись которого смотрит прямо на сервер (например, купленный в Namecheap без Cloudflare и с пустым списком NS), работает по HTTPS без Cloudflare. Админка сама заказывает ему доверенный сертификат Let's Encrypt, nginx отдаёт его по имени (SNI), и статус домена в `#/domains` становится зелёным. Cloudflare для такого домена не нужен.

Домены с Cloudflare не меняются: им сертификат не заказывается, их DNS не трогается, до сервера по-прежнему идёт режим Full с самоподписанным сертификатом.

## Какому домену заказывается

Все условия сразу:

- строка домена без Cloudflare (`cf_zone_id` пуст);
- имя — обычный домен: только строчные буквы, цифры, дефис и точки, верхняя метка начинается с буквы, не IP, без порта и звёздочки, не `admin.*` (vhost `admin.*` принимает только Cloudflare);
- домен не выключен;
- проверка уже показала жёлтый статус «Сертификат сервера не доверенный» (`reason: untrusted`), или это покупка Namecheap, которая ещё не OK;
- все адреса A и AAAA имени равны публичному IP сервера (`EMTDS_PUBLIC_IP`). Чужой адрес, адрес прокси или лишняя AAAA на другой сервер — заказа нет.

На голый IP сертификат не заказывается. Все импортированные домены разом не заказываются: домен из Keitaro получит сертификат после проверки (кнопка «Проверить» или массовая проверка), которая покажет жёлтый статус.

## Когда заказывается и продлевается

Заказ ведёт admin (`WatchCertificates`): первый проход через минуту после старта, дальше каждые две минуты. Других планировщиков нет: cron и движок сертификаты не заказывают.

- За проход — не больше одного заказа и не больше 20 DNS-запросов.
- Продление — когда до конца срока меньше 30 дней (у короткого сертификата — меньше трети срока). Выключенный домен продлевается, новый ему не заказывается.
- Отказ CA или сбой проверки: следующая попытка для этого домена через час, дальше 2, 4 … до 24 часов. Ответ CA о лимите (`Retry-After`) удлиняет паузу. Отказ при регистрации аккаунта ставит на ту же паузу все заказы. Состояние попыток лежит в `state.json` и переживает перезапуск.
- Строка удалена или перешла на Cloudflare — её сертификат удаляется с тома, и nginx перестаёт его отдавать.
- В течение часа после заказа admin каждые две минуты повторяет проверку домена (до пяти доменов за проход). Как только nginx отдаёт новый сертификат, жёлтый статус сменяется зелёным без кнопки.

Проверка владения — HTTP-01: CA приходит на `http://<домен>/.well-known/acme-challenge/<токен>`. nginx отдаёт этот путь в admin на порту 80 и на 443 (на случай, если чужой редирект уводит CA на HTTPS). Остальное на 80 уходит редиректом на HTTPS. Нужен свободный порт 80 этого сервера: если 80 занят чужим сервисом, который не отдаёт путь в admin, заказ не пройдёт и уйдёт в паузу.

## Где лежит

| Что | Где |
| --- | --- |
| Сертификат и ключ (источник правды) | том состояния, `/var/lib/emtds/tls/live/<домен>/fullchain.pem` и `privkey.pem` (ключ `0600`) |
| Ключ аккаунта ACME и состояние попыток | `/var/lib/emtds/tls/account.key`, `/var/lib/emtds/tls/state.json` (`0600`) |
| Копия для nginx на хосте | `/etc/emtds/tls/domains/<домен>/` (сертификат `0644`, ключ `0600`) |
| Vhost по имени | `/etc/nginx/conf.d/emtds-sni.conf`, общее тело — `/etc/nginx/emtds/engine-site.conf` |

Ключ не пишется в лог, в отчёт и в git. Каталог задаёт `EMTDS_TLS_DIR` (по умолчанию `tls` рядом с файлами данных admin).

## Как сертификат попадает в nginx

Таймер агента обновлений (`update.sh --timer`, раз в минуту) после своей работы зовёт `apply-edge.sh --sync-certs`:

1. Читает `tls/live` тома одноразовым контейнером `emtds:local` без сети, под пользователем `10001`, том — только на чтение. Ссылки и не обычные файлы не копируются, размер файлов ограничен.
2. Берёт пару, только если имя проходит то же правило, что выше, ключ подходит к сертификату, срок не истёк и сертификат выписан на это имя. Пара, пойманная посреди записи продления, не берётся: остаётся прежняя рабочая.
3. Совпал набор с уже установленным — ничего не пишет и nginx не перезагружает.
4. Иначе бэкап (`/etc/emtds/nginx-backup/<время>-<случайное>-certs`, хранятся пять последних), замена каталога и `emtds-sni.conf`, `nginx -t`, `systemctl reload nginx`. Провал `nginx -t` возвращает бэкап; тот же набор повторяется не раньше чем через час.

Полный `apply-edge.sh` тоже собирает `emtds-sni.conf` из уже установленных пар, поэтому выкладка их не теряет. nginx на сервере руками не правят.

## Что видят nginx и проверка

- Запрос с именем, у которого есть пара, получает её сертификат. Любое другое имя и голый IP получают прежний самоподписанный `ip.crt` (`default_server`).
- Проверка домена (`recheckDomain`) ходит на `https://<домен>/healthz`. Пока сертификата нет, статус жёлтый «Сертификат сервера не доверенный». С доверенным сертификатом и своим ответом движка с тем же Host — обычный зелёный OK. «Чужой адрес» и «не направлен» не перекрашиваются.

## Namecheap

Покупка с пустым списком NS ставит A `@` на публичный IP (см. [Namecheap](namecheap.md)). Когда DNS разошёлся и имя резолвится на сервер, домен получает сертификат тем же механизмом, Cloudflare не нужен.

## Включение

Заказ работает только на сервере: при `EMTDS_ENV=production` (его пишет `install.sh` в `/etc/emtds/server.env`) и с `EMTDS_PUBLIC_IP`. Локальный стек сертификаты не заказывает.

| Переменная | Назначение |
| --- | --- |
| `EMTDS_ACME` | `off` — выключить заказ; `on` — включить вне production |
| `EMTDS_ACME_EMAIL` | почта для уведомлений Let's Encrypt (необязательно) |
| `EMTDS_ACME_DIRECTORY` | адрес каталога ACME (по умолчанию боевой Let's Encrypt) |
| `EMTDS_TLS_DIR` | каталог сертификатов на томе |

## Тесты

`internal/admin/acme_test.go` поднимает поддельный ACME на `httptest`, без сети наружу: заказ, запись на том, ответ по SNI и зелёный статус; продление до конца срока и отсутствие петли на коротком сроке; пауза после отказа и после отказа аккаунта; выбор только прямых доменов по одному за проход; удаление при переходе на Cloudflare; выключение без публичного IP. `deploy/apply_edge_certs_test.go` проверяет `--sync-certs`: установку и reload, повтор без изменений, отказ плохих имён, чужих пар и ссылок, сохранение рабочей пары при недописанном продлении, откат при провале `nginx -t` и часовую паузу, скрипт чтения тома.
