# Постбеки

Старый пиксель: `GET /?pb=KEY&cid=&profit=&status=`. Ключ обязателен. Читаются только `cid`, `profit` и `status`. Пустой статус пишется. Чужой `subid` рядом с `cid` клик не подменяет. Параметр `tid` старый пиксель не читает. В строку уходит уже строчный `status`, отдельный сырой текст этот путь не сохраняет.

Новый путь: `GET` и `POST /postback`. Ключ не нужен.

- клик — первый непустой из `subid`, `clickid`, `cid`
- статус — первый непустой из `status`, `type`, `goal`. В столбец `status` текст уходит строчными буквами. Сырой текст до этого сохраняется в `original_status` и обрезается до 64 байт
- выплата — первое разобранное число из `payout`, `profit`, `sum`. Слагаемые не складываются
- `tid` — идентификатор сделки, пробелы по краям снимаются, длина не больше 128 байт. Пустой `tid` разбор не ломает

Ответ — JSON. Успех: `200` и `{"status":"success"}`. Ошибка: `{"status":"error","error":"..."}`. Нет subid — `400`, текст `subid is required`, исход `no_subid`. Выплата `NaN` или `Inf` — `400`, текст `invalid payout`, в журнал не пишется. Нет хранилища или сбой записи — `503`, текст `store unavailable`, исход `no_store` или `store_error`. Клик не найден — `404`, текст `click not found`, исход `click_not_found`, исходящий не ставится. Не GET и не POST — `405`, текст `method not allowed`. Повтор того же клика и статуса не ставит второй исходящий: очередь одна.

`lead` и `sale` на один клик остаются двумя строками в `conversions`, пока нет более нового отказа. Строка `rejected` их не стирает из базы. Если время отказа не старше лида и продажи того же subid, эти строки не показываются в журнале конверсий и в его выгрузке, не входят в число лидов, продаж и конверсий, и их выплата не входит в доход: сводка, отчёт и график. Строка отказа остаётся. Более поздние лид или продажа снова считаются и снова видны в журнале.

Журнал входящих и исходящих: `GET /api/postback-log`. Поля строки: время, subid, статус, выплата, исход, направление `in` или `out`. Ключ и полный query не пишутся. Исход исходящего — HTTP-код, `error` или `dropped`.

Системные предупреждения с запуска процесса: `GET /api/notices`. После рестарта список пустой. Файла журнала операционной системы нет.

Исходящие шаблоны кампании: `GET|PUT /api/campaigns/{id}/postbacks`.

Тело — массив `{url, method, statuses}`. Метод только GET или POST, адрес только `http` или `https`. Пустой список статусов срабатывает на любой статус. Очередь одна, в процессе движка. Адрес постбека сети движок не вызывает. Отдельный cron не запускается.

Общий каталог шаблонов: `GET /api/s2s` (раздел `flows`) и `PUT /api/s2s` (только администратор). Файл `s2s.json` рядом с `groups.json`, путь переопределяет `KUZTDS_S2S_FILE`. Запись — `{id, name, url, method, statuses}`. `PUT` принимает весь массив до 1 МиБ; пустой `id` сервер считает сам: `pb-` и первые 10 hex SHA-1 подписи. Подпись (`Signature`) — метод в верхнем регистре (пустой — GET), обрезанный адрес и статусы в нижнем регистре по алфавиту; одинаковые шаблоны получают один id. Повтор id — `400 duplicate id`. Удаление шаблона, который указан в `postback_ids` хоть одной кампании, — `400 template <id> is used by N campaigns`. Нет хранилища — `503`.

У кампании поле `postback_ids` — список id из каталога. После конверсии движок складывает свои `postbacks` и шаблоны каталога по `postback_ids`, дубли по подписи схлопывает (первая копия побеждает) и ставит в ту же очередь. Неизвестный id пишется в лог предупреждением и считается совпавшим, но не поставленным: метка пары subid и статуса снимается, повтор `/postback` поставит задание после появления шаблона. Движок перечитывает `s2s.json` вместе с остальными каталогами по таймеру `reloadCatalogs`.

Импорт Keitaro выносит в каталог один шаблон: подписи постбеков считаются по кампаниям, повтор внутри одной кампании даёт плюс один раз. Самая частая подпись становится общей, при равенстве берётся меньшая строка подписи; единственная подпись тоже становится общей. Если в каталоге уже есть запись с той же подписью, берётся её id. Имя — `Keitaro <хост адреса>`. У кампаний с этой подписью инлайн-копии снимаются, id добавляется в `postback_ids`. Каталог пишется до `groups.json`; без хранилища каталога кампании сохраняются с инлайн-постбеками, как раньше.
