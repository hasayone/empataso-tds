# Постбеки

Старый пиксель: `GET /?pb=KEY&cid=&profit=&status=`. Ключ обязателен. Читаются только `cid`, `profit` и `status`. Пустой статус по-прежнему пишется. Чужой `subid` рядом с `cid` клик не подменяет.

Новый путь: `GET` и `POST /postback`. Ключ не нужен.

- клик — первый непустой из `subid`, `clickid`, `cid`
- статус — первый непустой из `status`, `type`, `goal`
- выплата — первое разобранное число из `payout`, `profit`, `sum`. Слагаемые не складываются

Ответ `200`, если разбор прошёл. Нет subid — исход `no_subid`. Клик не найден — `click_not_found`, исходящий не ставится. Повтор того же клика и статуса не ставит второй исходящий: очередь одна.

`lead` и `sale` на один клик остаются двумя строками в `conversions`.

Журнал входящих и исходящих: `GET /api/postback-log`. Поля строки: время, subid, статус, выплата, исход, направление `in` или `out`. Ключ и полный query не пишутся. Исход исходящего — HTTP-код, `error` или `dropped`.

Системные предупреждения с запуска процесса: `GET /api/notices`. После рестарта список пустой. Файла журнала операционной системы нет.

Исходящие шаблоны кампании: `GET|PUT /api/campaigns/{id}/postbacks`.

Тело — массив `{url, method, statuses}`. Метод только GET или POST, адрес только `http` или `https`. Пустой список статусов срабатывает на любой статус. Очередь одна, в процессе движка. Адрес постбека сети движок не вызывает. Отдельный cron не запускается.
