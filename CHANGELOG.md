# Changelog

All notable changes to EmTDS are recorded in this file.

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and versions follow [Semantic Versioning](https://semver.org/spec/v2.0.0.html). Every noticeable change goes into `## [Unreleased]` first; the update agent shows the added lines of this file as "What's new" before an update is applied.

## [Unreleased]

### Added

- Traffic log: the campaign menu «Logs» has a third item, «Traffic log». It lists the latest clicks of the campaign (date and time, address, country, browser, stream and answer); a row opens the full path of the click: the request address with the secret query values hidden, the address headers and whether they came through a trusted proxy, every stream the router tried in order with every rule that turned the visitor away, the stream and answer chosen, the visitor data the engine knew (geo, network, device, language, referer, keyword, Sub IDs) and the time the engine spent. The list searches by any of these words and has a «Record clicks» switch per campaign (`traffic_log_off`, on by default). The engine writes the path after the answer from a bounded queue and never waits for it: when the queue is full the path is dropped and counted in `traffic_log.dropped` of the engine metrics. Paths live in Redis: the latest 500 clicks per campaign (`EMTDS_TRAFFIC_LOG_MAX`, at most 5000), an idle campaign log for 7 days (`EMTDS_TRAFFIC_LOG_TTL`), a single click path for 72 hours (`EMTDS_TRAFFIC_LOG_CLICK_TTL`). A role that hides a field does not see it in the log either. `GET`/`PUT /api/campaigns/{id}/traffic-log` and `GET /api/campaigns/{id}/traffic-log/{cid}` are in OpenAPI, Postman and `/llms.txt`.
- Visit card: a «Click path» section shows the stored path of the visit, or says it is no longer stored. «Simulate this click again» in the card and in the log opens «Test a visitor» of the campaign filled with that visitor and runs it; the simulation shows the same path and writes nothing to the statistics. `POST /api/simulate` returns it as `trace`.
- Geo: the city and country database no longer needs a click or a MaxMind key. The cron service checks for it at start and every 10 minutes whatever the `geo_db` switch says, downloads DB-IP City Lite when the file is missing or broken (the previous month when the current one is not published yet), retries a failed download with a growing pause, and refreshes the file monthly. The file is checked before it replaces the old one, and the engine and admin load it without a restart. `geo_db` without a key now fetches DB-IP City Lite too. `GET /api/health` reports `geo.city.loaded`; Tools → Geo databases shows the download state and keeps «Update now».
- Motion: the summary chart, the «Who visits» bars and the summary cards draw in when the page opens or the period changes. Keyword sparklines and the keyword trend do the same when their series is new; settings sections ease in once. Hover, the legend, a resize, Refresh and reduced motion stay on the finished frame.
- Appearance: a custom accent at the bottom of the Appearance card. The chosen colour is written to the same `emtds-accent` key and paints the same accent the admin already uses; the ready-made colours stay. On a wide screen the «Statistics» heading and its two cards sit in the empty columns of the Interface row; a narrow screen keeps Interface above Statistics.
- Board composition: the block «Partner groups» lists the group labels already stored on affiliate networks (the `group` field), with the same checkbox and search as offer and landing groups. A checked group is saved with the rest of the composition and stays on the section. Network names stay in the search under that block.
- Conversion alerts: each new conversion still uses the card template, and `[PROFIT]` is that conversion's payout. The once-a-day message is a short report of the period sum and the campaigns, streams, countries, devices and keywords that make it up, in the language of the recipient's profile (`ru`, `en` or `uk`). It is not the line "Profit for today".
- Conversion alerts: the period time zone is chosen from the same searchable list as the profile timezone, not typed in. The saved value is still `conversions.timezone`.
- Networks export: when the search finds one affiliate network, the menu also offers CSV and HTML of that network's offers, in the same offers export. The offer address and the network postback are not in the file. Without that one network the menu stays Export CSV and Export HTML.
- Offer dialog: the status on «Main» is one switch, the same flag as before. The full word sits on its left («Enabled» or «Disabled», «Включено» or «Отключено») and follows the switch. A click only changes the flag; the offer is saved with the dialog. The short «Main» tab stays a little shorter than it was.
- Offer settings: the daily conversion limit and the total conversion limit sit in one row, each half of the width. The time zone stays on the next full-width line. The switches, the number and saving are unchanged.
- Conversion alerts: the profit summary is either the existing interval («Summary every») or once a day at a chosen hour and minute in the period time zone. One mode runs at a time; the other stays visible. New conversions are still separate messages on the same job and the same interval, not a second cron. «Run now» sends the summary once and does not change the mode.
- Offer action (`action`, `action_body` on the «Action» tab): empty keeps the URL redirect. `404` answers 404, `text` and `html` return the typed body as text/plain and text/html (an empty body is refused), `none` does not redirect and does not replace the page. An unknown action stays a URL redirect. Sending the click to another campaign is not an offer action.
- Stream URL: a macro in square brackets such as `[SUBID]` or `[PAR-1]` in the address field of a stream is shown in the accent colour, the same way as a macro in braces of an offer URL. The saved value stays plain text.
- Alternative offer: the «Settings» tab of an offer has one «Alternative offer» (`fallback_id`, `GET`/`PUT /api/offers`). A stopped offer and an offer whose daily or total limit is used up send the click there, and the click is counted on that offer. The chain is followed with loop protection; an alternative that is also stopped, full or from another country is passed over. With nowhere to go, the offer is skipped and, when no offer is left, the campaign default action fires. An empty field skips the offer; a random offer is never put in its place. A copy of a board keeps the alternatives between the copied offers.
- Campaign streams: a stream that still gives a share to a disabled offer is red: the dot before the offer, the offer badge and the stream card ("the stream still takes traffic to a broken offer"). A reached limit is not marked, since the panel does not read the counters for it.
- AI assistant: the dialog belongs to the user, not to the page. A reload or a new tab opens the latest chat with its messages. A turn already running on the server is no longer cut by a closed or reloaded page: it goes on and stores its reply, and the page joins it again (`GET /api/ai/chats/{id}/stream` replays the steps and the reply so far and follows it live). Only the «Stop» button stops a turn (`POST /api/ai/chats/{id}/cancel`); the quotas, the step limit and the budget are unchanged.
- Offer countries (`countries`, `GET`/`PUT /api/offers`) are chosen on the «Settings» tab with the country picker of the campaign conditions: several chips, search by name or code, a cross removes one. An empty list means every country. With countries, the rotation does not pick the offer for a click from another country (the click country is the one the engine already resolves for the stream rules, the CDN header included); a click of unknown country reaches only an offer whose list has `unknown`. Existing offers that came with countries (the Keitaro import) now follow them.
- Offer status is a dot, green for an enabled offer and red for a disabled one, in the dialog (instead of the «Enabled» pill) and before the name in the list, centred on the name. A click on the dot switches the offer; a click on the name opens it and leaves the status. The row menu «···» has «Turn on» / «Turn off» and the group bar of ticked offers has «Turn on» and «Turn off»; both write `status` of the offer, the field the router already reads, and the group action touches only ticked offers that do not have the status yet. Same rights as editing an offer.
- Offer dialog: the «Create» plus next to the network select is as tall as the select.
- Offer dialog is four tabs in the theme of the panel: «Main» (name, group, on/off, network, redirect URL), «Settings», «Values» and «Notes». Settings starts with countries, then the payout type (CPA or CPC), the payout row (amount, currency as wide as its code, «Payout parameter»), upsells, and a conversion cap. Cap «yes» shows the daily limit, the total limit, the time zone and one alternative offer; cap «no» hides them. Labels sit in one column, fields are one height, radios sit in a row, light and dark theme, ru/en/uk. The «Local» tab with the «HTML in development» stub and the wall of macro chips are gone; a button next to the URL opens a picker with search (the click macros `{subid}`, `{root_subid}`, `{country}`, `{keyword}`, `{sub_id_1}`…`{sub_id_30}` and one `{offer_value:name}` for each named value). A click writes `key={macro}` at the end of the query: `?` when the address has none, `&` otherwise, the typed text, `[PAR-1]` and a `#fragment` kept, and a key the query already has is not written again. A macro already in the address, as `key={macro}` or alone, is marked in the accent colour. The macros in braces of the URL field are drawn in the accent colour too; the saved value is plain text.
- Offer values: name/value pairs (alues, GET/PUT /api/offers). The engine puts the value, URL-encoded, into {offer_value:name} of the offer URL; a name is unique, has no braces, brackets or control characters, an empty name is not saved, and an unknown name stays as written.
- Offer notes: a free 
otes field (up to 10000 characters) saved with the offer; the engine ignores it.
- Payout type of an offer (`payout_model`, `cpa` or `cpc`). CPA writes the amount on the conversion, as the payout parameter already did. CPC writes that amount as the revenue of the click and does not also put it on the conversion. The offers, networks and campaigns add that click revenue into revenue.
- Upsells of an offer (`upsell`). On: a postback with a new tid on the same click is another sale. Off: repeating the click without a new tid does not add a sale.
- Daily conversion limit of an offer (`conv_cap`, `conv_cap_limit`, `cap_tz`). The day ends at midnight in `cap_tz`; an empty zone stays on the UTC day, so a counter written before a zone was saved is not split. When the leads and sales of that day already equal N, a click goes to the alternative offer (`fallback_id`) until the next day, or the offer is skipped when it is empty. Rejected conversions are not counted. Turning the limit off keeps the number. A saved daily limit is not cleared by saving the total limit. A counter error never stops traffic.
- Total conversion limit of an offer (`conv_total`, `conv_total_limit`). It counts the leads and sales of the offer over all time; a rejection is not counted. Once the number is reached, a click goes to the same alternative offer, or the offer is skipped when it is empty. A loop of such offers ends. Turning the limit off keeps the number. The daily counter stays.
- Offers list: the actions column «More» (Edit, Turn on/off, Delete with confirmation) after the name, like campaigns and networks; the trash-button column is gone. DepSum stays in the column picker.
- Groups window (campaigns, offers, landings, networks, sources, domains): a pencil next to a group name renames the group in place (Enter saves, Escape cancels). The new label is written to every record of the group with the same sequential PUT as «Delete» (campaigns: the older field), so it shows in the list, in the group filter and on the records at once; there is no second field. An empty name is not saved, and a name another group already has (any letter case) is refused with a message in ru/en/uk instead of merging the groups.
- Network dialog, «Postback URL»: a macro in braces such as `{sub1}`, `{status}`, `{payout}` or `{{income}}` is shown in the accent colour of the theme, plain text of the address is not coloured. The field stays an ordinary textarea (typing, selection, caret, scrolling, two rows and resizing); a coloured copy of its text lies under it, so the saved value is the plain address. A question mark after the label opens a popup in the style of «Offer parameters» with the parameters the engine reads: `subid`, `status`, `payout`, `depsum`, `tid`, `key`, each with its other accepted names (`clickid`/`cid`, `type`/`goal`, `profit`/`sum`, `DepSum`), in ru/en/uk. The note that the tracker does not call this address stays.

- «Data sync» (`keitaro_sync`) now refreshes campaigns already moved from Keitaro, after the new-campaign step and before the click and conversion catch-up (which are unchanged). A campaign is matched by the stored Keitaro id (the Keitaro stream ids in the stream notes and the campaign number), never by the slug, so a renamed campaign is found and the manifest slug is healed. It takes the name, the campaign note, weight, domain and source (only when Keitaro sends them), and per stream the weight, filters, action and links; a new Keitaro stream is added after the previous one, and a campaign or stream switched off in Keitaro is switched off here (never switched on). Uniqueness («Unique by» / IP only), postbacks, folder, aliases, header, default answer, owner and stream names are not touched; a campaign that is not from Keitaro is not touched; a campaign deleted in Keitaro is kept and counted («not in Keitaro N»). Reads only; at most 50 campaigns and the shared 300 GET budget per pass (the rest goes round-robin to the next pass, `update_cursor`); 402/429 or a tracker error pauses only this step for an hour. One save per pass reloads the engine through `POST /internal/reload`, and sync passes never overlap. The card says that moved campaigns are refreshed too and shows «updated N» and «not in Keitaro N» in ru/en/uk.
- Campaign note. A campaign has a free `notes` field (up to 10000 characters, `GET`/`PUT /api/groups`); the Keitaro import and the sync fill it from the Keitaro campaign note. An empty note in Keitaro never erases a local one, and a full re-import keeps the local text too. The engine ignores the field.
- «Parameters» tab in the campaign settings. The long list «Our name / Name in the link / Token» left the first tab and is the second one: the fixed source fields, then `cost` and `currency`, then a single divider and the Sub ID rows that exist in the page (one group, not one section each). Names, tokens and saving are unchanged; the tab order is Settings, Parameters, Links, S2S postbacks, Notes.
- Parameters tab: the empty «Name in the link» and «Token» fields show a sample placeholder of what the field expects (`utm_term` / `{keyword}`, `cost` / `{price}`, `sub3` / `{sub3}`) and a short hint above the list says what each column is. A placeholder is never a value and is never saved; a typed token equal to its sample is saved.
- Campaign settings, first tab: «Visitors» (country, uniqueness, cookies) moved above «Default — when no stream matches»; the danger zone stays last. A new campaign answers 404 when no stream matches (a campaign with no type shows 404) and tells visitors apart by IP + user-agent; a saved campaign keeps its type and its «IP only» mode.
- «Shared templates» window of the S2S tab uses the same cards as the postbacks of a campaign: name on top, the address across the card, then one line with the method, the statuses and «Remove» on the right; «Add» sits under the list. Fields, statuses and saving are unchanged.
- «Links» tab: the two postback cards say what they are. `/?pb=KEY&cid=[CID]&profit=` is the «Old pixel» (needs `EMTDS_POSTBACK_KEY`, reads only `cid`, `profit` and `status`, always answers 200); `/postback?subid={subid}&…` is the «Network postback», the main address that a network calls itself. The addresses are unchanged.
- Conversions of a campaign (from the campaign menu) open already filtered by the campaign and by the statuses the campaign counts as a conversion, «Lead» and «Sale»; a rejected row is shown only when the filter is changed.
- «Links» tab of the campaign settings: every address is its own card with a short label above it, so nothing breaks in a narrow column. A long address wraps only before `?` and `&` (a macro such as `{status}` is never torn), the text is unchanged and selects whole with one click, and `[PAR-1] [PAR-2]` sit on their own line under the address with parameters. The same five addresses.
- «S2S postbacks» tab of the campaign settings is laid out clearly. Shared templates sit in their own block (the «Shared templates…» button at the right of the title, the template chips wrap below it); the macros hint is a quiet line with the macros in code style instead of a boxed callout; every postback is a card with the address on the full width (a long address is cut inside the field) and one bar under it: method, a joined segment of the lead / sale / rejected switches and a separate red «Remove» pushed to the right; «Add» sits under the list. The same fields, statuses, saving and templates; the checker row uses the same card. Light and dark theme.
- Tabs in the campaign settings drawer. The long scroll is split into «Settings» (identity, default answer, visitors, antiflood and, at the bottom, the danger zone — no field removed), «Links», «S2S postbacks» and, last, «Notes». The campaign canvas stays streams only, without tabs. «Notes» is a large always-visible textarea (up to 10000 characters) edited like any other campaign field: what is typed stays in the field while you switch tabs, marks the campaign as changed and is saved with the other settings as `notes`. ←/→/Home/End move between tabs; light and dark theme; labels in ru/en/uk.
- Assistant documents: Soul, Memory and Expertise. A new «Documents» tab in the AI settings holds three markdown texts: who the assistant is and how it answers, notes the administrator adds, and how this tracker works (campaigns and streams, offers, affiliate networks, the postback the engine never sends, the dashboard, access). Every assistant turn carries all three in the system prompt, each under its own heading (`## Soul`, `## Memory`, `## Expertise`), before the language instruction. A document is at most 8192 bytes: a save over the limit is `400 ai_bad_request` (`docs.<name>`, `too_long`), and a longer file edited by hand is cut with a note that it is longer than the limit; a document saved empty stays empty («(empty)» in the context). The texts live in `persona/soul.md`, `persona/memory.md` and `persona/expertise.md` inside the assistant directory (`EMTDS_AI_DIR`) on the data volume, so an update never erases them; a document never saved reads as a short built-in text, which is never written to the volume, so a restart keeps the saved text. Only whoever may change the AI settings (an administrator with a session) reads or saves them, through `docs` of `GET`/`PUT /api/ai/settings`; the assistant itself never rewrites them. Secrets of the process are cut out of the documents before they reach the model. Limits, quotas, step count and money are unchanged.
- Offers block on the dashboard. A new section «Offers» sits under «Performance by flow and stream» and is off by default: while it is off it is not on the page and no request is made. It is switched on in the dashboard preferences (gear next to refresh) with the other sections and is kept on the account in `dashboard.blocks` of `GET`/`PUT /api/me/views`, like the kept campaign, not in `localStorage`. An account that never stored the section keeps it off. The block asks `GET /api/report` for the same period and the same kept campaign as the rest of the dashboard and lists the ten offers with the most visits: visits, uniques, conversions and revenue (a column hidden from the user is left out). No leads, sales, EPC, CPC, cost, profit or ROI; the rows stay out of the PERF summary. It is offered only with the `report` section.
- Group actions in the lists. Networks and offers get a checkbox column (the header box ticks every row of the page you may change, Shift ticks a span) and a bar with «Group» and «Delete» for the ticked rows; campaigns get «Group» in their existing bar, with no mass delete. Nothing happens without a selection; delete asks once with the number of rows. Each row is written alone (`PUT`/`DELETE` per row; a campaign is sent from its last saved body, never the whole list in one `PUT`), only rows the role may change are touched, and the first failed request stops the loop and is shown.
- Network filter on the offers page. The toolbar of `#/offers` gets an affiliate network select beside «All groups» (default «All networks», searchable, same look). A pick keeps only the offers whose `network_id` is that network, an offer without a network is hidden, «All networks» brings everything back. It lists the networks the offers use, is cut on the client from the one `GET /api/offers` answer like the group filter, and also narrows the CSV/HTML export. Other pages and saving an offer are unchanged.
- Instruction block of a network template is laid out for reading: paragraphs with air, `status=` lines and code monospaced on their own, links underlined, long text wraps inside the dialog, light and dark theme. Only styles changed; the instruction text is shown as in the catalog.
- Affiliate network dialog and template catalog. The template picker starts empty («Choose a template») and searches by name; the catalog of exactly 333 network names (no own presets) comes from `GET /api/affiliate-network-templates`, one source in `internal/admin/net_templates.json`. Offer parameters, the postback address (rewritten to this tracker with the `{origin}` marker; a foreign host or a path token is never kept), the instruction (verbatim, shown read-only) and the status lists of the network (`conversions`, read-only, the tracker does not map them) come from a Keitaro template export, so every catalog template has real fields and a `source`. A template fills the name, the offer parameters and the postback address only with the fields it really has, and says «not extracted» when only the name is known; a field you typed is not overwritten. A person who may change networks can fill a template in later from the dialog (pencil next to the picker) or add one with a new name (`+`): `POST /api/affiliate-network-templates`, `PUT` and `DELETE /api/affiliate-network-templates/{id}`, session only. Opening a saved network whose name equals a template selects that template without touching the fields already typed, and a network with no template gets one added from it (name and offer parameters; the postback only as `{origin}/postback`, a foreign host, a path token and `from=` are dropped, and the server refuses them in a template). The edits live in `net-templates.json` on the data volume (`EMTDS_NET_TEMPLATES_FILE`), not in the built-in catalog, so an image update does not erase them; an empty field keeps the catalog value and a catalog name never changes. For a new network the offer parameters are empty and sit above the postback textarea (two rows). The label «Name» of the dialog and of the networks column is «Название»; the «?» next to «Offer parameters» explains `your_sub1={subid}`.
- Date column in the report. «Date» is the first column of `#/report` and is on by default («Restore defaults» brings it back; a saved view that turned it off keeps it off, a saved view without it gets it first). While it is on, the page asks `GET /api/report` for `day=1&tz=<interface zone>`: rows are also cut by event day, each row has `day` (`YYYY-MM-DD`) and counts that day alone, `sort=day` sorts by date, and the totals still cover the whole period. A bad `tz` is `400 bad tz`; without `day=1` the answer is as before. The hidden `ts` field hides `day`.
- Sub ID conditions of a stream: «contains» and «does not contain» next to «is» and «is not». The match is a case-insensitive substring, so `Fonbet` matches `Fonbet|Bovada|Another One`; a blank rule value matches nothing, and the engine and the stream preview share one function. Old streams keep the exact match. The Keitaro import now carries `sub_id_N` conditions of the contains mode and regular expressions that are only a list of literals (`/Fonbet|Bovada/`) as «contains»; a real regular expression (classes, quantifiers, anchors, groups) is still skipped with the note «too complex for contains».
- The assistant no longer stops after six steps and never asks you to send `/compact`. The default of «Steps per turn» and its ceiling are 1000 (a last resort, not a working limit), and the values 6 and 30 that earlier saves stored as the default now read as the new default. When the conversation of a turn grows to half of the input room, the assistant sums it up itself with one more model call («Compacting the conversation…» in the step log) and goes on with the same task; the summary call counts against the daily limits and budgets like any call, and a turn may compact as often as it has steps. The turn time limit is 15 s per step, 1000 steps in all (about 4 hours); the daily limits, budgets and `ai_busy` are unchanged.
- The assistant reads all campaigns, not 50. `list_campaigns` answered `result_too_large: narrow filters` on an account with thousands of campaigns, whatever the `limit`, because it read every campaign with all its streams as one answer. It now returns a page of summaries (`id`, `num`, `name`, `status`, `aliases`, `folder`, `board_id`, `domain_id`, `source_id`, `streams_total`, `streams_active`) with `total`, `offset`, `limit` and `next_offset`, searches the number too, and gives whole campaigns with their streams for up to 5 `ids`. A page is 100 rows by default and up to 200 (32 KiB); rows that do not fit are left for the page at `next_offset`, with `truncated`, so nothing is lost. Access is unchanged: the user sees only the campaigns the panel shows.
- The assistant no longer ends a turn on a promise. A reply that only says «I will load more pages» after tool work, or that the output limit cut off, is answered with one more model call that asks it to call the tool or give the final answer (at most 3 in a row, each counts as a step). A tool call that fails the same way twice is not run a third time; after three such refusals the turn stops with a plain line instead of looping. The daily limits and budgets are unchanged.
- The assistant no longer fails a turn on one empty summary, and names the cause of a provider failure. When the model returns no text for the context summary, the summary is asked for again once with a larger output room; if it stays empty and the conversation still fits the input room, the turn goes on without compacting (no new summary is paid for at every step), otherwise it ends with «the conversation did not compact» and keeps the text found so far. A provider failure shows its cause in place of one general line: overloaded or down (a 5xx answer), unreachable (network), plus the existing rate limit and timeout texts; no key and no provider answer body is shown. The daily limits and budgets are unchanged.
- The assistant says plainly when a change is not allowed. If it tries to change a section the assistant permissions or your access leave read-only, the reply says in the language of the panel that the section cannot be changed and can be read; with the «Edits without deletion» set, a delete says that deleting is not allowed and reading and editing are. The model is also told up front which sections it may only read. The permissions themselves are unchanged.
- Campaign choice on the dashboard. A search field in the header finds a campaign by name, id, number or alias (40 rows at a time, from the campaign list the page already holds) and keeps it on the account with the other page views (`dashboard.campaign` in `GET`/`PUT /api/me/views`), so it survives a reload and is not shared with other users. While it is kept, the cards, chart, performance table, «Who visits», recent clicks and the spend behind cost and profit cover that campaign only; a cross next to its name shows all campaigns again and clears the memory. The filter is the existing `campaign_id` condition of the stats requests, so a campaign the account may not see still gives empty statistics.
- Geo databases download from «Tools». Each database row has «Download» or «Update», which queues the same `geo_db` job of the cron service as the schedule; the table shows the run in progress, the last result or the error, and the engine picks the new file up within a minute. A city database without a MaxMind key gets «Download DB-IP City Lite (free)» (CC BY 4.0, attribution shown) and a link to the key on «Automation». Without the city database a banner above «Location» says «City and country unavailable: the database is not downloaded — Download». Only callers with the system settings right download (API keys need the `cron` action); others see «ask an administrator». New `GET /api/tools/geo` and `POST /api/tools/geo/download`.
- IP check history in «Tools». Every check is kept on the server (who, when, IP, country, city, ASN, organization, proxy, lists; 2000 checks and 90 days) and listed under the form by pages; a row click checks that address again. A user sees their own checks; the owner sees everyone's with a user filter and «Clear history» with confirmation, checked on the server. New `GET /api/tools/lookups` and `DELETE /api/tools/lookups`.
- Postback log. Every incoming postback is logged, accepted or not, with the reason (accepted, duplicate, click not found, no click id, wrong key or signature, invalid payout, method not allowed, storage errors): time, sender IP, network, method, path, parameters with tokens, keys and signatures masked, User-Agent, campaign and the conversion it gave. Logging is asynchronous and bounded and never slows down or fails the postback answer; rejected lines are capped at 20 a second. A «Postback log» button beside «Documentation» in the postbacks window opens the table with period, result, network, IP and click id filters, pages and rows that open their details. `GET /api/postback-log` takes `outcome`, `network`, `ip`, `cid`, `direction` and `offset`, and is open to the conversions section, limited to the campaigns the caller sees.
- Report and keyword statistics are paged on the server. The warning «Showing the first 2000 rows — narrow the filter. Totals are hidden» is gone: a pager above and below the table has first, previous, page numbers, next and last, the rows shown as «Rows 1–1000 of N», and 100, 500, 1000 (default) or 2000 rows per page, saved with the page views. The late redraw now runs only while the campaign is the page on screen, leaving the campaign cancels a waiting redraw, and a finished visitor test does not redraw a campaign that was left. The menu item, the unsaved-changes prompt and the list reuse of loaded campaigns are unchanged.
- A campaign saved in the panel is live in the engine at once. Before, the engine took the groups file only at its next timer tick (`EMTDS_RELOAD_INTERVAL`, a minute by default), so after a rename or a new link the old id kept answering with its old destination and the new id answered as an unknown campaign. Every write of the groups file now ends with `POST /internal/reload` to the engine (new route, not published by nginx), which re-reads the campaigns and the catalogs and swaps them in; a failed call is logged and the timer stays as the fallback. A file replaced by rename with the same size and modification time is now noticed too. No restart and no Redis cleanup are needed: no click route lives in Redis.
- A copy of a migrated campaign no longer sends the click back to the old Keitaro. The copy keeps every destination of the original, and a migrated stream often holds a plain campaign link of the tracker (`https://<keitaro>/middleware?…`), which changing the campaign id or its domain does not touch. A new campaign saved with such a link in its default or in a stream without offers and landings now gets a link to the campaign of the same id or alias in this panel (`redirect: group`); when none exists, or the caller may not see it, the address stays. Campaigns already saved, other sections, restores and assistant writes are not rewritten. The answer of `PUT /api/groups` and `PUT /api/groups/{id}` lists the changed campaigns under `relinked`, and the panel shows the stored destination.
- «Settings → About» no longer shows the raw git error when the updater cannot read its repository. With no repository set, or with the product repository that is not public, it says calmly that the repository is not public and updates are paused (`repo_paused`); with another repository that was deleted or closed it says the repository was not found (`repo_not_found`). The address row stays with the server command that sets another repository, «Check now» still works, and «Update» writes no request (`repo_state` and `apply_block` in `GET /api/update`, 409 with the same code on `POST /api/update/apply`) and leaves a run in progress alone.
- Campaign page in the admin: the «Campaigns» button in the header opens the list without reading all campaigns again when they are already loaded (the menu item is unchanged), and the per-stream offer reports that were still queued are dropped when you leave the campaign, so they no longer hold the list back. An offer line in the expanded stream row stays inside the destination card: the name is cut with an ellipsis, the percent, bots, conversions and revenue stay visible, in light and dark theme. On narrow widths the purple trunk line of the canvas keeps 12px of air from the canvas edge and from the stream blocks.
- The visitor check takes the country from the country list. The extra country-code field is gone, and the list keeps the «Country» label.
- The click log and the conversion log opened from a campaign («Logs» menu) now show the filter at once: «Campaign ID — Equals — the campaign» as a normal condition you can edit or drop; before, the campaign was a hidden extra condition and the filter list was empty. A click that one campaign forwards to another is stored under the serving campaign, so the journal of the entry campaign was empty although the visitor reached the offer. A condition on «Campaign» or «Campaign ID» (is, is one of, is not, is not one of) in the two journals and their CSV exports now matches the serving campaign and the entry campaign (`origin_campaign`, `origin_campaign_id`). Statistics, the report and the access scope of a role compare the serving campaign only, as before.
- A long name on an unsaved-changes chip stays left-aligned, so the type, the number and the start of the name stay visible, and scrolls to its end on hover or keyboard focus when it does not fit. A name that fits stays still, and reduced motion does not scroll.
- Saving a copied campaign no longer fails with «HTTP 413» on a large installation: the copy is sent alone with `PUT /api/groups/{id}` instead of the whole list of thousands of campaigns, and a list of more than 500 campaigns is never sent whole, so turning many campaigns on or off at once saves each of them alone. Changing a campaign ID («ID — link») no longer deletes the campaign when the save fails: `PUT /api/groups/{old id}` with the new id in the body renames it in one write, keeps its place, section, owner and number and moves the campaign links of other campaigns to the new id; a taken id answers 409 with «ID «…» уже занят другой кампанией или алиасом», an id with a space, `/`, `?` or `#` answers 400. Clicks already logged stay under the old id. A campaign body over the limit answers 413 instead of «bad json».
- Error toasts no longer show raw codes such as `rate_limited`. A refusal for asking too often names what was asked and when it can be repeated, for example «Проверка обновлений: слишком много запросов. Повторить можно через 3 мин.» (a manual update check is held for 5 minutes after the last check, the one the updater runs right after an apply included); the other common codes (`forbidden`, `bad json`, `not found`, `conflict`, server errors) are translated, and an unknown code gets a general text with the code in small print for support. `POST /api/update/check`, `POST /api/login`, `POST /api/setup`, `POST /api/recover`, the API key limit and the public docs limit answer 429 with `Retry-After` and `retry_after` in seconds.
- Campaigns, domains and the other pages no longer hang on «Loading…» after a large Keitaro transfer. Thousands of imported streams carry the same list of thousands of device models, which made `GET /api/groups` about 500 MB (210 MB gzipped) and drove the admin out of memory. The panel now reads `GET /api/groups?shared=1`: each long list filter (1 KB of text or more) is sent once in `lists` and put back by `refs`, which cuts that answer to about 14 MB (under 1 MB gzipped); pages of one section that ask at the same time, the user access editor included, share one request, and the unsaved-changes snapshot names a shared list instead of copying it. The engine and the admin keep one copy of each equal long list in memory. The plain `GET /api/groups` answer is unchanged.
- Adding a regular user to a section no longer hides the default section from them. The user card has a «Main section» mark, on by default (`no_main_board` in `POST`/`PUT /api/users`), and lists the sections open by membership; saving section members changes only `board_ids`. A regular user sees the default section unless the mark is cleared, plus the member sections; existing users keep the default section without any manual change, and administrators and all-sections accounts still see everything. A user with no section gets `403 no boards` on section data and a notice in the panel.
- Clean Ubuntu install opens the admin on `http://<IP>/` too. `install.sh` installs nginx 1.25.1+ from the official nginx.org repository (signing key checked by fingerprint, apt pin 900): the distribution nginx 1.24 failed `nginx -t` on `http2 on`. A suitable nginx is kept; an old one with only package configs is replaced after a copy of `/etc/nginx`, an old one with own sites stops the install with a `--no-edge` hint. `apply-edge.sh` adds `conf.d/emtds-http.conf` (port 80 redirects to https on the same host) only when nothing but an unmodified package welcome page listens on port 80; that page is moved to the backup and restored on rollback, and a server with a foreign port 80 listener (hosting panel) stays as it was. `GUID_INSTALL_UBUNTU.MD` describes the nginx version, the nginx.org setup, the self-signed certificate warning on `https://<IP>/` and how to read the setup token.
- An administrator («Full access») and an account with all sections always see every section. Adding such a user to a section's members, or removing them, no longer leaves them with that one section; accounts already narrowed this way see every section again after the update. A regular user is still limited to the sections that list them as a member.
- After an update the running commit is no longer offered as a new version. The updater checks the channel again once an apply succeeds, and a check made for another build than the running one gives no «New version available» banner, no list of commits ahead and no «Update» (`apply_block: check_stale`, `check_stale` in `GET /api/update`); its line in «Settings → About» offers «Check now», which is not held back by the age of that check.
- A long Keitaro click or conversion log import no longer fails on one broken page. A page whose answer breaks off mid-body, does not connect, or comes back 429, 502, 503, 504 or Cloudflare 520–524 is asked again after 2, 10 and 30 seconds; only then does the import stop. A refused column list (400) still falls back at once. The error now names the cause, for example `keitaro: чтение /admin_api/v1/clicks/log: unexpected EOF`.
- AI settings, "Connection": the note about the key storage spans the full width of the field grid under the fields instead of half of it.
- Keitaro transfer result: the "finished" note no longer touches the counters above it, the warning table wraps its columns inside the panel at about 580 px without side scroll, and the counters wrap too. An offer country `Unknown` (or an empty code) is kept as the country "Unknown" and is no longer reported as an approximation; real garbage still is.
- The campaign filter bar: the group filter has the same width as the state filter, the search field takes the rest of the row, and the bar stays in one row at about 740 px.
- The Markdown button of the API reference opens a formatted page inside the admin (contents, highlighted samples, downloads of the `.md`, OpenAPI and Postman files) instead of the raw text in a new tab.
- The dialog that shows a new API key once: clicking the key (or Enter/Space on it) copies it the same way as the «Copy» button, the field spans the dialog width and wraps long keys, and after copying the button reads «Copied» for two seconds.

## [v0.1.0] - 2026-11-17

First tagged version: the current state of the product.

### Added

- **Engine:**
  - Campaigns and flows with streams, conditions and 18 output types.
  - Click handling with uniqueness by IP or by cookie, anti-flood and per-stream impression limits.
  - Postbacks and conversions.
  - Bot protection: user-agent and referer signatures, search-engine IP lists, reverse DNS, separate bot output.
  - Landings and offers.
- **Admin panel (embedded in the binary):**
  - Reports and dashboard with filters, sorting and saved table settings.
  - Users, roles and per-section permissions.
  - API keys.
  - Domains parked as a list, with the Cloudflare integration (zones, DNS records, `ssl` and `always_use_https` settings).
  - Transfer from Keitaro.
  - Integrations.
  - Telegram notifications sent by the background cron service.
  - OpenAPI, Postman collection and `/llms.txt`, generated from one route catalog.
- **Update agent** (`deploy/update.sh`):
  - Applies only fast-forward updates and fetches only from the pinned `origin`.
  - Checks for updates every hour.
  - Shows "What's new" taken from this file.
  - Optional commit and tag signature check against `/etc/emtds/allowed_signers`; off by default.
- **One-command installer** from git: `deploy/install.sh` clones the repository, builds the images with the commit baked in and starts the stack.
- **First-login token:** the installer prints a one-time token that is required to create the first administrator.
- **Settings → About:** version, build commit, update state and server state.
- **Theme:** light and dark themes plus the brand colour scheme of the admin panel.

### Changed

- The product is branded as EmTDS: directories `/opt/emtds` and `/etc/emtds`, Docker Compose projects `emtds-infra` and `emtds-app`, environment variables `EMTDS_*`.
- The "Profile" menu item is renamed to "Settings".
- The menu and the Settings tabs are built from one list, so they always match.

### Security

- Passwords are hashed with argon2id; sessions are stored on the server; CSRF protection and parameterized queries are used throughout.
- Access to the admin panel and to API keys is limited by roles and sections.
- The admin container has no `docker.sock` and no root access to the host; updates run only through the host agent.
- A secrets scan (gitleaks, pinned version) runs in CI on new commits.
