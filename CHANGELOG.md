# Changelog

All notable changes to EmTDS are recorded in this file.

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and versions follow [Semantic Versioning](https://semver.org/spec/v2.0.0.html). Every noticeable change goes into `## [Unreleased]` first; the update agent shows the added lines of this file as "What's new" before an update is applied.

## [Unreleased]

### Added

- Offers block on the dashboard. A new section «Offers» sits under «Performance by flow and stream» and is off by default: while it is off it is not on the page and no request is made. It is switched on in the dashboard preferences (gear next to refresh) with the other sections and is kept on the account in `dashboard.blocks` of `GET`/`PUT /api/me/views`, like the kept campaign, not in `localStorage`. An account that never stored the section keeps it off. The block asks `GET /api/report` for the same period and the same kept campaign as the rest of the dashboard and lists the ten offers with the most visits: visits, uniques, conversions and revenue (a column hidden from the user is left out). No leads, sales, EPC, CPC, cost, profit or ROI; the rows stay out of the PERF summary. It is offered only with the `report` section.
- Group actions in the lists. Networks and offers get a checkbox column (the header box ticks every row of the page you may change, Shift ticks a span) and a bar with «Group» and «Delete» for the ticked rows; campaigns get «Group» in their existing bar, with no mass delete. Nothing happens without a selection; delete asks once with the number of rows. Each row is written alone (`PUT`/`DELETE` per row; a campaign is sent from its last saved body, never the whole list in one `PUT`), only rows the role may change are touched, and the first failed request stops the loop and is shown.
- Network filter on the offers page. The toolbar of `#/offers` gets an affiliate network select beside «All groups» (default «All networks», searchable, same look). A pick keeps only the offers whose `network_id` is that network, an offer without a network is hidden, «All networks» brings everything back. It lists the networks the offers use, is cut on the client from the one `GET /api/offers` answer like the group filter, and also narrows the CSV/HTML export. Other pages and saving an offer are unchanged.
- Instruction block of a network template is laid out for reading: paragraphs with air, `status=` lines and code monospaced on their own, links underlined, long text wraps inside the dialog, light and dark theme. Only styles changed; the instruction text is shown as in the catalog.
- Affiliate network dialog and template catalog. The template picker starts empty («Choose a template») and searches by name; the catalog of exactly 333 network names (no own presets) comes from `GET /api/affiliate-network-templates`, one source in `internal/admin/net_templates.json`. Offer parameters, the postback address (rewritten to this tracker with the `{origin}` marker; a foreign host or a path token is never kept), the instruction (verbatim, shown read-only) and the status lists of the network (`conversions`, read-only, the tracker does not map them) come from a Keitaro template export, so every catalog template has real fields and a `source`. A template fills the name, the offer parameters and the postback address only with the fields it really has, and says «not extracted» when only the name is known; a field you typed is not overwritten. A person who may change networks can fill a template in later from the dialog (pencil next to the picker) or add one with a new name (`+`): `POST /api/affiliate-network-templates`, `PUT` and `DELETE /api/affiliate-network-templates/{id}`, session only. Opening a saved network whose name equals a template selects that template without touching the fields already typed, and a network with no template gets one added from it (name and offer parameters; the postback only as `{origin}/postback`, a foreign host, a path token and `from=` are dropped, and the server refuses them in a template). The edits live in `net-templates.json` on the data volume (`EMTDS_NET_TEMPLATES_FILE`), not in the built-in catalog, so an image update does not erase them; an empty field keeps the catalog value and a catalog name never changes. For a new network the offer parameters are empty and sit above the postback textarea (two rows). The label «Name» of the dialog and of the networks column is «Название»; the «?» next to «Offer parameters» explains `your_sub1={subid}`.
- Date column in the report. «Date» is the first column of `#/report` and is on by default («Restore defaults» brings it back; a saved view that turned it off keeps it off, a saved view without it gets it first). While it is on, the page asks `GET /api/report` for `day=1&tz=<interface zone>`: rows are also cut by event day, each row has `day` (`YYYY-MM-DD`) and counts that day alone, `sort=day` sorts by date, and the totals still cover the whole period. A bad `tz` is `400 bad tz`; without `day=1` the answer is as before. The hidden `ts` field hides `day`.
- Sub ID conditions of a stream: «contains» and «does not contain» next to «is» and «is not». The match is a case-insensitive substring, so `Fonbet` matches `Fonbet|Bovada|Another One`; a blank rule value matches nothing, and the engine and the stream preview share one function. Old streams keep the exact match. The Keitaro import now carries `sub_id_N` conditions of the contains mode and regular expressions that are only a list of literals (`/Fonbet|Bovada/`) as «contains»; a real regular expression (classes, quantifiers, anchors, groups) is still skipped with the note «too complex for contains».
- The assistant no longer stops after six steps and never asks you to send `/compact`. The default of «Steps per turn» and its ceiling are 1000 (a last resort, not a working limit), and the values 6 and 30 that earlier saves stored as the default now read as the new default. When the conversation of a turn grows to half of the input room, the assistant sums it up itself with one more model call («Compacting the conversation…» in the step log) and goes on with the same task; the summary call counts against the daily limits and budgets like any call, and a turn may compact as often as it has steps. The turn time limit is 15 s per step, 1000 steps in all (about 4 hours); the daily limits, budgets and `ai_busy` are unchanged.
- The assistant reads all campaigns, not 50. `list_campaigns` answered `result_too_large: narrow filters` on an account with thousands of campaigns, whatever the `limit`, because it read every campaign with all its streams as one answer. It now returns a page of summaries (`id`, `num`, `name`, `status`, `aliases`, `folder`, `board_id`, `domain_id`, `source_id`, `streams_total`, `streams_active`) with `total`, `offset`, `limit` and `next_offset`, searches the number too, and gives whole campaigns with their streams for up to 5 `ids`. A page is 100 rows by default and up to 200 (32 KiB); rows that do not fit are left for the page at `next_offset`, with `truncated`, so nothing is lost. Access is unchanged: the user sees only the campaigns the panel shows.
- The assistant no longer ends a turn on a promise. A reply that only says «I will load more pages» after tool work, or that the output limit cut off, is answered with one more model call that asks it to call the tool or give the final answer (at most 3 in a row, each counts as a step). A tool call that fails the same way twice is not run a third time; after three such refusals the turn stops with a plain line instead of looping. The daily limits and budgets are unchanged.
- The assistant no longer fails a turn on one empty summary, and names the cause of a provider failure. When the model returns no text for the context summary, the summary is asked for again once with a larger output room; if it stays empty and the conversation still fits the input room, the turn goes on without compacting (no new summary is paid for at every step), otherwise it ends with «the conversation did not compact» and keeps the text found so far. A provider failure shows its cause in place of one general line: overloaded or down (a 5xx answer), unreachable (network), plus the existing rate limit and timeout texts; no key and no provider answer body is shown. The daily limits and budgets are unchanged.
- The assistant says plainly when a change is not allowed. If it tries to change a section the assistant permissions or your access leave read-only, the reply says in the language of the panel that the section cannot be changed and can be read; with the «Edits without deletion» set, a delete says that deleting is not allowed and reading and editing are. The model is also told up front which sections it may only read. The permissions themselves are unchanged.
- Campaign choice on the dashboard. A search field in the header finds a campaign by name, id, number or alias (40 rows at a time, from the campaign list the page already holds) and keeps it on the account with the other page views (`dashboard.campaign` in `GET`/`PUT /api/me/views`), so it survives a reload and is not shared with other users. While it is kept, the cards, chart, performance table, «Who visits», recent clicks and the spend behind cost and profit cover that campaign only; a cross next to its name shows all campaigns again and clears the memory. The filter is the existing `campaign_id` condition of the stats requests, so a campaign the account may not see still gives empty statistics.
- Geo databases download from «Tools». Each database row has «Download» or «Update», which queues the same `geo_db` job of the cron service as the schedule; the table shows the run in progress, the last result or the error, and the engine picks the new file up within a minute. A city database without a MaxMind key gets «Download DB-IP City Lite (free)» (CC BY 4.0, attribution shown) and a link to the key on «Automation». Without the city database a banner above «Location» says «City and country unavailable: the database is not downloaded — Download». Only callers with the system settings right download (API keys need the `cron` action); others see «ask an administrator». New `GET /api/tools/geo` and `POST /api/tools/geo/download`.
- IP check history in «Tools». Every check is kept on the server (who, when, IP, country, city, ASN, organization, proxy, lists; 2000 checks and 90 days) and listed under the form by pages; a row click checks that address again. A user sees their own checks; the owner sees everyone's with a user filter and «Clear history» with confirmation, checked on the server. New `GET /api/tools/lookups` and `DELETE /api/tools/lookups`.
- Postback log. Every incoming postback is logged, accepted or not, with the reason (accepted, duplicate, click not found, no click id, wrong key or signature, invalid payout, method not allowed, storage errors): time, sender IP, network, method, path, parameters with tokens, keys and signatures masked, User-Agent, campaign and the conversion it gave. Logging is asynchronous and bounded and never slows down or fails the postback answer; rejected lines are capped at 20 a second. A «Postback log» button beside «Documentation» in the postbacks window opens the table with period, result, network, IP and click id filters, pages and rows that open their details. `GET /api/postback-log` takes `outcome`, `network`, `ip`, `cid`, `direction` and `offset`, and is open to the conversions section, limited to the campaigns the caller sees.
- Report and keyword statistics are paged on the server. The warning «Showing the first 2000 rows — narrow the filter. Totals are hidden» is gone: a pager above and below the table has first, previous, page numbers, next and last, the rows shown as «Rows 1–1000 of N», and 100, 500, 1000 (default) or 2000 rows per page, saved with the page views. Sorting orders the whole set on the server, with a fixed tie-break so a page boundary never moves; a new filter, period or sort goes back to page one. The total row is always shown and counts every row of the set («Total of all N rows»), ratios from the sums. CSV and HTML export save the whole set in the current sort, up to 100000 rows, and say so when it is larger. `GET /api/report` and `GET /api/keywords/stats` take `limit`, `offset`, `sort` and `dir` and then answer `{rows, total, offset, limit, sort, dir, totals, truncated}`; a request without them answers as before.
- Quick controls in the access editor of a user, a role and an API key. Every chip group («Sections», «Hidden metrics», and the entities and labels of a resource) has «Select all» and «Clear all» on the right of its title; «Hidden metrics» also counts «hidden N of M». A «Quick access» switch above the sections has «Read everything», «Edit everything» and «Custom»: a preset sets read or full on every resource that offers the mode and opens every section of the window (Dashboard, logs, Report, Keywords, Lists, Tools, Groups and the rest), and leaves the hidden metrics as they are. Any change by hand switches it to «Custom», and on open it shows the preset the stored access matches: every section open and the modes of the resources. The saved access and the server checks are unchanged.
- Content width and two accents in the profile appearance settings. A «Content width» card switches between «In a container» (limited width, centred) and «Full width» (the content follows the screen with margins and card grids add columns on wide screens); the choice is kept in the browser. «Yellow» (dark text on the fill) and «Fire» join the accent colours.
- Campaigns header has the same groups button as affiliate networks, immediately left of the column gear. It opens the shared groups window for the campaign folder (`folder` on the campaign, no second catalog): Create starts a campaign in that group, and Delete clears the folder on the campaigns that have it.
- Assistant budget in US dollars. On the «Usage» tab of the assistant settings every user has a «Budget, USD» field right of the amount spent, and a block of groups (roles) appears below the users when the system has roles. An empty field means no limit and a negative value is refused. The budget counts only money of the UTC day (the price of the tokens), not chat length or tokens, and is saved with the other assistant settings (`user_budget_usd`, `group_budget_usd` in `PUT /api/ai/settings`). A turn that would pass the budget of the user or of their group, the stricter one wins, is refused with `ai_quota` (`params.scope`: `user_budget` or `group_budget`) and the chat tells which. Save stays visible on the «Usage» tab.
- Chips of the allowed models carry actions. On hover or keyboard focus a chip shows a cross that takes the model off the selection (its prices go too) and, for a model that is not the default, a star that makes it the default. Taking off the default hands it to the next selected model by name (case ignored), or to the first by name when it was the last. Nothing is saved until "Save".
- Assistant replies link to records. The assistant writes a campaign, offer, landing, affiliate network or traffic source as `[[type:id|Name]]`, and the panel shows it as a link to the page of that record (`#/flows/{id}`, `#/offers/{id}`, `#/landings/{id}`, `#/networks/{id}`, `#/sources/{id}`). Any other text of a reply stays plain, a broken token stays text, and older replies show as before.
- Keitaro check shows the tracker version. The API does not report it, so "Check connection" reads a few fresh click and conversion log records (read-only) and votes: SubID format (dotted is Keitaro 11), id columns (`click_id`/`conversion_id` vs `event_id`/`event_type`), Rebill (10) and custom conversion types (11). The card says "Keitaro 10" or "Keitaro 11" with the signs, or that the version is not determined when the signs are missing or disagree. Log import then asks the id columns of the found version, reads them into the click and conversion rows, and takes the conversion type from `event_type` when `status` is empty.
- A clear button in the search fields of campaigns, offers, landings, networks, sources and domains. It shows only while the field has text and clears the field in one click.
- Voice input in the assistant message field. A microphone button beside "Send" starts dictation in the language of the interface (ru-RU, en-US, uk-UA) and the same button stops it. Each confirmed phrase is appended to the text after a space for editing; the draft shows only beside the button, and nothing is sent by itself. One click starts a recording that lasts until you press stop: the microphone button turns into the stop button, the recogniser restarts by itself when the browser closes its session, and animated voice waves follow the loudness of the microphone (still bars with reduced motion). A failure (no microphone access, speech not recognised) is shown in full and only when the whole session brought no phrase. Chrome and Edge use the browser Web Speech API.
- Dictation in a browser without its own speech service. When the browser answers `network` or `service-not-allowed` (the embedded Electron browser) or has no Web Speech API (Firefox), dictation goes on inside the page: the recording is turned into text by Whisper tiny through transformers.js. The audio does not leave the browser, there is no paid API and no server of ours. The model (about 40 MB) downloads once into the browser cache with a progress line and is not in the repository. The browser is remembered and the next dictation goes straight to this mode. No message about the internet is shown.
- Header marks for the administrator from one answer, `GET /api/system/signals` (`update`, `down`). A newer commit for the running build puts a yellow dot on the avatar and the download icon on the «About» entry of the profile menu. An engine, ClickHouse or Redis that does not answer puts a red dot and a red triangle there, and opens a window once per set of failed services: which ones, a request to restart the server or the service and a link to «Settings → About». The marks are read once a minute.
- «Settings → About» marks each build of the admin, the engine and cron as Production or Development. Production comes only from `EMTDS_ENV=production`, which `install.sh` writes to `/etc/emtds/server.env`. A local stack is Development. The field is `env` in `GET /api/version` and in `/internal/version` of the engine.
- `GUID_INSTALL_UBUNTU.MD`: installing on a clean Ubuntu step by step (Docker, git, nginx, the clone in `/opt/emtds`, `deploy/install.sh --repo … --channel main`, the checks and the first login).
- Daily ceilings of the assistant on the «Usage» tab under the cards: tokens a day for everyone and for one user, US dollars a day for everyone and for one user. An empty field or «No limit» removes a ceiling; tokens have no ceiling by default. In `PUT /api/ai/settings` `null` means no limit and `0` is a real ceiling that refuses every turn. A card without a ceiling does not show «of».
- Bot signature database. The `ch_ua` check (on in the default profile, so every stream gets it without a switch) also matches the User-Agent against open bot lists downloaded by the new cron job `bot_signatures`: Matomo DeviceDetector `bots.yml`, Crawler User Agents and isbot. A match gives the label `sign_db` and the header `X-Emtds-Bot-Reason` with the source and the rule. Built-in signatures and search engines are checked first, so a search engine User-Agent is still confirmed by its IP list or DNS as before; weak generic words never make a bot, and a VPN, a proxy, an ASN or an empty referer are not part of this check. «Automation → Bot signatures» (on, every 24 hours) has «Run now», the status, the last success, the number of signatures and the sources to add, edit, remove, switch on and off with their errors. Rules are validated and deduplicated before they are written to `bot_signatures.json` in the data directory; a failing source keeps its previous rules and a broken download never replaces the working database. The engine swaps the database in memory without stopping clicks and does not touch the network on a click. FingerprintJS BotD is not used: it needs JavaScript on every visitor's page.
- Keitaro import journal and «Continue». The state of the last manual import is written to `keitaro-job.json` on the state volume (beside `keitaro-import.json`) while it runs, without the tracker address, the key or passwords, so it survives an admin restart; a run cut by a restart comes back as stopped and «cut by an admin restart». «Integrations → Keitaro → What to move» shows the last import: the stage, the error, the click and conversion rows written so far, the start and the last change, live while it runs. A full import stopped by a timeout, a broken log read or a restart gets «Continue» (`POST /api/keitaro/import` with only `resume: true`): nothing imported is removed, catalogs that passed are not imported again, clicks continue from the last written batch without doubling a `cid`, conversions are read again and collapse as before. «Import» and «Remove imported» stay as they were; after «Remove imported» there is nothing to continue. `GET /api/keitaro/job` adds `last_stage`, `updated_at`, `interrupted`, `resumable`, `resumes` and `logs`.

### Changed

- The dashboard shows a skeleton of its own blocks while the summary loads. The header (campaign search, refresh, preferences) stays in place and keeps working. Metric cards, the chart, the campaigns table, Offers, Who visits and recent clicks are gray strips of the same height as the real blocks, and only the blocks this user has switched on; a metric hidden by access and a switched-off chart or Offers block are left out, with no figures on the strips. The last shape (which blocks were on, how many rows) is remembered in this browser for that user and does not stand in for fresh numbers; hiding a column drops it from the skeleton. Refresh of an open summary still keeps the numbers on screen.
- Lists that already have a toolbar or a bottom panel keep that row while they load. Create, search, filters, refresh, view buttons, pager buttons and export are strips of the same height and about the same width, in the same row; the counter is a short strip. They are not buttons until the rows arrive. Campaigns, offers, networks, landings, the report, logs, domains, users and automation use only the panels they already have. A page without a bottom panel does not gain one. Column sets are unchanged.
- The recent-clicks table on the dashboard keeps the Destination column inside the card. The header and a long address are cut with an ellipsis on one line; the table stays the width of its block. Other columns and their sorting are unchanged.
- Traffic share bar of a stream on the campaign canvas is drawn whenever the campaign has traffic (before, only while ordering by traffic), with a visible track in the light and dark theme. The percent and the shares are unchanged.
- Duplicating a campaign assigns a new id of 9 characters that is not already a campaign id or an alias, including campaigns that are not on the current page and campaigns in other sections. A clash draws another id of the same length. The name still gains « (copy)» when the campaign has a name.
- The save bar shows that a save is in progress. While the request runs, Save is disabled, reads «Saving…» and shows a bar; a second click does not send another request. An error restores the button and the translated text. Opening a campaign paints skeleton stream rows on the empty canvas until the streams load; a failed load shows the error. Reduced motion keeps both marks still.
- The campaigns list shows skeleton rows and «Loading campaigns…» while the rows are still loading, and the toolbar and the bottom panel stay as strips of the same height. A failed load shows the error instead of the skeleton. Reduced motion keeps the rows still.
- Tables that wait on the server (offers, networks, landings, report, click and conversion logs, keywords, domains, users, automation and the other admin tables) show the same skeleton rows and «Loading…» until the answer. An empty answer stays the empty state. A failed load shows the error. Reduced motion keeps the rows still.
- DepSum is no longer shown: the conversion-log total and column, the campaign, offer and network total tiles, and the DepSum column of campaigns, offers, networks, the report and keywords. The deposit amount stays stored and is still summed beside revenue.
- A stream destination names an offer or a landing on the action type («HTTP redirect (offer)», «HTTP redirect (landing)», both when the stream sends to each). The compact row keeps one line of bots, conversions and revenue for the whole stream and does not ask for a breakdown. The detailed row asks GET /api/report for that stream and folds country and source into one line per offer (bots, conversions, revenue); an offer with no rows is skipped, and the stream total is not split by share. On the detailed row an offer with conversions or revenue has its name and share on the left of the bots, conversions and revenue. The badges under that row are the other offers of the stream, the ones with neither, and they are left out when there are none. The compact row keeps one summary and the badges. On the detailed row that chip, fixed width, sits to the left of the bots, conversions and revenue; a stream with one offer and no per-offer rows puts the chip beside the stream line. Offers whose share is zero are one badge, +N (0%), with their names in its title; +N without (0%) is only the offers above zero that did not fit.
- The campaign canvas sort cycles through off, traffic with the fewest visits on top, traffic with the most on top, revenue with the least on top and revenue with the most on top. Off is the default: streams stay in their stored order and the button is not pressed. Revenue is the amount the stream line already shows; zero and a missing amount sort as zero, and equal values keep their stored order.
- A stream on the campaign scheme names the offers and landings that receive traffic, in both the compact and the detailed row, and folds the rest into +N. That row does not also show the saved URL. Hovering the destination lists every selected offer and landing with its share, including a zero share. A numeric id with no catalog name is not shown. A stream with only its own URL stays a link; an offer id that appears only in that URL is not a selected offer.
- Campaign page header: «Test a visitor» is an icon button with the same name in the tooltip. «Settings» shows the gear and the word «Settings». Click log and conversion log are one «Logs» menu; each item keeps its icon and the same page. On a stream line, conversions and revenue use the revenue green only when that amount is above zero; bots and a zero stay the hint colour. The bot condition chip shows the bot icon before the word.
- Conversion alerts send the profit for a period to the same Telegram chat. «Run now» and the schedule each send that summary once, for the period chosen on the card (today, or any period the report header already has, including a custom range), and still send each new conversion as its own message. The first run no longer stays silent: it does not replay old conversions line by line, and it does send the profit. The interval next to the period is the summary schedule.
- The «Update» button of «Settings → About» is always drawn, highlighted and above the report of the last run. When it cannot be used the reason is written under it, for example that a Keitaro import is running: the update waits for it and the import is not interrupted; the page rechecks every 15 seconds and the button turns on when the import ends. The «New version available» banner has the same «Update» action (the same request into the inbox, the updater on the host pulls git) and can be hidden in this browser until the next version or for 24 hours; the avatar dot stays. When the admin does not confirm idle within 10 minutes the update run now says that an import or a catch-up of Keitaro is running and nothing was applied, instead of suggesting `--keitaro-idle`.
- «Settings → About» shows the progress of an update right after «Update» is confirmed: request accepted, waiting for the agent on the server, applying with the phases of the run report (env, resources, backup, build, keitaro_gate, …), then done or the reason of the failure. A request already in the inbox or a running update opens the same progress instead of the toast «Request already pending», and a rollback follows the same way. While the admin panel restarts during the run the page waits for it. The page falls into four blocks like the settings cards, «Version», «Update», «How to update manually» and «Server», with the buttons of each block at the right of its title and the copy button inside each command row.
- Assistant settings, allowed models: the ticked models and the default one show as chips above the model list and update at once, before Save. The prices of the ticked models are a form block per model with labelled «Input» and «Output» fields instead of a table, with «Input» and «Output» side by side. The limits moved from their own tab to a folded «Limits» block under the prices.
- The list of fields (hidden metrics in the access editor, filters, columns) follows one order by group: campaign, time, result, money, geo, device, traffic source, identifiers, network, origin. The «Hidden metrics» heading in the access editor has a top margin like the other headings.
- The period button of the header shows the chosen period next to the calendar icon. When the header does not fit, the nav labels hide first, then the period label, and only then the nav folds into the menu button. The period stays in the title and the accessible name of the button.
- Assistant limits: the per-turn limits stay in the folded «Limits» block under the prices, and the daily ceilings moved to the «Usage» tab.

The settings fall into groups with space between them: connection (switch, address, X-Tenant-ID, API token), apps (creation switch, admin address, app card address, locales), postback (address, method, tracking token), counters with «Save» and «Check» in a separate row, and the campaign keys. A long postback address wraps inside its field and no longer stretches the grid.
- On a narrow screen (up to 720px) the «Create» button in the lists of campaigns, offers, landings, networks, sources and domains shows only «+»; the name stays for screen readers.

### Fixed

- The visitor check takes the country from the country list. The extra country-code field is gone, and the list keeps the «Country» label.
- The click log and the conversion log opened from a campaign («Logs» menu) now show the filter at once: «Campaign ID — Equals — the campaign» as a normal condition you can edit or drop; before, the campaign was a hidden extra condition and the filter list was empty. A click that one campaign forwards to another is stored under the serving campaign, so the journal of the entry campaign was empty although the visitor reached the offer. A condition on «Campaign» or «Campaign ID» (is, is one of, is not, is not one of) in the two journals and their CSV exports now matches the serving campaign and the entry campaign (`origin_campaign`, `origin_campaign_id`). Statistics, the report and the access scope of a role compare the serving campaign only, as before.
- A long name on an unsaved-changes chip stays left-aligned, so the type, the number and the start of the name stay visible, and scrolls to its end on hover or keyboard focus when it does not fit. A name that fits stays still, and reduced motion does not scroll.
- Saving a copied campaign no longer fails with «HTTP 413» on a large installation: the copy is sent alone with `PUT /api/groups/{id}` instead of the whole list of thousands of campaigns, and a list of more than 500 campaigns is never sent whole, so turning many campaigns on or off at once saves each of them alone. Changing a campaign ID («ID — link») no longer deletes the campaign when the save fails: `PUT /api/groups/{old id}` with the new id in the body renames it in one write, keeps its place, section, owner and number and moves the campaign links of other campaigns to the new id; a taken id answers 409 with «ID «…» уже занят другой кампанией или алиасом», an id with a space, `/`, `?` or `#` answers 400. Clicks already logged stay under the old id. A campaign body over the limit answers 413 instead of «bad json».
- Error toasts no longer show raw codes such as `rate_limited`. A refusal for asking too often names what was asked and when it can be repeated, for example «Проверка обновлений: слишком много запросов. Повторить можно через 3 мин.» (a manual update check is held for 5 minutes after the last check, the one the updater runs right after an apply included); the other common codes (`forbidden`, `bad json`, `not found`, `conflict`, server errors) are translated, and an unknown code gets a general text with the code in small print for support. `POST /api/update/check`, `POST /api/login`, `POST /api/setup`, `POST /api/recover`, the API key limit and the public docs limit answer 429 with `Retry-After` and `retry_after` in seconds.
- Campaigns, domains and the other pages no longer hang on «Loading…» after a large Keitaro transfer. Thousands of imported streams carry the same list of thousands of device models, which made `GET /api/groups` about 500 MB (210 MB gzipped) and drove the admin out of memory. The panel now reads `GET /api/groups?shared=1`: each long list filter (1 KB of text or more) is sent once in `lists` and put back by `refs`, which cuts that answer to about 14 MB (under 1 MB gzipped); pages of one section that ask at the same time, the user access editor included, share one request, and the unsaved-changes snapshot names a shared list instead of copying it. The engine and the admin keep one copy of each equal long list in memory. The plain `GET /api/groups` answer is unchanged.
- Adding a regular user to a section no longer hides the default section from them. The user card has a «Main section» mark, on by default (`no_main_board` in `POST`/`PUT /api/users`), and lists the sections open by membership; saving section members changes only `board_ids`. A regular user sees the default section unless the mark is cleared, plus the member sections; existing users keep the default section without any manual change, and administrators and all-sections accounts still see everything. A user with no section gets `403 no boards` on section data and a notice in the panel.
- Clean Ubuntu install opens the admin on `http://<IP>/` too. `install.sh` installs nginx 1.25.1+ from the official nginx.org repository (signing key checked by fingerprint, apt pin 900): the distribution nginx 1.24 failed `nginx -t` on `http2 on`. A suitable nginx is kept; an old one with only package configs is replaced after a copy of `/etc/nginx`, an old one with own sites stops the install with a `--no-edge` hint. `apply-edge.sh` adds `conf.d/emtds-http.conf` (port 80 redirects to https on the same host) only when nothing but an unmodified package welcome page listens on port 80; that page is moved to the backup and restored on rollback, and a server with a foreign port 80 listener (hosting panel) stays as it was. `GUID_INSTALL_UBUNTU.MD` describes the nginx version, the nginx.org setup, the self-signed certificate warning on `https://<IP>/` and how to read the setup token.
- An administrator («Full access») and an account with all sections always see every section. Adding such a user to a section's members, or removing them, no longer leaves them with that one section; accounts already narrowed this way see every section again after the update. A regular user is still limited to the sections that list them as a member.
- After an update the running commit is no longer offered as a new version. The updater checks the channel again once an apply succeeds, and a check made for another build than the running one gives no «New version available» banner, no list of commits ahead and no «Update» (`apply_block: check_stale`, `check_stale` in `GET /api/update`); its line in «Settings → About» offers «Check now», which is not held back by the age of that check.
- A long Keitaro click or conversion log import no longer fails on one broken page. A page whose answer breaks off mid-body, does not connect, or comes back 429, 502, 503, 504 or Cloudflare 520–524 is asked again after 2, 10 and 30 seconds; only then does the import stop. A refused column list (400) still falls back at once. The error now names the cause, for example `keitaro: чтение /admin_api/v1/clicks/log: unexpected EOF`.
- AI settings, "Connection": the note about the key storage spans the full width of the field grid under the fields instead of half of it.
- Keitaro transfer result: the "finished" note no longer touches the counters above it, the warning table wraps its columns inside the panel at about 580 px without side scroll, and the counters wrap too. An offer country `Unknown` (or an empty code) is kept as the country "Unknown" and is no longer reported as an approximation; real garbage still is.
- The campaign filter bar: the group filter has the same width as the state filter, the search field takes the rest of the row, and the bar stays in one row at about 740 px.
- The Markdown button of the API reference opens a formatted page inside the admin (contents, highlighted samples, downloads of the `.md`, OpenAPI and Postman files) instead of the raw text in a new tab.
- The dialog that shows a new API key once: clicking the key (or Enter/Space on it) copies it the same way as the «Copy» button, the field spans the dialog width and wraps long keys, and after copying the button reads «Copied» for two seconds.

## [v0.1.0] - 2026-11-17

First tagged version: the current state of the product.

### Added

- **Engine:**
  - Campaigns and flows with streams, conditions and 18 output types.
  - Click handling with uniqueness by IP or by cookie, anti-flood and per-stream impression limits.
  - Postbacks and conversions.
  - Bot protection: user-agent and referer signatures, search-engine IP lists, reverse DNS, separate bot output.
  - Landings and offers.
- **Admin panel (embedded in the binary):**
  - Reports and dashboard with filters, sorting and saved table settings.
  - Users, roles and per-section permissions.
  - API keys.
  - Domains parked as a list, with the Cloudflare integration (zones, DNS records, `ssl` and `always_use_https` settings).
  - Transfer from Keitaro.
  - Integrations.
  - Telegram notifications sent by the background cron service.
  - OpenAPI, Postman collection and `/llms.txt`, generated from one route catalog.
- **Update agent** (`deploy/update.sh`):
  - Applies only fast-forward updates and fetches only from the pinned `origin`.
  - Checks for updates every hour.
  - Shows "What's new" taken from this file.
  - Optional commit and tag signature check against `/etc/emtds/allowed_signers`; off by default.
- **One-command installer** from git: `deploy/install.sh` clones the repository, builds the images with the commit baked in and starts the stack.
- **First-login token:** the installer prints a one-time token that is required to create the first administrator.
- **Settings → About:** version, build commit, update state and server state.
- **Theme:** light and dark themes plus the brand colour scheme of the admin panel.

### Changed

- The product is branded as EmTDS: directories `/opt/emtds` and `/etc/emtds`, Docker Compose projects `emtds-infra` and `emtds-app`, environment variables `EMTDS_*`.
- The "Profile" menu item is renamed to "Settings".
- The menu and the Settings tabs are built from one list, so they always match.

### Security

- Passwords are hashed with argon2id; sessions are stored on the server; CSRF protection and parameterized queries are used throughout.
- Access to the admin panel and to API keys is limited by roles and sections.
- The admin container has no `docker.sock` and no root access to the host; updates run only through the host agent.
- A secrets scan (gitleaks, pinned version) runs in CI on new commits.
